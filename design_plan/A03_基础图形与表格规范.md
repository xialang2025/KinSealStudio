## 3. 逐类外观字段规范

### 3.1 开放线条族：直线、折线、自由直线、曲线/圆弧

这4类分别具有下表字段，H只给共同语义；每类独立执行GP0/1，不能因窗口看似相同就合并默认/范围。

| 稳定字段后缀 | 帮助标签/语义 | H示例及未知事项 | 调查/验收 |
|---|---|---|---|
| .stroke.style | 线型，实线/虚线等 | 完整枚举、dash相位/单位、无笔选项未知 | GP0/1；每选项GP5，短/长及缩放图比较 |
| .stroke.width | 线宽，即粗细 | 直线/折线例8，自由/圆弧例5；整数/小数/0含义未知 | GP1/5；水平/斜线与奇偶宽样本 |
| .end.arrow | 末端箭头，尾部形状 | H提菱形、圆形，示例实心三角形；是否仅尾端、大小是否另字段未知 | GP0完整查字段；GP1枚举；GP3交换端点看箭头是否翻转 |
| .stroke.cap | 端点形状，首尾两端形状 | H半圆/矩形；不能直接等同Qt RoundCap/SquareCap所有数值 | GP1/5；线宽较大时检查端帽超出/矩形基准 |
| .stroke.color | 边框色，线条颜色 | H红色示例；颜色表示/Alpha通道关系未知 | 调用公共色板，GP1/5；色板取消不提交 |
| .opacity | 透明度 | H100示例；0代表透/不透、范围、整体还是仅线条未知 | GP1/5；透明底/不透明底各取多个档位 |

GEO.LINE的几何是线段、GEO.POLYLINE有多段、GEO.FREE有采样路径、GEO.ARC有曲线/弧线的具体控制数据；这些仅是需要表达的几何类别，源字段/点数/是否自动闭合仍待第4节。

不得在这4类自动增加前景色/背景色/填充样式；帮助未列不代表绝对不存在，GP0新发现字段再追加。箭头是路径末端标志，不能当作独立三角形与线段在模型中永久分离，除非源/编辑证据显示如此。

### 3.3 纯图像表格

H明确：“表格为纯图像对象，不能往表格里添加文字、数据等嵌入对象；只能作为底盘图像。文字/数值显示应叠加在表格上方并置最上层。”因此它不同于配方显示器、历史数据显示器，不建立单元格值、数据绑定、公式、编辑键盘或PLC地址。

| 字段ID | 标签/语义（H） | 必测范围/联动 |
|---|---|---|
| GEO.TABLE.columns | 横向个数=列数 | 例10列；min/max/0/小数、列宽分配及缩小后保留GP1/3/5 |
| GEO.TABLE.rows | 纵向个数=行数 | 例5行；行数/对象高度非整除时边界像素GP1/5 |
| GEO.TABLE.lineStyle | 线条类型，单元格线型 | H实线/虚线；影响内部线还是边框未知，GP1/5 |
| GEO.TABLE.lineColor | 内部单元格线条颜色 | H白色例；与边框色不同，交点/末端颜色GP5 |
| GEO.TABLE.frameColor | 外部边框颜色 | H红色例；描边关闭时是否禁用/草稿保留GP0/3 |

## 5. 几何模型、渲染与持久化实现契约

本节是后续实现应满足的约束；**建议模型字段不是已恢复的原生源字段**。源type编号、序列化顺序、端序、Qt图元子类型与设备type均未在本轮恢复，留待GP4/5，不编造数字。

### 5.1 建议几何表示及一致性要求

| 家族 | 需要表达的语义 | 不能省略的差异 |
|---|---|---|
| 直线 | 首点、尾点、首尾角色、stroke/箭头 | 用正宽高矩形存几何会丢方向；反向拖不得任意交换箭头 |
| 折线/自由直线 | 有序点/段集合及原生证实的曲线/简化参数 | 不把每段当独立对象；复制/缩放/撤销整体保持拓扑 |
| 曲线/圆弧 | 由GP4证实的圆心/轴/角或控制点表示 | 不以一个QRect丢曲率；角单位/方向/原点/整圆约定均写清 |
| 矩形/圆角/椭圆 | 几何框、必要变换、圆角X/Y | QRect含右下端点与浮点边界差别需校准，不能直接整数化所有源double |
| 多边形 | 有序顶点、闭合方式、填充规则 | 自交/重复点/洞若原生支持须保存；未知结构拒绝改写 |
| 扇形 | 扇形有效几何、扫角及边界线角色 | 不是圆弧加隐含填充，径向边界/首末角需准确 |
| 表格 | 几何框、行列数、内部线/外框/底色/三个开关 | 没有单元格数据；不把叠加文字并成表格内容 |

统一保留对象ID、层次/组、原生可证坐标精度、图形专有属性与未改metadata。命中测试区、选择框、实际绘制边界与控制柄分别处理；粗线/箭头越出几何框不得被无意裁掉。锁定/组合/复制/撤销使用共用编辑机制，但原生对顶点编辑是否可用按GP3确定。

### 5.2 像素与外观校准

1. 每类画同坐标、同尺寸、同背景的最小原厂样本；线条至少水平/垂直/斜向，宽1/奇数/偶数，曲线小/大半径；闭合形状至少纯色/透明/渐变以及可见粗边框。
2. 核笔的端帽/折角、dash序列/相位、箭头形状/实心空心/尺寸，填充方向/辐射中心、边界包不包含最后一行/列、抗锯齿、RGB565量化及Alpha混合顺序。
3. 几何缩放、镜像、负向拖、z重排、表格行列非整除和1行/列分别与原厂解码图比；图片相同不自动证明hitTest与控制点一致。
4. 对表格用三种不同色区分内部线、外框与底色，透明度三档隔离其作用。交点重复绘制是否加深/Alpha叠加、关闭描边后最外围格线是否保留均GP5观察。
5. 当前Qt6与原厂Qt4存在部分图库边缘/渐变残差，不能预设这些图形全部零差异；报告ROI差异数量和原始像素SHA，允许范围须有具体原因，不能用“肉眼差不多”代替。

### 5.3 .ksp / .sm / 设备三层

- .ksp：阶段1新增专有属性与足够表达几何的数据，升schema/迁移，保留隐藏草稿；未来schema旧程序明确拒绝。没有native source支持时仍可编辑保存，但编译/导.sm分层拒绝。
- .sm：单默认图形、改单字段、改几何点、图形前/中/后混入已知type、表格+上方文字，逐一GP4恢复typed边界和字段引用；必须解析完整流和嵌套图元。现有codec只接受顶层type10/28，不能凭内部Rectangle已识别就说顶层矩形已支持。
- 设备：先GP5确定静态图形是否烘进背景、需要独立控制图/记录，或依权限/语言转为动态；没有记录也可能属于背景。不能为了复用640B人为分配新type，不能由“纯图像表格”推出它一定使用独立位图文件。
- 新增纯背景绘图若与动态对象交叠，应进入已有underlay/图层合成分析；不能只更新SheetPixel而保留动态图片里旧背景。出现动态依赖未知时按Q-S05-002拒绝相应组合。
