## 2. 已知USB契约

设备`VID:PID=7365:616C`，interface 0，bulk OUT `0x01`、IN `0x81`；使用系统libusb0。安装目录DownT.dll的`Usb_*`导出仅证明USB路径；没有串口/网口下载证据。CH340端口不等于这条路径。

命令32B：`0..16`为17个ASCII字节`KinSealStudioKiss`（不含NUL），`17`为命令，`18..31`为参数/其余清零。现实现10秒读写超时是实现参数，不能当固件上限。识别为`31(02)`、`53(00)`，返回24B，分别检查首字节`4C`、`00`；其余普通确认恰1B `4F`。重启只要求命令完整写出，不等待未证实的ACK。

| 时序 | 段/参数 | 精确约束 |
|---|---|---|
| 开始 | `34(01 01 01)`→`35` | 两次均检查O；三个参数的全部语义仍需补证，不扩展选项 |
| 核心段 | `0A SysPara`→可选`0B ControlPara`→`0C SheetPara` | 每段命令ACK→全部数据写入→35/O |
| 宏 | 可选`36 MarcoVar`→`1D MarcoRun` | 14块计划存在；历史原厂该顺序是主机模拟证据，不据此宣称宏E通过 |
| 配置/资源 | `0E AlarmPara`→`16空`→`15 Collect`→`19空`→`12 AddrPara`→`14 PicLenPara`→`0D Curve` | 16/19没有数据仍保留命令及状态检查，不命名为控制段 |
| 快照与像素 | `1E upLoad.knr`→可选`10 ControlPixel`→`0F SheetPixel` | 1E外加压缩文件长度BE32；文件内另含解压长度BE32+zlib |
| 协议程序 | `11 Modbus_RTU_com1.bin` | 命令参数是数据长LE32，不把整个ZIP当payload |
| 收尾 | `1B/O`→`1A` | 分别记提交ACK和重启写出；不自动记屏内读回/运行通过 |

静态10块、动态12块、动态含宏14块均须完整且非空。段长随工程变化，不抄旧TEST常量。原厂重复编译的不稳定字段遵循阶段5差分规范，不能把未初始化尾字节复制进协议常量。

## 3. 顺序任务

### S06-01 · 固定输入并核对只读计划

1. 读取阶段5manifest与源码身份，列出本切片是10、12还是14块及选用原因。
2. 用既有`buildDeviceTransferPlan`解析顺序、选项与长度；对照上表和协议第12节。宏顺序另标主机证据。
3. 复用现有计划测试；后续实现阶段仅对新增段/逻辑添加独立意义的测试，不把旧测试数量作为本次覆盖率。
4. 产出`S06-01-transfer-contract`：逐步序号、命令、payload哈希、期望应答、下一状态。此表是离线回放输入，不附USB自动执行脚本。

通过：正常三类计划与受支持切片对应；空段、缺段、坏长度、未知目标、未支持对象在打开USB前失败，输出保持事务完整。阻塞：新增段集合未经原厂证明时只关闭旧范围。

### S06-02 · 补齐下载窗口交互与取消事务

1. 后台私有桌面中以无设备副本打开原生“工具→下载工程”，记录菜单/工具栏入口、初始模式、机型/路径/时钟/下载选项的真实标签、顺序、默认、enabled/visible、焦点及帮助目标。
2. 对未保存工程记录保存→取消/失败→返回的路径；不点击真实设备的下载启动。不能仅从截图推导默认值。
3. 对复刻现有进程链逐项检查：重复点击、编译失败、无驱动、无设备、子进程崩溃、关闭父窗口。所有取消点写成“取消请求→是否已发送命令→屏内状态→恢复入口”。
4. 原生传输中取消的语义如无既有证据，使用mock bulk读写调查主机分支并注明不是硬件事实。只有保存选择取消才可默认无设备副作用；发送开始以后不能承诺回滚。
5. 补字段字典`S06.download.*`；未知选项阻塞对应UI/协议切片，保留现有范围。

通过：UI与真实原生操作一致；运行中取消如未恢复，明确产品限制/禁用依据，不能显示“已恢复原工程”。

### S06-03 · 错误注入与完成判定

先只做离线/mock，按专题`TR-01..TR-08`覆盖部分写、读长度错误、错ACK、超时、缺驱动、接口占用及提交后重启失败。每例保留首个错误步骤、已写段列表、提交/重启状态；失败后不继续后续段，不自动重试/断点续传。需要新容错算法时先补协议证据，防止重复写入或不完整提交。

输出层次至少区分`compiled`、`transferAccepted`、`commitAccepted`、`resetWritten`、`screenDisplayAndTouchConfirmed`。这是建议记录格式；现有CLI只返回`ok/message`，实施时不得假称这些键已经存在。

### S06-04 · 工程上载独立恢复

帮助`Data-Transfer/upload.html`支持“工具/工具栏上载数据→选型号→选保存路径/文件名→上传文件→必要时密码→进度→完成自动关闭”，要求工程启用上载。它不证明USB命令或上载文件格式已恢复。

1. 无设备后台枚举窗口、型号、路径、覆盖提示、密码框、进度、关闭/取消；建立下表未知字段的可观察真值表。
2. 静态定点调查DownT上传导出及原生调用处，标输入输出缓冲区、长度、状态码；无法定位时从实际导出名反查，不猜命令码。
3. 先mock观察主机读请求与文件写出，产物只写新文件；将`upLoad.knr`/`.sm`与读回数据逐层解析核对，不能把下载快照存在当作上传已实现。
4. 只有未来另获硬件操作授权且具可恢复工程时，才做无密码/正确密码/错误密码/禁止上载/中断读回。密码使用专用测试值，不在日志中存实际密码。
5. 上传临时文件只有完整性/格式通过后才原子落成；错误/取消不覆盖已有文件。原厂是否同样原子保存须实测，采用此策略时记录产品差异。

|---|---|---|---|
| S06.upload.model | 帮助要求选型号 | 当前V5.1列表/默认/与设备匹配方式：后台窗口+调用参数 | D/U/T |

| S06.upload.enabled/password | 帮助有使能/密码 | 源/设备字段、长度/编码、握手与错误码：单变量编译+调用链 | D/P/C/T |

### S06-05 · U盘/SD卡包

帮助`SystemSetUp/mainframeProject/downSet.htm`写FAT32、32GB以下、工具→下载工程→下载到U盘→选盘→下载→屏端升级组态。当前V5.1限制与包布局仍须核对；帮助不授权格式化用户磁盘。

1. 后台枚举介质模式全部字段，包括更新工程/固件/时钟等实际存在项；未出现项不预设。
2. 优先让原生写到可控测试目录/隔离虚拟介质，记录生成前后目录差、文件名、层级、头/尾、长度、哈希；禁止写用户真实盘。
3. 同源重复两次，再分别只改型号、文字、语言、宏、上传使能、下载选项。比较`.kns/.laz/load.bin/Usbload.bin`与散段关系、压缩、长度和校验。不把USB段集当介质包格式。
4. 恢复后离线独立生成并原厂/解码对照；写入新目录而非覆盖根盘。空间不足/只读/路径失效/取消保留旧文件，失败不提示可拔出升级。
5. 屏端介质升级E在阶段10另行执行；缺硬件只关闭D/U/P/C，保留T/E未验。

### S06-06 · 收口与交接

输出三个独立能力行：USB下载、工程上载、介质包。逐行列D/U/P/R/C/T/E适用层，N/A必须有理由；不能用USB T成功关闭上载或介质T。将未恢复窗口/命令/格式列稳定问题ID及下一探针。S06-04/05未知不阻塞既有USB限定范围，但阻塞“阶段6全功能实现完成”。
