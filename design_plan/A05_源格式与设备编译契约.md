# A05｜源格式与设备编译契约

版本：2026-11-10；适用对象：KinSealStudio Lite 0.7.0及后续复刻。首轮目标为AMT070W124-L800X480R、800×480、现有原固件。本文由[阶段1](02_阶段1_工程模型与文件格式.md)和[阶段5](06_阶段5_设备编译与格式差分.md)共同调用，集中保存已经可定位的格式事实，避免两个阶段分别维护不同版本。LT779不使用本契约。

本文的格式调查依据只读源码和已保留历史证据，没有为格式分工重新构建或执行原厂编译，没有访问USB或观察屏端；本轮另有全局入口私有桌面采集，见总入口。源码描述当前实现，历史原厂样本描述已观察格式，未来设计要求另行标明。

## 3. .ksp当前契约

顶层format为`KinSealStudio-Prototype`。常用键如下；具体类型和默认值以FMT-MODEL及各properties模块读写函数共同为准。

| 范围 | 键/关系 |
|---|---|
| 工程身份 | schemaVersion、projectName、targetModel |
| 页面 | resolution.width/height；pages数组当前只接受一个成员；成员含name、objects |
| 对象基础 | id、type、name、text、address、x、y、width、height、layer、group；QRect geometry是内存字段，JSON将其拆为这四个整数，不存在geometry嵌套键 |
| 专有属性 | staticText、bitButton、wordButton、lamp、functionButton；字/功能/灯仍共享bitButton外观/部分公共条件，不能仅根据type=switch判断为位按钮 |
| 语言 | languages为有序列表；activeLanguage为编辑器所选语言，必须属于该列表；它不等于设备启动语言 |
| 公共资源 | macros为名称→源码；pictures为稳定ID→Base64图片；connections为连接上下文 |
| 原生保全 | nativeSourceSnapshot为Base64 .sm字节；nativeSourceWarnings保存未映射休眠值提示 |

`toJson`写的是足以表达当前内容的版本，并非每次固定写8：

| 最低schema | 触发能力 |
|---:|---|
| 1 | 旧基础工程 |
| 2 | 静态文本属性、多语言、非默认层或组等扩展 |
| 3 | 位按钮/宏/工程图片 |
| 4 | 非空connections |
| 5 | 原生源快照及警告 |
| 6 | 字按钮 |
| 7 | 指示灯 |
| 8 | 功能按钮 |

这些是当前版本触发条件，不是允许手工把高版本文件改回低版本。现有加载器显式拒绝schema不在1..8、字按钮低于6、指示灯低于7、功能按钮低于8。未来新增结构应设计新schema及迁移/降级拒绝规则，不能继续塞字段让旧编辑器静默丢失。

当前保护边界：AMT指定型号/800×480、单页、至多100对象；connections至多2；源快照至多16MiB；warnings至多128条、每条4096个QString代码单元；宏源码每条至多1MiB代码单元。这些来自Lite实现，不是原生极限。设备编译另要求对象1..100、语言1..8。不能因为.ksp能保存，就跳过C层能力检查。

`HmiProject::fromJson`通过局部loaded_project完成后替换调用方；失败不应改变当前工程。`save`使用QSaveFile。未来扩展仍保留这种事务语义。当前JSON没有自动保存全部未知顶层键的通用机制；要保全未来扩展键，应明确存储边界和兼容策略后实施，不能声称现有实现已完成。

## 4. .sm当前可定位文法

### 4.1 文件头与基础值

已核头顺序为：Qt QString签名`KinSealStudio-V1.0.2` → 大端u32版本122 → QString型号`AMT070W124-L800X480R` → 主体。源结构检查上限64MiB；单QString上限1MiB字节，是当前分配保护。

QString：大端u32字节长度，随后UTF-16BE代码单元；`0xffffffff`表示null，`0`表示非null空串。奇数字节数、超上限、超剩余文件均失败。不能把UTF-16代码单元数当字节数，不能把null与空串全局归一。SourceDocument内部保存每字段start/end/kind/value，修改由typed遍历得到的span完成，不用绝对文件偏移搜索替换。

主体当前遍历顺序为：system → configuration → project.pages计数/单page → history宏源码/缓存/地址历史 → trailer设置/page-map → EOF。SourceDocument::parse必须消耗完整字节；尾部残留也失败。parser里的200页/1024对象等计数上限是读取保护，不能写成已恢复多页模型或原生最大数。

### 4.2 对象与嵌套结构

page.objects每项含movable、type、对应typed图元、z。当前顶层只允许10和28；type10再用switch.mode区分0位按钮、1字按钮、3功能按钮、4指示灯。type28是静态文本源对象。源内文字、图片、Rectangle/Pixmap、组边界及元数据都属于变长嵌套结构；每控件不是固定640字节。

| 类别 | 当前关键源路径/恢复要求 |
|---|---|
| 共用 | control读取几何、图元/字体/颜色、权限地址、组元数据；SourceUpdates按字段更新并保留未改span |
| 静态文本 | static.194语言行及static.head/tail；不同行独立样式若当前模型无法表达则拒绝语义导入 |
| 位按钮 | switch.12c操作地址、switch.144操作块、switch.248监视、switch.290文字列表、switch.294图片列表、switch.tail公共尾 |
| 字按钮 | word.150地址、word.16c typed字段，特定标志时有word.198额外地址；未恢复的活动第二地址不可假装支持 |
| 指示灯 | subtype4直接进入宏/监视公共后段；2..32多态列表；同文为全局switch.tail.4；无图保留路径并重建Rectangle子图元 |
| 功能按钮 | function.1c8精确顺序`iiqbbiq`：i32功能、i32类型、opaque QString、u8、u8、i32键、QString字符；键不能误读为u8 |

表中的`.12c`等是SourceDocument的稳定语义路径命名，**不表示文件绝对偏移或该字段在任意源中的固定位置**。新增类型必须先恢复其typed宽度/变长分支、嵌套边界和引用，再允许写回。

### 4.3 三种不同成功

1. `inspectNativeProjectEnvelope`：只认头与保留原始字节，明确主体未知。
2. `restoreNativeProjectArchive`：核对原始SHA256和头信息后逐字节恢复；不代表可编辑。
3. `validateNativeProjectSourceStructure`及`importNativeProjectSource`/`exportNativeProjectSource`：完整已支持文法遍历与受限语义互通；配置活动语义仍受白名单保护。

现有nativeSourceSnapshot并非“未知对象随意透传”的证明。只有对象边界及其跨对象/跨页引用均已证实，才能设计局部编辑后透传；边界未知时只允许整文件归档恢复，或只读/明确拒绝。源快照存在不意味着后续新增任意字段可不经差分直接写入。

源单态列表不会保存未使用另一态全部草稿；.ksp继续承担完整编辑信息。编辑器语言切换不改设备启动语言；startup由原厂系统配置按语言名映射，删除原启动语言才回索引0，新工程为0。宏改源码后清除旧二进制MD5/已编译标记，不能保存失配机器码并宣称原厂可直接编译。

### 5.2 已核定公共字段

以下偏移仅针对640字节设备记录，未列部分不是全部未知，更不是可自由复用区；逐字段完整规则由5个native_*_control.cpp及其原厂活动掩码补充。

| 字段 | 当前已知编码 |
|---|---|
| 记录大小/身份 | 640B；首字节type10或type28；type10的0x106为LE u16 subtype |
| 几何 | 0x004/006/008/00a：x/y/宽/高，LE u16 |
| 图像定位 | 0x00c：解压后像素偏移；0x010：该控件全部活动帧原始字节数，LE u32；不能填写压缩文件偏移 |
| 静态文本 | type28：0x100为u16零，0x102为LE u16语言数；每语言一图 |
| 字按钮 | subtype1；0x103按下效果；0x110/114总位数/小数位；0x118/11c操作/类型；0x120/128/130 LE f64常数/最小/最大；0x138为36B主地址 |
| 指示灯 | subtype4；0x180地址类型，0x184监视模式，0x188字位，0x18c U16/U32，0x190状态数，0x198 36B监视地址，0x1bc同文标志 |
| 功能按钮 | subtype3；0x118/11c功能/类型（无类型=-1的i32位型）；0x120键，0x121本地编码首字节；0x1bc同文；0x1be LE u16毫秒按压时间 |

未初始化/休眠区域可以在有证据的掩码下规范置零。不能把不同运行间偶尔相同的脏值变成常量，不能扩大掩码掩盖仍有活动意义的字段。源地址结构和设备36B地址是两种布局；FMT-LAMP证实设备地址相对字节4不是U32宽度字段。地址跨度由源/扫描/预检共同保证。

### 5.3 图片、长度表和计数不变量

- 背景为800×480 RGB565，原始768000B。状态图每帧原始字节为width×height×2；奇数宽时剔除Qt行填充，不能把bytesPerLine直接当屏端stride。
- 每状态图独立LZO压缩、解压回验，块按32B补齐。长度记录12B：LE u32编码标记0、补齐长度、实际压缩长度。
- PicLenPara头2400B为三组200页u32数组；当前第0项在0x000为背景压缩长、0x320为控制像素压缩总长、0x640为控制图数量；其后依次追加12B图记录。不是每页面先跟12B图记录。
- SheetPara的byte2为控制记录数，byte3是独立页面标志；不能按u16合并。0x44（十进制68）为控制图解压字节总量。SysPara偏移2172/2174分别为LE u16启动语言索引/语言数。
- type28在多语言或显现条件启用时生成动态记录；普通单语言无显现文本可烘入背景，不要求每个文本都有ControlPara记录。

| 控件 | 每语言状态/帧顺序 |
|---|---|
| 位按钮双态 | ON→OFF；单态只有OFF；该状态闪烁的无字帧紧随正常帧 |
| 字按钮 | OFF常态→可选ON按下态；闪烁额外帧按该状态规则 |
| 指示灯双态/多态 | 双态ON→OFF；多态0..N−1；多态闪烁不额外增图，前两头标志不能推出全部状态的屏端效果 |
| 功能按钮 | normal→可选normal无字帧→可选隐藏pressed-state1；隐藏按下图不是可编辑state0的自动复制 |

一般顺序为控件（当前按layer稳定排序）→语言→状态/额外帧。指示灯/功能按钮sameLanguage为真时只发一套完整图，不重复语言套数。图片数量、长度表数量、record.rawBytes、rawOffset前缀和及语言标志必须互相一致。

### 5.4 扫描、宏和传输边界

设备编译只开放已核定`Link/serial_amz/MODBUS/Modbus_RTU.ini`、COM1、站号1及节点1；PLC地址目录支持更多数字编码，不代表这些协议可编译通信。扫描仅收集实际读取，包括交替、监视、活动权限；纯写/通知不自动加入扫描。AddrPara为200B页计数头+12B扫描段，排序/合并/边界以device_scan_table现有回放为准。

宏必须用已配置真实ARM SDK编译、链接并提取RAW；源码或ELF不能冒充设备RAW。当前未恢复变量绑定、初始化/全局宏等语义继续拒绝。SDK路径与专有工具不写成必须复制到文档包的依赖。

纯`buildDeviceTransferPlan`使用0x0B控制参数、0x10控制图、0x36宏变量、0x1D宏代码；0x16/19为空步骤。upLoad.knr线上再加4B大端“压缩文件长度”，文件内自身还有qCompress大端解压长度；0x11程序长度选项为小端。阶段5只验证离线计划，实际传输交由阶段6。T的ACK与E的显示/触控分开。
