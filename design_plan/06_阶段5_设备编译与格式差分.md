# 06 阶段5：设备编译与格式差分

文档版本：2026-11-10。对应[完整路线图](完整复刻路线图.md)阶段5；格式事实集中调用[A05](A05_源格式与设备编译契约.md)。本阶段以AMT070W124-L800X480R、800×480及现有固件为唯一首轮后端。LT779另建扩展编译后端。本轮生成本文时没有构建、调用USB或写屏。

## 1. 阶段结果和层次边界

本阶段把已确定的工程语义编译为目标固件能够解释的段、记录、图片与索引，并解释与原厂输出的差异。交付物是离线编译器、格式规范、最小原厂对照语料、拒绝清单和分层验收；传输T由阶段6、设备运行E由阶段10分别确认。

不能用“文件生成成功”“旧模板能下载”“屏返回O”替代C层闭合。C层通过要求同范围字段、资源、引用和解码语义正确；目标接受及运行另加证据。当前0.7.0已有5类受限单页C，不需要推倒重写；其余26类、基础图形、配置及多页按切片逐项扩展。

开始条件：本次字段D明确，模型能够保真保存，原厂有效最小源及编译产物可获得。未恢复设备映射只阻塞对应C；阶段4可以先交编辑器U/P/R，但编译必须明确拒绝该对象/组合。

## 3. 本阶段输入和差分结果格式

每个编译切片先填写：目标型号/固件（未知版本明记未确认）、原件与运行副本SHA、工程SHA、支持字段、语言/状态/页数、连接、图片/字体、宏SDK身份、输出目录、验收层。原厂运行副本SHA与原件不同，必须分别登记，A05已有已知身份。

每个对照样本至少记录下列四层，不能只给一个equal=true：

| 层 | 输出 | 可得结论 |
|---|---|---|
| B 原始字节 | 文件长度/SHA、变化区间、同输入重复编译结果 | 定位容器/不稳定区，不能直接推出语义错误 |
| S 段/容器结构 | 条目、顺序、计数、偏移、压缩/补齐、引用、校验 | 结构与边界是否一致 |
| M 解码语义 | 活动字段值、地址/扫描、帧映射、RGB565像素、宏RAW | 编译是否表达同一功能；差异需解释 |
| E 行为 | 外部刺激、真实屏端显示/触控/寄存器/时序 | 运行层结论；本文本轮不执行 |

同源原厂压缩字节不同，但解压像素相同、块长度/索引有效时可通过相应C语义检查；不能要求LZO/zlib只有唯一输出。相反，活动字段不相等不能用“压缩不同”掩盖。

## 4. 按顺序执行的任务

### S05-01 冻结目标、5类编译基线和纯离线入口

**输入/前置**：阶段0身份与阶段1当前源支持清单、A05、第2节模块与现存样例。

**步骤**：

1. 复核当前buildProjectPayload所有预检：对象/语言/几何、外部配置/扫描、宏、未知类型、动态文本重叠和透明动态重叠。列出“允许/拒绝/待验”的准确组合，不从旧报告过期限制反推当前能力。
2. 识别CLI：`--validate-project <工程>`只验证加载；`--export-native-project <工程> <输出.sm>`导源；`--compile-project <工程> <新输出目录>`纯离线生成。`--download-*`全部不在本阶段命令清单。
3. 为当前5类各选一个默认正例和一个组合/边界正例；混合语言用现存样例，先核文件哈希，不复制全部dist/build/原生安装。
4. 记录已存在原厂TEST的14项ZIP/文件基线及固化段SHA；固定Alarm/Collect/Curve等并非完整配置编译器，任何新活动配置触碰它们时继续拒绝。

**验收S05-A01**：文档能逐一指出每段由谁生成、哪些仍固定、何时拒绝、如何证明未访问USB。负向：旧单文本入口不能编译新按钮；未知type不能被忽略或只绘入背景后报告成功。

**恢复点**：保留现有可用编译器和有效样本；新类型未开闸前在输入校验失败，旧5类编译路径不受影响。

### S05-02 建立最小原厂差分语料和稳定性基线

**前置**：S05-01；对应原厂对象/字段可被确认，输入源能由原厂UI正确建立、保存并重开；问题Q-S05-004。原厂UI创建的有效源可先用于格式调查，不要求Lite源导出先完成；产品导出正确性只阻塞“Lite导出→原厂复开/编译”的互通交叉验证。

**最小样本矩阵**：

| 样本组 | 只改变的因素 | 必须观察 |
|---|---|---|
| R0 | 空/默认工程与一个默认控件 | 新增段、type/subtype、引用和基线差异 |
| R1 | 完全同输入重复编译至少2次，另进程再编译1次 | 哪些字节不稳定、是否与活动字段相邻 |
| R2 | 单字段：位置、尺寸、文字、地址、操作/模式、权限 | 所有跟随变化段，不能只比ControlPara |
| R3 | 1/2/8语言、状态下界/上界、单/双态、同文 | 图像套数、顺序、翻译、启动语言、rawBytes |
| R4 | 无图、透明、按下、闪烁、缺图、奇数宽 | 图块、补齐、隐藏状态、合成与拒绝 |
| R5 | 两对象调序/层次、重叠、复制/删除、引用删除 | 控制表、帧、扫描、触控序线索及索引重排 |
| R6 | 两页及调序/删页/启动页/窗口 | 可先用原厂UI建立有效多页源采样，帮助阶段1恢复边界；Lite多页导出正确后再交叉验证；Q-S05-001 |

**步骤**：

1. 原厂每次只运行一个编译进程。先验证新源在原厂实际包含目标对象与属性，再编译；空白失败副本、菜单没弹框不计成功。
2. 直接枚举容器和目录条目、长度、SHA，再按B/S/M分层提取。每个新字段至少有默认、变更和邻近边界；复杂枚举由实际状态空间决定，不机械全笛卡尔积。
3. 写差异分类：活动字段、休眠字段、未初始化、时间/路径、压缩编码、未知。每个允许忽略区必须记录范围、证据、适用type/固件和反例；未知保持失败/待验。
4. 只保留唯一最小源、涉及的原始段、必要差异JSON；完整编译产物可压缩一份或选择必要段，但不得删掉唯一可重现依据。

**验收S05-A02**：同输入不稳定区与单字段变化区分别可重现；明确数据来源是原厂UI创建、产品源经原厂编译还是人工注入。负向：不能把一次偶然相同值当常量，不能用整640B或整段忽略掩码过关。

### S05-03 建立语义编译中间结果与整体预检

**前置**：阶段1模型/引用和本切片S05-02；是后续实现方案，现有工程尚未具备完整多页IR，不得写成已实现。

**定位**：buildProjectPayload、5类记录编码器、图像编译器、device_address_compiler、device_macro_compiler。优先拆出纯编译职责，USB继续只消费已生成计划。

**步骤**：

1. 从同一不可变工程快照生成逻辑记录、资源/图帧、地址读取需求、宏引用和页面映射；分配索引前校验所有活动字段可表达。
2. 把UI状态转成明确语义：活动/隐藏字段分开；共享sameLanguage与状态数归一；不把通知写加入读取、不把指示灯当可写按钮。
3. 统一支持能力检查，错误包含页/对象稳定ID、属性路径、值和拒绝原因；界面入口与CLI使用同一检查，不允许CLI绕过下载前守卫。
4. 后置生成长度/索引：以最终图帧与记录顺序计算rawOffset/压缩偏移/页计数；所有乘加先做溢出检查。编译失败保留调用方之前的有效结果。

**验收S05-A03**：相同工程快照产生相同逻辑输出；切换选中对象/编辑语言不意外改变启动语言；未知活动值在生成正式包前失败。负向：越界geometry、错误状态数、冲突子类型、未注册语言、悬空宏/图片、SDK缺失/失败、非法连接均返回可定位错误并保留旧包。

### S05-04 逐类型恢复并实现设备控制记录

**前置**：该类型S05-02/03、D字段及阶段1源边界；新问题接Q-S01相关节点，不猜偏移。

**步骤**：

1. 复用A05已核640B公共头，但先证明新type是否真为640B、是否有subtype和附加结构。共享UI或源父类不等于设备联合体一致。
2. 每字段记录模型键→源路径→设备段/偏移/宽度/端序→活动条件→地址角色/资源引用→证据ID；无映射的活动字段直接拒绝。
3. 先实现默认最小type，再按原厂单字段样本扩每种活动模式；编码buffer清零，但只对有证据未初始化区域做规范化声明。
4. 编码器检查图像rawBytes/offset、语言/状态、地址跨度和对象身份。失败不修改调用方输出；指示灯和功能按钮禁用宏等既有边界继续成立。
5. 加入真实原厂记录夹具按活动掩码对照；同时做新建产品工程→导源→原厂复开编译，防止仅旧seed改字段可用。

**验收S05-A04**：默认/所有本次开放枚举/边界活动字段与原厂相符，引用与图帧一致；每项未知不掩盖。负向：未开放字段、混合属性、非法字符/代理项、非法type/功能、溢出及错误rawBytes均拒绝且输出不变。

### S05-05 页面背景、动态图帧、字体及压缩索引

**前置**：S05-04对应记录；阶段3/4渲染契约；Q-S05-002涉及动态重叠。

**步骤**：

1. 复用共用渲染器，把属性预览/画布/设备栅格差异拆成R与C问题。每帧写frame ID、对象、语言、逻辑状态、正常/无字/按下角色、尺寸和源资源哈希。
2. 按A05现有5类不同状态顺序发图；图库Alpha、奇数宽、图像模式、空翻译、隐藏pressed资源分别处理；不能一律补ON/OFF或复制第一语言。
3. 每帧RGB565原始字节数固定为宽×高×2，独立LZO压缩→解压回验→32B补齐；记录实际压缩长和补齐长，不把Qt行填充写入屏端。
4. 统一生成PicLenPara三组页数组+12B图记录、SheetPara计数/raw总量、ControlPara.rawOffset/rawBytes。跨页规则未知前保持单页，不把头数组有200槽当成已支持200页。
5. 动态文本重叠、透明动态覆盖等先用最小原厂样本恢复“完整下层静态背景/动态图”的关系；在未闭合前保留明确拒绝。触控优先级只能列E待验，不能由图层排序推断。

**验收S05-A05**：所有帧解压成功；表中帧数=实际块数，累计rawBytes=SheetPara总量，压缩块边界连续、填充正确；已采样原厂文字掩码/像素差异有计数和归因。负向：缺图、伪占位、空压缩、错stride、越界长度、漏语言、错误同文套数、动态重叠未支持均失败。

### S05-06 地址扫描、驱动程序和宏段联合校验

**前置**：阶段8/9可按切片提供输入；当前先复用已核默认Modbus与普通按钮宏。

**步骤**：

1. 把操作写、读改写、监视、显现、触控、通知、宏变量/资料传输分不同地址角色；只为实际读需求构造扫描表，按连接/route/node隔离，不靠地址文本相似合并。
2. 复用device_scan_table的原厂回放排序、间隙合并、位边界、DWORD对齐/数量和段上限；新增协议必须有独立证据及设备模板ABI，地址输入能解析不够。
3. 宏引用按实际编译后的索引回填；SDK真实生成RAW，检查宏数量/RW/ZI/长度/入口。源码更改清旧MD5和缓存，变量绑定/初始化/全局宏未恢复继续拒绝。
4. 任一新增配置影响固定Sys/Alarm/Collect/Curve/协议bin时，同时恢复对应字段/校验；未恢复不要仅把原厂新段拷进模板冒充独立编译。

**验收S05-A06**：默认Modbus现有扫描回放/七类地址槽/跨度校验通过；宏RAW与同源原厂对照，容器未初始化差异单独说明。负向：其他连接配置、route/node不明、越界跨字、无调用点宏、无SDK/编译失败、未知变量或数据类型全部在输出/USB前失败。

### S05-07 多页、窗口及复杂配置扩展

**前置**：Q-S01-001/003的源模型已能保真，S05-02 R6；问题Q-S05-001。

**步骤**：

1. 最小两普通画面，分别含一个已恢复控件；切启动页、调序、改ID、删除被引用页，逐次原厂保存/编译。再单独加入窗口、键盘、Logo，不能一起加入后猜段对应。
2. 恢复页面表、控制列表边界、图片/扫描页数组、启动/背景/窗口关系、跨页按钮/宏/配置引用及页号映射。
3. 生成每页独立语义后在最后派生全局索引；改名不该改变稳定ID，重排必须重写所有依赖索引，删除不能留下悬空引用。
4. 按采集→报警→历史/配方→资料传输的实际依赖逐项编译，不因存在相关控件就把固定空配置段当有效运行配置。

**验收S05-A07**：两页→调序→删页的各段结构和活动字段与原厂一致，所有引用闭合；窗口/配置按已恢复范围分别通过。负向：页ID重复、启动页缺失、被引用页删除取消、超页/资源阈值、未恢复配置/窗口类型明确拒绝。未通过前多页工程不能只编第一页。
