## 3. 顺序任务

### S11-01 · 冻结版本和声明

1. 从实际CMake/README与可执行版本资源建立一致版本号，核对当前源码是否含其他未完成任务，不混入用户既存改动。
2. 汇总各阶段的能力行和问题ID，生成功能分层支持表；阶段10未验项目显式保留，受限版本可标“已编译/已传输/待现场”，不得删掉。
3. 读取当次程序/样例/资源哈希，旧包若哈希不同只留历史。若真实仓库存在按项目既定提交/推送规则；当前工作区无Git仓库，不自行初始化或选择远端。
4. 准备新输出目录；旧发布包、正在运行程序及用户工程不覆盖。

### S11-02 · 依赖和许可盘点

1. 从PE导入、Qt部署输出、运行时动态加载和资源读取列所有依赖；USB用系统libusb0，宏工具链外部配置，不因开发机已安装而省略。
2. 将“普通编辑/保存/渲染/编译/USB/宏”分场景测试依赖缺失：无Qt安装、无编译器、无原厂安装、无USB驱动/设备、无SDK、无指定字体、无图库或资源损坏。
3. 当前lzokay MIT许可证路径[LICENSE](../third_party/lzokay/LICENSE)应随编解码器分发；Qt及其他库按实际链接/分发方式核实。原厂固件/工具链/图库等来源和分发依据需逐项记录，有疑问的组件可做外部选择或另列交付条件，不将不明材料直接塞包。
4. 输出`S11-dependencies`：组件/版本/hash/使用场景/来源/分发策略/缺失提示。未取证的许可结论写待核，不能用本文件代替法律授权。

### S11-03 · 可重复打包与干净环境

1. 实施阶段使用Build.ps1现有检查，按变更补必要测试；输出新Deploy目录，记录脚本/工具hash和实际退出码。当前文档任务不运行构建。
2. 先审阅Build复制清单：目前会拷贝整个docs及多个手册/图片，可能带开发证据；明确用户包与实现规格包各自白名单，避免每版把历史调查副本复制进去。
3. 在隔离进程环境移除已安装Qt/MinGW/原厂软件路径，不修改用户全局PATH；运行离屏/私有桌面验证、打开所有声明样例并做支持范围内保存/源导出/离线编译。
4. 验证中文/空格/长路径、只读安装目录、普通用户、DPI/缩放、多显示器边界（使用后台离屏/私有桌面条件）、缺字体提示。无法可靠后台模拟的场景记录外部待验，不拉到前台抢焦点。
5. 错误/取消不落成半工程，不删旧包；无设备状态明确且不能报告USB成功。宏缺SDK只影响相关场景，其他编辑功能继续工作。

### S11-04 · 安装器、升级与卸载

便携是现有能力；如要提供安装器，先补原生安装入口/默认目录/快捷方式/文件关联/驱动选项/升级提示/卸载是否留工程的当前版本调查。不能只凭Setup文件名推导安装逻辑。

区分应用文件、用户设置、项目与SDK/驱动。升级前记录旧设置/工程，测试向前迁移与旧版拒绝新schema；禁止新安装器自动降级保存用户工程。卸载测试在专用沙盒，不删除用户工程/独立SDK或系统驱动，除非用户显式选择且语义/范围清楚。

若本次只发布便携包，安装器行状态“未提供”，不伪称完整安装/卸载兼容。未来增加安装器另有版本输入和验收。

### S11-05 · 本地帮助与用户操作说明

1. 按阶段0全入口台账建立`commandId→helpTopic→用户章节→已实现能力`，覆盖菜单、右键、双击窗口、嵌套对话框和错误。链接从运行包真实相对路径打开，不依赖开发机绝对目录。
2. 用户手册说明建工程→设置型号/连接→画面/控件→属性确定/取消→保存/原生导出→编译→下载/上载/介质→模拟→错误处理；只介绍发布版本实际支持的入口，未知功能显示范围提示。
3. 用户页不暴露偏移/反编译细节；实现规格继续调用本design_plan、协议/字段子文档，两个用途分开链接。
4. 修复原生失效帮助目标等缺陷时入差异表：原生行为/采用行为/理由/证据/适用版本。一般缺陷逐项决定，不以“交互一致”自动复制所有坏链接。
5. 不照搬原CHM所有内容为当前能力承诺；帮助旧版本“6语言”、在线30分钟等以最新证据/采用策略标明。帮助按钮取消/加载失败/离线状态有明确结果。

### S11-06 · 发布审查与交付

依次检查：支持表与程序守卫一致→格式/迁移→关键错误/取消→清洁环境→帮助链接→依赖/许可→实际设备证据及限制→版本hash。较大程序变更先按项目要求只检查不改逻辑；复核发现项单列，修复再按受影响范围验证，不能悄悄变更已验证版本。

输出正式发布manifest、用户手册、变更/差异/限制、样例索引、测试摘要及原始代表证据、恢复说明。每个功能需要追溯到任务ID/字段ID/用例ID；本轮新文档的未执行用例不能标pass。执行[A06专题](A06_运行与发布验收用例.md)REL组。

## 4. 收口、恢复点与磁盘控制

| 维度 | 发布核验边界 |
|---|---|
| D | 支持范围、帮助与差异清晰，未核全局入口不宣称全软件D通过 |
| U | 干净环境与用户权限/DPI/帮助/取消可用；原有程序交互不能代替部署UI |
| P | schema迁移/旧版拒绝/用户工程与设置保全、安装卸载范围有证据 |
| R | 字体/图库/Qt渲染环境在目标系统验证，不以开发机截图推定 |
| C | 构建/离线编译/包依赖在本次冻结程序hash下复核；历史数仅作参照 |
| T | 发布说明只引用对应版本真实下载/上传/介质结果，缺项公开 |
| E | 发布声明受阶段10现场范围约束；便携测试不使E自动通过 |

局部发布允许保留E待验，但版本名称/说明须明确；“完整复刻”发布要求声明的全软件范围与各层证据闭合。当前M0入口/字段仍有待验，因此本任务书不是完整复刻已完成证明。

恢复点为冻结的发布manifest、最后通过的检查、差异/限制与待处理项；失败时保留已成功旧包和新目录诊断，继续从首个失败检查，不重装用户环境。

最小证据保留本次manifest、工具hash、测试摘要及首个真实失败、帮助映射、依赖表和代表包。打包暂存、测试安装副本、重复图、可再生构建输出只有确认无需保留且不被文档引用后，限定在本阶段专用临时根内删除。已交付发布包、用户工程、系统SDK/驱动、历史独有证据不归自动清理。清理记录列路径、用途、依据、删除前后字节；本轮只写Markdown，无打包临时物。

完成全部声明范围后回到总入口登记交付状态。LT779需另起输入身份、固件解析/资源/协议/下载与设备测试契约，不复用AMT通过结论。
