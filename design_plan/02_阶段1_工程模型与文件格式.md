# 02 阶段1：工程模型与文件格式

文档版本：2026-11-10。对应[完整路线图](完整复刻路线图.md)阶段1；共同格式事实调用[A05 源格式与设备编译契约](A05_源格式与设备编译契约.md)。初版为调查和执行规划；本次0.8.0实际生产修改与验证见本文末尾恢复点及[阶段1验收](../docs/阶段1工程模型与验收.md)，不再将当前实施轮表述为只写文档。

## 1. 本阶段的目标、入口和退出标准

将“编辑工程→保存重开→原生源互通→配置/资源引用”做成明确、可迁移、失败不破坏已有文件的契约。先保全现有5类，再扩多画面、系统/工程配置、其余控件和未知对象策略。模型结构必须表达真实业务语义；不得把原生结构内偏移直接当业务字段，也不得把当前单页上限写成原厂上限。

本阶段可以分三种切片交付：

| 切片 | 可宣布完成的层 | 仍未知时如何处理 |
|---|---|---|
| K 编辑格式 | 本次字段的D、.ksp P及调用方U | 原生源/设备映射待验可继续；新对象编译明确拒绝 |
| N 原生源互通 | 已恢复类型/配置的.sm P及原厂复开/重编译 | 未恢复活动字段保持只读或拒绝；整文件归档不冒充可编辑 |
| M 多页/配置模型 | 稳定ID、引用、迁移和事务可用 | 多页设备C由阶段5闭合；不得把只保存多页JSON叫已能下载 |

完整阶段退出还需S01-01至S01-09在声明范围内完成；未恢复其他类型可按类型列边界，而不是用一个“格式已完成”覆盖整软件。当前状态：**0.8.0已实现K层多页/稳定引用/schema9迁移及既有五类单页适配；多页N语义/C、完整活动配置和其他对象仍有明确待验边界。最新逐任务结果见末尾恢复点。**

## 2. 前置输入与接续规则

开始先读取阶段0的基线/问题登记结果、[覆盖矩阵](控件文档与实施覆盖矩阵.md)、[待验核销表](复刻待验核销记录.md)及A05。保留原始308候选快照，不重排U-ID；本阶段问题使用A05中的Q-S01-001..004，新发现追加ID。

必须具备以下输入，缺失的只阻塞相关子任务：

1. 当前源码身份与修改前文件SHA；执行程序修改时再检查git status并遵循工作区修改日志/Git规则。当前文档任务不修改程序。
2. 原生安装路径及原件SHA；后台运行如使用已知私有副本，单独记录其SHA及差异，不能称未修改原件运行。
3. 现存正例：`samples/native-device-test/CodexProbeTest.sm`、`CodexProbeText4.sm`，以及`samples/bit-button`、`word-button`、`lamp`、`function-button`各.ksp；所有路径相对KinSealStudio根。
4. 已保留的5类实施/源交接报告，见第3节。历史.scratch缺失不阻塞已有证据读取；缺少某个新类型原厂源时，按S01-04采集最小样本，不制造模板替代正例。

原生调查按“问题→最小样本→后台运行/源结果→结论”推进；若需要REA，先复用[已导出证据](复刻路线图证据/REA-20261110.json)，只有具体缺口才开定点分析。运行原生编译必须串行，避免跨私有桌面编译互斥误判格式失败。禁止抢占用户窗口/键鼠。

## 4. 按顺序执行的任务

### S01-01 冻结格式基线与回归入口

**输入/定位**：第2节样本、project_model、native_project_codec、CMakeLists中的KinSealNativeSourceTests、各properties模块。

**步骤**：

1. 记录当前源码、样本和现存报告SHA；为本次切片列“字段/类型/配置/层”支持表。把已缺失历史路径记为线索，不当作可运行输入。
2. 按A05将.ksp、.sm、编译段、容器、上传快照分五类；确认实际调用入口：HmiProject::load/save、import/exportNativeProjectSource，旧native_test_project只用于旧模板回归。
3. 列已有回归的实际夹具路径；测试函数引用不存在的旧.scratch时先标记不可复现项，再将最小必要夹具整理到tests/fixtures的后续变更清单，不能靠跳过测试制造通过。
4. 在本阶段执行记录中填写源码身份、支持范围、测试可复现性和缺失证据。不要为了文档任务运行整套构建。

**验收S01-A01**：每个输入可定位；历史通过、当前能运行、当前未运行分别标记。负向：头能识别但主体未知的.sm不得进入“语义可编辑”正例。

**恢复点**：仅形成基线，原工程不变。后续每任务单独保留一个可回退源码版本及小样本，不制作整个安装目录副本。

### S01-02 建立工程领域模型和稳定引用

**前置**：S01-01；阶段2工程管理UI的字段定义可逐项输入，不要求全UI完成。问题Q-S01-001/003。

**定位**：project_model.h/.cpp、plc_address.h/.cpp、各properties、mainwindow工程保存/选择调用处、canvas_editing等所有直接访问project.objects/pageName的调用点；修改前用rg枚举，不能只改头文件。

**步骤**：

1. 先列实体：工程、目标能力、连接、普通画面/窗口/键盘/Logo、语言、图片、宏、采集组、报警、配方和资料传输。每项写稳定ID、名称、所有者、顺序、是否可删除，以及引用它的字段；尚未调查的配置用明确未实现实体，不填猜测默认。
2. 为当前单页→多页设计迁移：旧objects/pageName唯一地迁入第一个普通页面，保持对象ID、layer及group；明确“当前编辑页”“设备启动页”不同。当前activeLanguage继续只作编辑态，启动语言另据原生系统字段维护。
3. 统一引用按稳定ID，列表索引只在原生保存/设备编译时派生；复制产生新ID并重写组内引用，跨页移动保留或映射引用的规则由原生调查确认。
4. 为删除/改名/复制做事务：先收集受影响引用，确认原生处理行为，再一次提交；取消时页面、资源和选择状态一起回滚。禁止先删资源再报告被引用。
5. 将能力查询独立于显示名称：能编辑、能.sm导出、能编译分别询问，避免新对象仅因为可绘制就进入下载路径。

**验收S01-A02**：旧5类.ksp迁移后的序列化语义与迁移前相同；未变对象ID/层次/资源哈希保持；当前/启动页语言不串改。负向：重复ID、悬空引用、跨工程图片ID冲突、非法启动页均有定位明确的失败；失败当前工程不变。

**恢复点**：先保留旧schema读取与单页编译适配器；多页C未知时只允许编辑保存，多页编译明确拒绝，不能截取第一页继续。

### S01-03 .ksp版本、迁移和损坏输入

**前置**：S01-02本次新增实体定义；A05第3节。

**步骤**：

1. 保留schema1..8读取测试，逐个核对原有触发条件；新增多页/配置使用新schema。保存选择最低可表达版本或统一新版本须写明，旧版本错误不得通过手改版本号绕开。
2. 为每个字段写“缺省/显式空/null/未知枚举/越界”的规则。未知JSON字段策略必须显式设计：可保全的extension袋需有所有者和版本边界，不可理解的活动功能拒绝；当前实现不自动保全全部未知键。
3. 写迁移链和幂等性：旧文件加载后保存再加载，核心语义不变；低schema携带高能力不静默接收；未来schema读取失败时不改原文件。
4. 资源先校验后提交：图片Base64/真实解码、宏源码、connections、快照大小；限制值标Lite保护而非原生极限。UTF-16代码单元、UTF-8磁盘字节、二进制长度分别计算。
5. save使用原子替换；磁盘满/权限不足/短写不得覆盖原有效工程。只对该真实事务新增必要回归，不为纯文档镜像实现添加测试。

**验收S01-A03**：至少覆盖schema1..8各一个最小正例、混合5类新版本、资源/快照/草稿往返。负向包括未来schema、重复ID、伪Base64、截断JSON、非法枚举、错误对象专有属性组合、超资源上限；断言输出参数/原有效文件未改变。

**恢复点**：始终保留原始输入，不覆盖迁移前样本。新格式失败可回到旧程序/旧工程；不要把旧程序打不开新schema误判为迁移失败。

### S01-04 扩展原生typed结构，先恢复边界

**前置**：S01-01；按需接收阶段4的单控件手册。问题Q-S01-001/002。

**步骤**：

1. 先复用SourceReader、SourceDocument的安全读取与字段span机制；不得把源文件当640B块、不得扫描偶然字符串替换。
2. 每个新增type先做最小样本：空工程A；仅一个默认控件B；只改一个字段C；同字段边界D；已知对象前/中/后混入新type E；同时保存并原厂重开。记录输入/源SHA和对象位置。
3. 有变长分支时单独采样：空/单/多语言、无图/Pixmap/Rectangle、列表0/1/多项、状态增减、引用有无、嵌套图元顺序。查Qt typed写入/读取的具体宽度和顺序；只用字符串或反编译常量不能证明分支已可用。
4. 实现结构读取先输出字段路径、kind、start/end；要求完全消耗对象和文件。再接语义import，最后接export；每一步分别写支持表。
5. 输出结构规范至少包含：入口type/subtype、前后公共结构、字段序列、条件分支、计数/长度单位、null、保留span、所有外部引用、EOF规则。offset未恢复写待验ID，不能填写推测值。

**验收S01-A04**：新type在单独/混合/调序样本中全部边界正确；未编辑可逐字节还原，单字段编辑经原厂复开再编译有对照。负向：截断每个变长块、奇数QString、恶意计数、未知子图元、尾部垃圾、未知version，不改变调用方工程和字节输出。

**恢复点**：先只读识别，完整语义未恢复时仍明确拒绝编辑该对象；即使识别出下一对象位置，也不自动开放透传。

### S01-05 原生保全、隐藏字段与冲突取舍

**前置**：S01-04对应type边界，Q-S01-002/004；[已有差异和待验](复刻待验核销记录.md)。

**步骤**：

1. 对字段分成活动已映射、休眠已保全、不可表达活动、未知边界四类；分别采取编辑、原span保留、只读/拒绝、整文件归档/拒绝。不能把四类都称“支持”。
2. 源改动只作用于typed字段和必须同步的计数/引用。未改metadata的逐字节保全单独断言；新对象用真实已核原厂seed，不复制其他subtype伪装。
3. 对切换行为做矩阵：单态/双态，5→2→5，勾选/取消无图，隐藏语言/删语言，同文/分语言，禁用条件→启用。记录原生是保留、删除、归一还是报错；.ksp可保留更多草稿但.sm的能力边界要公开。
4. 已知原生缺陷逐项记录“原生观察→产品选择→影响层/验收”。本轮已选交互一致、缺陷明确取舍；如已有功能按钮Space不互斥/代理项问题，调用既有报告，不把脏值当必须复刻的功能。
5. 限制nativeSourceSnapshot的角色：与当前模型匹配后才能更新；快照被篡改或源配置不匹配就拒绝，不能用哈希关闭全部守卫。

**验收S01-A05**：未改隐藏span一致；活动条件新启用时生成规范有效数据；取消不污染原快照。负向：无法表达的每语言样式、未知活动地址/宏变量、损坏快照、冲突同文标志均有清晰拒绝；不丢值后继续导出。

**恢复点**：保留原.sm和.ksp两者；任何“兼容保存”失败退回原文件，只提示无法导出，不覆盖原生源。

### S01-06 系统/配置节点、引用与语言

**前置**：S01-02/04；阶段2配置窗口规格；Q-S01-003。

**步骤**：

1. 按系统、工程、画面、采集、报警、配方、宏、资料传输分块采样；每次只改变一个活动字段，另采禁用残留字段反例。原厂保存重开与编译分别比对。
2. 记录每块字段表与引用表：源字段、模型键、启用条件、默认/范围、原生改名/删除效果、设备产物归属和Q-ID。缺C映射时允许K/N切片，但不撤销设备默认配置守卫。
3. 明确页面/窗口/键盘的不同角色、ID空间和启动引用；不能用数组下标充当原生page ID。
4. 语言列表变更同步翻译、图序、startup映射；activeLanguage不影响启动；源按语言独立样式不能表达时设计新模型或拒绝。
5. 默认配置指纹只归一已有明确证据的字段；放开某个新配置后，只扩大该字段白名单，不移除整块校验。

**验收S01-A06**：每个开放配置都能新建→保存→关闭重开→原厂复开；删除被引用节点的确认/取消/错误有证据。负向：非法ID、丢失启动页、配置镜像不一致、语言目标越界、禁用字段人工激活明确拒绝。设备C未闭合列为阻塞，不靠模板编译“成功”跳过。

### S01-08 整理格式规范和最小语料

**前置**：本次切片S01-03..07；A05作为共同事实入口，新增字段事实先更新相应功能子规格。

**步骤**：

1. 为每语料写sample ID、来源类型（原厂UI/产品源经原厂编译/人工注入）、原厂SHA、输入SHA、操作、输出SHA、支持层、预期。失败/空白工作副本不计正例。
2. 原件源和最小编译段保留一份；把分析报告指向它，不为每个任务复制整个目录。只有新语义/新边界才新增样本。
3. 规范文件必须能独立说明容器、原始值、规范化、引用、错误和兼容；原始span或复杂源语法保存在专题子文档，而非粘贴大段反编译。

**验收S01-A08**：从文档任一已恢复字段可追到现存样本/测试/报告，至少一个原厂源正例及一个明确拒绝反例。相对链接全部存在，历史缺失路径作为纯文本线索注明，不设硬前置。
