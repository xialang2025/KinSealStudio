## 2. 已有包格式与限制来源

| 项目 | 当前已核定值/布局 | 适用边界 |
|---|---|---|
| 编译链 | ADS1.2 `armcc→armlink→fromelf`，ARM920T，ELF32 LE ARM提RAW | 工具与参数从现有编译器实际调用逐项抄录；不能直接把AXF当RAW |
| SDK选择 | `KINSEAL_ARM_SDK`→QSettings的`armSdkDirectory`→程序旁`arm-sdk` | 当前产品策略；原生路径界面另核 |
| 所需文件 | `validateDeviceMacroSdkDirectory`中完整required列表 | 后续任务必须读取函数，不根据示例漏DLL/库 |
| MarcoRun头 | 有效数u8；byte1=FF；2..101为100个flag；102..301为100个LE16 RAW长；到1023保留 | 普通宏生成器已核最多100；flag其余位义未恢复 |
| 机器码 | 从1024开始按实际长度连续串接 | 容器不按1KiB填充 |
| 目标RO/RW | RO0=80520400；下个RO加alignUp(rawLen,400)；RW=80440000+i×400 | 十六进制，仅当前AMT配置；不得推广其他固件 |
| MarcoVar | 每宏904B：4B头+25×36B地址项，头+2为变量数 | 本版零变量块只证明零变量场景；类型表见协议16.2 |
| ANSI与源格式 | `.sm`源码QString UTF16BE；SDK输入用当前系统ANSI且要求无损往返 | 不能直接改为UTF8后声称等价 |
| 本版保护 | 单RAW≤65535B，总包≤20000(hex)，RW/ZI≤每宏1024B，要求Macro_Entry在RO首地址 | 这些是已核实现保护/型号约束，未普遍证明原生UI均如此 |
| 本版进程保护 | 单步骤30秒、总120秒、日志256KiB上限 | 见源码常量；产品选择，不是宏执行时限 |

宏名称按QMap排序并同步按钮索引是当前产品一致性策略。2026-11-14已证原厂三宏样例SetLB1→zeta→Alpha按创建序显示，保存后以新进程重开仍同序；它不证明编译包或禁用过滤顺序。产品QMap策略与原厂树序有明确差异，S08-03仍需恢复有效编译索引，不能说原厂强制按名称排序。

## 3. 顺序任务

### S08-01 · 宏管理器和编辑器完整规格

1. 后台枚举工程树宏节点右键、工具菜单管理/查找、创建/复制/重命名/删除/导入导出/编辑全部实际入口及嵌套窗口。
2. 对空工程创建普通宏，逐项记录名称、源码、启用、调度类型、变量表、编译/检查/帮助按钮的存在性与标签。尚未发现的控件写“未发现/待核”，不预设与常见IDE相同。
3. 对每字段记录类型/默认/边界/排序/错误文本，源码框换行/Tab/编码/查找行为、修改后确定/取消/关闭的dirty状态。
4. 绑定宏的控件打开编辑后取消；删除/重命名被引用宏，记录提示、引用迁移、撤销/重开及源文件差异。公共禁用宏组仍不得开放。
5. 形成`S08.editor.*`字典与启用矩阵（普通/初始化/全局/周期×启用×有无变量×有引用），D/U只按查明的子集关闭。

### S08-02 · SDK配置与可重复编译

1. 静态读取现有required文件与参数，从输入manifest校验工具/库哈希；路径含空格/中文、目录缺文件、错误位数/版本分别设计负例。
2. 实施阶段运行在本阶段私有临时目录，不改变系统PATH或SDK文件。原始源码和生成ANSI字节均哈希记录，遇无法往返字符时在编译前拒绝。
3. 同一最小宏重复编译，再只改一个常数，解析AXF入口、RO/RW/ZI段和RAW；保留对照差分而非整套重复SDK副本。
4. 失败/超时/取消时中止受拥有的子进程，保留截断标志和首个诊断；没有所有宏成功前不替换有效包/绑定索引，不打开USB。
5. 复用既有`KinSealDeviceMacroTests`并使用本批`KinSealStage8CompilerTests`覆盖真实/合成SDK；正式轮次和结果见[阶段8验收](../docs/阶段8宏编辑编译与验收.md)。编译成功C只代表限定工具链与输入，不记E。

### S08-03 · 名称、索引与编译状态

1. 制作2宏不同名称/不同代码，交换创建顺序、列表顺序、重命名、启用状态、插入编译失败宏及删除中间项。每次保存重开、原厂重编译。
2. 同时对照`.sm`宏源码/MD5/绑定、MarcoRun有效数/flag/长度/顺序、MarcoVar槽与type10按钮宏索引。
3. 将“编辑器选中索引”“源引用”“有效编译索引”“运行入口地址”列成映射，失败宏不能让后续按钮跳到错误宏。
4. 未核启动/系统flag时不设置未知位；若需支持先补容器生成函数和单变量样本。

### S08-04 · 地址变量表

1. 用原生允许的每种变量类型分别新增1项，变地址族、读/写属性、长度、变量数，重复编译；变量0..25边界来自原生窗口/生成器共同确认，不仅按包大小推导。
2. 对照每904B宏块的头和36B槽：通用地址字段、+3字长、+5读写、+6宏类型、+8数值地址；类型索引与按钮条件枚举分离。
3. 确认变量源声明/宏头的shared slot与`macrogetData=804C5070`关系、读前同步与写后提交时序。静态布局不能证明设备何时交换。
4. 与阶段9对齐外部地址扫描、跨字范围、连接/节点。未恢复时继续明确拒绝有变量宏，不能填零块假装已支持。

### S08-05 · 初始化、全局、周期和事件调度

每种原生实际存在的调度分别建立：触发条件、频率/单位、使能、忙时重入/丢弃/排队、触发合并、画面切换/启动/断电、错误结果、调用优先级与关闭。至少按帮助种子列全局/初始化/画面/按钮；周期可能是全局条件而非独立类型，须核V5.1字段。值全部从V5.1窗口/源/编译/可控运行取得；不得猜周期或线程模型。

先用mock宿主调用或可控时钟验证调度器结构；保留“宿主模拟”证据级别。ARM设备宏不能直接作为x64函数调用。离线模拟按原帮助不支持宏；兼容模式不因本阶段实现宏调度就自动开放离线执行。

E样例依次：启动仅写专用内部计数、周期递增、按钮触发写LB、变量读写、连续触发、编译失败宏不入包。真正HMI行为由阶段10另行有授权时执行，当前只写测试计划。

### S08-06 · 统一权限和发布边界

按控件建立`macroBindable`能力及引用来源；指示灯/功能按钮禁用必须在UI、直接文件校验、源导出和编译四处一致。更新帮助要区分宏编辑、宏编译、宏下载和宏运行；SDK缺失时允许无宏工程正常使用，不捆绑未知授权SDK。
