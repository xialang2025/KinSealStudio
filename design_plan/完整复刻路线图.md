## 1. 完整复刻的目标和边界

完整复刻需要覆盖：主窗口及全部确认入口 → 工程/画面/窗口/配置管理 → 绘图与控件属性 → 工程持久化 → 原生源工程互通 → 设备编译 → 下载/上传及介质包 → 离线/在线模拟 → 对应固件上的显示、触控和PLC联动 → 部署与历史工程兼容。

先保持现有AMT型号和固件完成闭环，再扩机型。LT779及其UI_Editor/SDK应作为另一套“目标运行时+资源编译后端”单独立项；不能把KinSeal的.kns或640字节控件记录改个扩展名就视为适配。若以后要求LT779兼容，要另给固件解析器、存储布局、字库/图像格式及下载协议建立契约。

复刻保留原生真实的禁用、空页、字段残留、状态顺序等行为；若选择修正原生缺陷，必须在差异表中写明并由产品范围决定。原生帮助中出现、V5.1尚未确认的功能先列“待核”；本版自身的100控件/单画面等限制不能反写成原生上限。

### 1.1 分层完成标准

每个控件、工程配置和工具命令均建立下表的独立状态，不能用一个“已完成”覆盖全部层次，也不按手册数量推算整款软件完成百分比。

| 维度 | 通过所需证据 |
|---|---|
| D 行为规格 | 入口、窗口/页签、全部字段、默认/范围/单位、启用矩阵、事件与错误、确定/取消/重开均有来源；未知项单列 |
| U 编辑交互 | 原生与复刻执行相同操作，结果/禁用/焦点与快捷键一致；合成点击失败不得当作原生禁用 |
| P 持久化 | 新建、保存、关闭重开、复制、撤销、语言/状态切换后值保持；支持范围内.sm往返及隐藏字段不丢 |
| R 渲染 | 属性预览、画布、解压后的设备图一致；字体、奇数宽、Alpha、重叠和层次分别比对 |
| C 编译 | 记录字段、引用索引、扫描表、图帧顺序、语言布局、压缩/对齐和包结构与原厂对照；不支持数据明确拒绝 |
| T 传输 | 指定程序哈希、指定工程哈希、目标型号、每段长度/确认、提交、重启分别记录 |
| E 设备运行 | 屏端实际显示/触控/寄存器变化/权限/故障恢复有刺激与观测结果；USB ACK不能代替 |

“D已形成、U/P/R/C部分通过、T有历史回执、E待确认”是有效状态；“全部全链路完成”需要这些维度在声明范围内同时闭合。

覆盖矩阵现已逐行列出D/U/P/R/C/T/E。表中的“编目”“历史局部”“现场局部”均不等于整层通过；只有列明字段/组合/机型/版本范围并有对应证据，才可把该范围升级为“通过”。本轮只复核文档，未重新执行表中历史测试。

### 2.2 格式与兼容边界

- .ksp是本项目的版本化编辑格式；源码当前支持schema1..8，新增功能按钮使用schema8。后续扩展应有显式迁移和旧版拒绝规则。
- .sm是原生编辑源工程；现有typed codec恢复了5类控件的部分/既定范围，不代表任意原厂工程均能编辑。
- .kns、.laz、load.bin/Usbload.bin、各dat/bin属于编译或分发产物；upLoad.knr用于原生可编辑快照相关链路，精确关系以格式调查为准。不得相互混用。
- 当前已实现设备范围主要为单个800×480画面、1..8语言、最多100个受支持控件；其他PLC配置、多页面、部分透明动态重叠在USB前拒绝。这些是复刻版当前范围。
- 新增功能先扩模型/codec/编译校验，再开放下载入口；不能在画布支持后静默丢弃未恢复字段。

### 4.3 证据与冲突处理

运行事实优先核对“真实Qt属性/用户等价事件→确定→落盘→重开→编译”的链路。Win32 IsWindowEnabled和PostMessage点击可能不能反映Qt真实状态；某次合成点击无效不能证明原生禁止该功能。强行setChecked/setValue还可能跳过信号及归一化，必须另做保存/编译验证。

每条结论记录证据类型：V（带身份的运行观察）、H（帮助）、B（静态资源/反编译）、I（推断）、T（传输回执）、HMI（现场运行）。新证据与旧手册矛盾时保留“旧结论→新证据→采用结论→影响文件”记录，不能简单按文档更新时间认定真伪。

重点先核销已有5类实施的旧缺口：指示灯禁用宏/通知、状态数2..32及归一化；功能按钮禁用宏、UTF16单元字符限制、设备本地字节和隐藏ON图；静态文本后续权限/多语言编译。已解决项从待验转为已补证并链接来源。

首批[核销记录](复刻待验核销记录.md)已将功能按钮宏禁用、指示灯宏禁用及状态数2..32三个事实按历史补证关闭；多态完整渲染和18功能设备时序继续追踪。原CSV的U-308是说明性结尾，已标记为非问题，仍保留在308条原始提取数中。关闭这些事实不等于对应控件D/U/P/R/C/T/E全部通过。

原CSV冻结为2026-11-10候选快照，引用使用“快照日期+线索ID+来源哈希”。正式问题另用稳定Q-ID，新增只追加、拆分保留父子关系、合并保留旧ID去向。既有自动盘点脚本是历史提取工具，会覆盖CSV和矩阵，不能直接用来维护本版人工核销内容；重新盘点应输出新快照并对照合并，保留旧文件及编号。规则和快照哈希见核销记录。

| 9.2 原生模块ABI与设备模板编译 | 以Modbus RTU作为首个纵向样本：DllFun回调、操作分派、请求/响应元数据、协议bin/AddrPara/扫描表位置、读合并与写命令 | 原厂相同输入的结构/帧模板/引用对照；普通DLL执行结果不能冒称固件通信通过 |
| 9.3 PC在线模拟传输后端 | 串口/USB转串口/型号确有的网络连接，收发、CRC/响应、异常码/超时/断线、读写队列和并发 | PC到受控PLC/模拟从站联测，日志可回放 |
| 9.4 HMI固件解释与实机联动 | 保留当前原固件时先验证编译模板是否被其解释；只有证据显示必须修改固件才另行立项 | HMI到PLC真实读写、地址/数据类型/扫描/多端口联测 |

安装目录51个PlcDll是文件数，未必等于51种独立协议，也不代表已经全部恢复；应按机型/连接列表和协议变体去重。初始顺序：默认Modbus RTU完整闭环 → 客户实际需要的下一协议 → 多连接/多站；不先承诺全量重写设备驱动。

资料传输配置另测定时/位触发、位/字/双字、长度/源目标跨度、同PLC及COM1/COM2限制与内部中转；读、写和触发扫描都要体现在编译器。
