包内 23 个 PE 均为 x86_64。EXE 直接导入 Qt6Core、Qt6Gui、Qt6Widgets、Qt6Svg、Qt6SerialPort、MinGW pthread 及 Windows API；Qt6Network 由已部署插件等依赖引入。除 EXE 外的 22 个 PE，与本机 Qt6.12.0/MinGW 安装中相应候选文件 SHA256 逐字一致。详细 hash 保存在机器盘点中。

17 个 Qt PE 的文件版本为 `6.12.0.0`，本机检查数字签名有效；但本机安装中 Qt SBOM 所记 SHA1 与这 17 个实际文件**全部不一致**。已保留 SBOM 路径、hash、条目和实际 hash；差异原因未查明，不用“可能是签名”替代证据，不把 SBOM 写成这组二进制的认证。签名有效同样不能证明可再分发许可。

## 缺依赖场景及真实结果边界

机器策略提供 `DEP-01`～`DEP-10` 的安全测试方法和预期：去开发环境 PATH、缺核心 Qt、缺 qwindows、无原厂目录、缺 USB、缺 SDK、缺字族、无外部图库、损坏图片、只读安装目录。**这十项在静态盘点中均记 `not_run_by_static_audit`**；本轮真正执行的结果应以部署测试原始回执为准，不能将本表预期改写成 pass。

缺 Qt 核心 DLL 属于 Windows 加载器阶段，应用可能根本没有运行，不能要求它弹出自己的友好错误。缺 SDK 的宏编译已存在明确中文目录/文件缺失诊断，普通无宏工程应独立可用；具体退出码仍以本轮命令为准。缺 libusb 的源码错误为“系统缺少 libusb-win32 驱动运行库”，缺导出为“系统 libusb-win32 运行库缺少必要接口”；本机库和设备在线，本轮不会重命名系统 DLL、卸载驱动或向在线设备发送故障测试下载。

字体诊断保存 `requestedFamily`、`resolvedFamily`、`exactMatch` 和 Qt 版本，足以揭示替代字族；现有代码不会因每个控件字体替代自动弹窗，用户需要在工程副本核对显示。普通文件的只读属性也不等于标准用户无写权限，真正权限/DPI/多显示器条件不能由不等价的模拟伪造通过。
