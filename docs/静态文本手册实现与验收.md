# 静态文本手册实现与验收

本文保留2026年11月8日静态文本阶段的验收历史。0.4已接入多语言及显现文本的type28设备编译，当前支持范围见[位按钮设备编译台账](位按钮设备编译实现.md)；文中旧版拒绝条件与包目录不代表当前版本。

日期：2026 年 11 月 8 日。实现标记：`//20261108-14 add/change`。

依据：[静态文本功能与交互复刻手册](../design_plan/静态文本功能与交互复刻手册.md)。用户已确认本轮“先验收编辑与外观，权限实机验证稍后”。本文记录这一阶段的实现和验收结果，**不能作为“手册所有设备功能已完成”的声明**。

## 原厂外观证据

原厂隔离桌面的 13 种默认白色背景/红色前景预览已保存到工作区 `.scratch/kinseal-statictext-20261108/native-style-corpus/`。预览的实际填充区域为中心 100×100 像素。新预览按此尺寸绘制，而非填满外部预览边框。

- 对所有 13 项，对照去除中央文字区域的填充像素，最大单通道差异不超过 2（8 位通道）。由原厂截图采样的 8 个位置及原图哈希保存到 `tests/fixtures/native-static-text-fills.json`，自动测试容差同为 2。
- 原厂“横向/纵向过渡”为前景色到背景色，对称过渡在中点达到背景色；斜向和两个角辐射按实际截图修正方向。中心辐射的默认预览为背景色中心、前景色边缘。
- 原厂粗体 `TEST` 的完整 RGB565 帧已由原厂 LZO 解码器独立还原；新版相同输入的 SHA-256 为 `2bdc57203e07323fb8de6b8bb5b0d156bba82669a549799f2413672edf1c177e`，与原厂逐字节相同。
- 上述结果只覆盖当前 100×100 默认填充预览和指定字体粗体样本。非方形渐变、自适应具体算法、其他字号和字体、透明叠加及超长文字的全部原厂边界仍未穷尽。

## 数据保存与兼容

`HmiObject` 新增 `staticText`、`layer` 和 `group`；工程保存语言列表及当前语言。静态文本记录保存每个外观与权限字段，包括当前未启用条件中的输入值。对象经过移动、缩放、复制、分层及撤销重做时，整份属性一起保留。

含新增属性、分层、组合或非默认语言配置的工程保存为 `.ksp` schemaVersion **2**；旧 schemaVersion 1 仍可打开。这样旧编辑器会拒绝读取扩展工程，避免旧版打开后保存时悄悄删除新属性。旧单文本样本保留已验证的旧栅格路径，原有 TEST/AB12/中文/多行回归继续执行。

本版的工程数值保护范围：字号 0.1–4096、字距 −4096–4096、填充透明度 0–255；文字框在 800×480 画面内。整数比较值按所选位宽校验，浮点值须可表示。**这些是当前实现的存储/输入保护，不是本轮已证明的原厂全部输入极限。** 编辑器仍有此前的 100 控件上限。

## 下载能力与尚未完成项

当前可独立编译下载 **一个静态文本、不启用显现权限、单一工程语言** 的画面。新增字体、颜色、填充、字号、字距及字体标志会进入 RGB565 栅格；原有 USB 状态机负责传输。`upLoad.knr` 仍只恢复了文字和几何字段，尚未恢复全部外观属性的原厂可编辑快照，因此不能声称从设备上传后能在原厂编辑器完整恢复本版外观属性。`.ksp` 保留完整编辑数据；旧固定 `.sm` 导出会拒绝新增属性，避免无声丢失。

以下项目尚未完成，不能以 PC 预览代替设备兼容：

1. **显现权限的设备编译与动态运行**。原厂离线差分证明它会新增 `ControlPara.dat`、`ControlPixel.dat` 并改变图片长度表，当前只恢复了部分结构，地址与条件的全部字段尚未验证。启用显现总开关的工程在打开 USB 前拒绝；不把动态权限烘焙成永久可见文字。
2. **设备多语言、多个静态文本的独立编译**。上位机可以编辑和保存，设备编译仍保留单文本边界。
3. **外部设备地址选择与权限模拟运行**。没有配置完整 PLC 协议地址表；多个条件的 AND/OR、最低等级等值边界、误差公式及 32 位字序仍需运行证据。当前不提供假定这些规则的权限模拟器。
4. **完整原厂外观兼容**。非方形渐变、全字号/字体、自适应、不同透明度等仍需更多原厂和设备差分；原有长英文有少量字距差异。

## 验证入口与交付

执行 `Build.ps1 -Deploy`：构建编辑器和 Qt 测试程序，运行离屏事件测试、旧下载样本回归和便携包验证。Windows 真实字体与截图使用 `py -3 tools/run_private_static_text_tests.py` 在独立桌面运行，不切换用户桌面；该辅助工具不随运行包部署，也不是新版运行依赖。

当前交付目录为 `dist/KinSealStudioLite-StaticText/`；窗口标题带“静态文本版”，避免与旧目录混淆。示例在 `samples/static-text/`：外观与样式验证可用于单文本下载，显现权限示例用于编辑/保存和后续协议验证。

## 本轮验收结果

1. `Build.ps1 -Deploy` 成功，完成 Release 构建、内置 TEST 数据校验、工程往返、旧文字与几何的编译回归、拒绝路径、样例读取和便携包自测。Qt offscreen 测试为 11 通过、0 失败、1 跳过；跳过项需要真实 Windows 字体引擎，另在私有桌面执行。
2. 私有 Windows 桌面的 Qt 测试为 **12 通过、0 失败、0 跳过**。覆盖完整属性保存与回填、取消事务、依赖联动、语言草稿、画布拖框/缩放/撤销重做、新建入口、颜色与地址输入事务、原厂字体/填充证据，以及工程语言切换后的右侧属性同步。日志为 `build/static-text-windows-tests.txt`。
3. 使用新版便携程序的正式 `--download-single-text` 入口，后台下载 `samples/static-text/外观与样式验证.ksp`：退出码 0，USB 数据段与提交命令均获设备确认，重启命令已发送。结果保存在 `build/static-text-hardware-download.json`；本次没有调用原厂程序、原厂 DLL 或 Python 下载桥接。
4. 用户现场确认 **“文字、样式和位置都正确”**：屏幕显示两行“静态文本验证AB12”“粗体 + 下划线”，白色文字、粗体、下划线和蓝青渐变背景正确。样例文本框为 `(200,140,400,160)`，微软雅黑 28，字距 2，纵向对称过渡，填充透明度 200。此结果仅证明该组合样例的显示，不能扩大为全部字体、透明度和渐变算法均与原厂相同。
5. 完成只读复核后，修正工程语言切换时右侧文本未同步、后续应用可能覆盖当前译文的问题；回归确认中英文分别保留。此修正未改变已验收样例的编译或 USB 传输逻辑。
6. 默认外观与权限页的真实 Windows 后台截图分别保存在 `artifacts/static-text-default.png` 和 `artifacts/static-text-permissions.png`。测试没有切换用户桌面，没有操作用户鼠标键盘，也没有关闭用户正在运行的旧版程序。

## 用户试用步骤

1. 启动 `dist/KinSealStudioLite-StaticText/KinSealStudioLite.exe`，核对标题中的“静态文本版”。
2. 新建工程，点击“静态文本”，设置内容、字体和填充；按“确定”后在画布拖出矩形。
3. 双击文本框检查属性回填；编辑后“取消”应保持原对象，“确定”应更新画布。移动或拖动控制点可调整位置与尺寸。
4. 保存为 `.ksp` 后重新打开，检查文字、颜色及尺寸。新属性必须使用新版编辑器；旧版本会拒绝 schemaVersion 2。
5. 下载本阶段的工程时，保留一个静态文本、一个工程语言，并关闭“显现”总开关；让屏进入 USB 下载模式后点击“下载工程”。显现权限可另行编辑保存，设备端编译与动态验证仍待后续完成。

当前工作区及 `KinSealStudio` 子目录均不是 Git 仓库，无法执行项目规则要求的 GitHub 自动提交推送；文件和构建结果已保存在上述目录。
