## 原厂Space界面缺陷与字符边界

原厂[Space]控件对象名为空；真实点击后其checked=true，同时Enter仍checked=true，见`keyboard-57.json`。该控件没有与其它键正确互斥，UI样例保存key0。此事实与合法源key8可编译分别记录，产品支持合法key8，不把Space偷偷改成Enter。

原厂emoji会被maxLength1截成孤立高代理项；产品明确拒绝活动键盘字符中的孤立代理项。原厂“Unicode”字样不代表设备字段是UTF16；已观察到设备只保存Windows本地编码首字节。

调查期间曾并发启动多个私有桌面原厂导出进程，触发全局确认：**“有其他组态正在编译中，继续可能会造成文件冲突，是否继续”**。截图`diagnostic-bilingual-single-control-hint.bmp`。这是原厂跨桌面编译互斥提示，已改严格串行，不能归因Space或多语言编码。失败的空白/未完成输出均不计作成功样本。

实际设备触碰后的系统弹窗、重启、键盘输入等行为未由本子任务现场观察。主代理已报告16控件双语联调USB传输成功；该信息不扩展为所有固件动作已通过实屏验收。
