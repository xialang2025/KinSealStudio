# AMZ070 开关语言帧与指示灯监视字段

本次核对原厂 KinSealStudio V5.1 写出的开关控件记录和 AMZ070W01 应用固件使用这些记录定位图像的方式。偏移均从单条 640 字节的 `ControlPara.dat` 记录首字节起算。所有实验证据来自普通工程的本地编译、历史原厂产物和原始机器指令在内存中的执行。[固件反汇编](../../firmware_analysis/amz070w01-disasm-20261119/反汇编说明.md)

## 位按钮和字按钮共用各语种图像

开关记录的 `+0x1BC` 为 1 时，每个活动状态只需生成第一个工程语言的一组图像。为 0 时，外层按保存的工程语言顺序循环，内层依次生成同一语言的全部活动状态。原厂 V5.1 在 `0x0062C2C0…0x0062C2D2` 取得语言数，`0x0062C2FC…0x0062C309` 读取开关对象的 `+0x22F` 开关并可把循环次数限制为 1，随后才按位按钮或字按钮分派。`0x00695091` 将对应标志写入控件记录。

| 控件与条件 | 每个有效语种的图像顺序 |
| --- | --- |
| 位按钮，双态监视 | 先状态 1，再状态 0 |
| 字按钮，启用按下效果 | 先状态 0，再状态 1 |
| 单态位按钮或无按下效果的字按钮 | 仅状态 0 |
| 当前状态启用闪烁 | 先保存正常显示帧，随后保存闪烁隐藏帧 |

设状态、闪烁共同决定的单语种帧数为 `F`，每帧使用 `width × height × 2` 字节 RGB565。`+0x0C` 是本控件的未压缩图像起点，`+0x10` 是帧字节数乘以 `F`，再乘以有效语种数。每个压缩帧在 `PicLenPara.dat` 中占 12 字节索引，载荷在 `ControlPixel.dat` 中按 32 字节边界补齐。[像素帧补齐规则](ControlPixel控件帧的32字节补齐_20261128.md)

AMZ070W01 的 `0x800AA854` 将前 448 字节复制到运行时控件。显示例程 `0x80047640…0x8004773C` 使用第 0 个状态帧作为索引起点。`+0x1BC` 非零时直接使用给定的帧号，为零时叠加当前语言的字节跨度。把 Lite 生成的真实记录交给原固件的这些指令执行，可以逐个检查各语言拥有的帧地址。旧 Lite 对位、字按钮把该标志写成零，多语种开启同文时还会重复生成像素。

早期 KSP 允许两个状态分别选择“同文”。编译器只在所有**活动**状态都选择同文时设置 `+0x1BC`。双态且设置不同时仍为每个语言保存一组图像，分别绘制各状态的共享文本或翻译。只显示状态 0 的按钮以状态 0 为准。V5.1 的一个全局开关可以表示每个活动状态设置相同的工程。

## 单指示灯工程的三个监视字

原厂 V5.1 在 `0x00693FB9…0x00694001` 读取编辑器对象中的三个 32 位整数，再在 `0x00694007…0x00694018` 将监视结构写入控件记录。双态和多态指示灯都会执行这些赋值，即使编辑器在当前模式下隐藏了某项设置。历史工程中的未使用值可能保留全部四个字节。

| 原生 V122 `.sm` 的结构字段 | 原厂编辑器对象偏移 | `ControlPara.dat` 偏移 | 可核实的含义 |
| --- | --- | --- | --- |
| `switch.248.1` | `+0x24C` | `+0x188…18B` | 双态字地址模式的位序号，其他模式也复制源值 |
| `switch.248.4` | `+0x26C` | `+0x18C…18F` | 多态灯的数据类型，双态下仍复制源值 |
| `switch.274.0` | `+0x274` | `+0x194…197` | 已确定序列化位置和复制行为，完整运行语义仍待验证 |

源工程用 Qt 大端序写这些整数，设备记录用小端序。例如 `lamp-multi5-u16-r4` 的 `switch.248.1` 为 `06 12 49 08`，原厂控件记录写成 `08 49 12 06`。Lite 解析本次编译实际封存的源工程，确认单个控件为同一子型 4 指示灯，且监视模式、状态数一致后才写这三个字。这样用户修改过的活动字段会跟随最新设置，也能保留同一源工程的非活动字段。另取字地址第 7 位指示灯，开启只在 KSP 中支持的水平翻转。编译后封存的 JSON 保有翻转属性，三个设备字依次为 7、0、0。

本轮这项补写针对可唯一对应源与输出的单灯工程。11 条原厂记录共 7,040 字节。按每处不同的字节计数，旧交付版的差异为 2,385 字节，补写后为 2,312 字节，减少 73 字节。132 个比较位置中其余 59 字节原本已相同。原厂监视地址结构的其他字节还含本地写端未赋值的间隙及运行时状态，例如固件在 `0x80031834…0x80031844` 比较当前与上次监视值，随后更新缓存。`+0x19C` 在多份本地地址样本中碰巧相同，目前缺少把该字节当成所有地址统一常量的写端依据。仍需多控件的逐条对应证据，以及相同源项目在不同进程中重复编译的原始产物。

## 可复验范围

- 原厂 EXE 的 SHA-256 为 `305592b4e4bc1b15a707c7bc832c31f27ca0958b97f9c79a5b50ac6df49e907c`，固件 `AMZ070W01.bin` 为 `7f625b7a967c1ecc0ff5db1fba4d6ed68cb1d9474216e87009395f1d53a88db5`。位、字按钮各在 1、3、8 语种下切换状态、同文和两行闪烁选项，执行原厂 x86 循环的 96 个受控组合。仿真替代三个绘图回调，保留原有循环、分派及顺序。原厂历史包筛查中有非共用的位、字按钮，暂缺开启同文的位、字按钮原包。
- 六份受控 KSP 各生成八个控件。三份具有原生同文表示的工程额外导出 SM，再分别从 USB 散件和介质散件入口编译。合计 12 次工程编译、96 条记录、594 帧、864 个原固件图像地址比较。Windows 字体后端在独立桌面绘制受控的多语言文本，检查可见状态压缩帧是否按语言区分及共用。[开关回执](样例/AMZ070开关语言帧固件与原厂写端复验_20261128.json) · [复验程序](../../tests/verify_amz_button_frame_rules.py)
- 11 份单灯参考来自 Git 对象 `e3b72657` 中同次原厂编译保存的源工程和控制记录。两种编译入口分别核对 132 个原厂参考字节。另在两份源工程中各只改一项，分别覆盖活动位序号及非活动的高位整数，并比较整条 640 字节记录。三字段读出及最终整结构写入的原厂指令片段共执行 13 次，额外向局部栈填入 `AD AD`，观察到同样的两个字节出现在 `+0x182…183` 的结构空隙。新建单灯 KSP 还核对直接编译与保存为 SM 后从两种入口重新编译的整条记录。[指示灯回执](样例/AMZ070单灯监视源字段原厂逐字复验_20261128.json) · [复验程序](../../tests/verify_native_lamp_monitor_words.py)
