# V122 双语静态文本叠放与控件帧编码

`static-odd2-transparent-top` 和 `static-odd2-opacity128-top` 均含两条 `0x1C` 静态文本记录。下层是无字的横向渐变，语言数为二。上层是居中显示的字母 T，两份工程分别将上层设置为透明填充和 Alpha 128 纯色填充。两个对象均关闭条件显现。即使缺少设备现场读数，也可以从 SM 编译出这两份工程的页帧、控件帧和图长表。

## 如何判断上层帧是否包含下层图像

原厂下层坐标为 (41,53)，尺寸为 101×61。上层坐标为 (54,64)，尺寸为 55×29。由此得到上层在下层中的裁剪起点 (13,11)。从底图对应的 55×29 区域统计到 29 种不同的 RGB565 颜色。单独编译下层的基准工程和两份叠放工程的下层帧完全一致。

| 原厂上层模式 | 可见字形 | 同一帧的其余像素 | 与对应位置的下层像素相等数 |
| --- | --- | --- | --- |
| 透明填充 | 16 点均为 `FE84` | 1579 点均为页底 `C6FF` | 0 / 1579 |
| 纯色，Alpha 128 | 相同 16 点均为 `FE84` | 1579 点均为 `DA6A` | 0 / 1579 |

字形在对象局部坐标的包围盒为 (24,10) 至 (30,19)。两种填充产生相同字形位置，填充 Alpha 仅改变背景。上下两个对象分别保存各自的中文帧和英文帧。原生参考的每一对语言帧都相同。

## 编译规则和反证

1. 按对象图层稳定排序。每个对象先发第一语言帧，再发第二语言帧。四帧依次为下层中文、下层英文、上层中文、上层英文。
2. 每条控件记录为 640 字节，类型为 28。相对记录起点 `+4` 起依次编码四个小端 u16 的 X、Y、宽、高。`+0x0C` 和 `+0x10` 分别为解压像素偏移和字节数，下层为 0、24644，上层为 24644、6380。`+0x15` 为关闭的显现开关，`+0x102` 为小端 u16 语言数 2。
3. 下层两个 101×61 帧各自压缩为 249 字节，各自补齐到 256。上层两个 55×29 帧各自压缩为 66 字节，各自补齐到 96。四帧连接组成 704 字节 `ControlPixel.dat`。2400 字节的页索引后追加四个 12 字节的控件帧索引，`PicLenPara.dat` 总长 2448 字节。
4. 透明上层在默认页底绘制文字。对 Alpha 128 纯色样本，按未降色的页底 RGB (197,222,255)，将同一源色 (224,32,32) 连续覆盖两次后得到 RGB (217,79,87)，打包为 RGB565 的 `DA6A`。每通道使用 `mul(c,a) = (v + (v >> 8) + 128) >> 8`，其中 `v = c × a`。一次覆盖的通道为 `mul(源色,a) + mul(底色,255−a)`。该计算独立重建了两个完整压缩文件。单次覆盖产生 `D412`，直接在 RGB565 表面连续覆盖则为 `DA8B`。该受控输入支持这项编译计算，原厂内部调用填充的次数尚无独立跟踪证据。
5. 在 Windows 字体后端运行普通 CLI，保留工程原有微软雅黑字形。改用 Qt offscreen 插件时可观察到不同字形；同一透明样例的上层压缩长度从 66 变为 155 字节。无须连接 USB 即可完成文件比对。

## 可输出的工程及保留项

当前开放两层双语静态文本、独立图层顺序、下层完整包住上层、图形位于正常页底、下层双语无字、全不透明横向渐变、上层两个语言同字、两个控件均无显现条件和翻转的组合。上层可使用透明填充或透明度 128 的纯色填充。回归脚本同时验证下层两语言出现不同文字、上层条件显现、仅部分相交、增加第三层、纯色透明度更改为 64 时仍会拒绝发布。

这两份工程可以确定全部控件帧资源。运行时最终显示还受固件的帧选择和重绘行为影响；其他工程中的即时语言、可见状态、用户权限和下层寄存器状态需要设备运行数据。此处只核实两份原厂编译文件，未进行实屏重绘测试。

整份 `ControlPara.dat` 仍有差异，不能仅凭当前两个文件把所有剩余字节归为无效。两份原厂下层记录的 `+3` 分别为 `06` 和 `0E`，Lite 输出为零。两份原厂 `SheetPara.dat` 的 `+59` 都为 `06`，本轮比对仍有这一个字节差异。完整相等的文件、逐路结果以及未比较为相等的记录字节数见验收记录。
