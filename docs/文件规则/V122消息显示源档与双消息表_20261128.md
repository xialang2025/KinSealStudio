# V122 消息显示器的 SM、Message.dat 和 SimMessage.dat

Lite 的画布现在可以读取原厂类型 35，编辑后写回双语消息、状态数、移动方式和速度、监视字地址及显现条件。10 份原厂消息工程分别经 SM → KSP → SM，全文件逐字节相同。其中包括单态、三态、双语字号、按语言设色、U32 和受位及权限控制的样例。另用完全去除源快照的 KSP 新建双语三态 SM，再由 Lite 重开并核对文本和属性。[逐份源档和编译表的 SHA-256](样例/V122消息显示源档与双消息表_20261128.json)

## 工程文件

原厂以 Qt 4.8 大端流保存消息对象。类型号之后依次是边框矩形、背景矩形和文字三个预览子图元、组信息、公共条件与私有记录。私有区中 `head.2` 保存数据类型，`head.3` 是完整监视地址，`head.4/5/6` 分别保存状态数、移动方式和速度。公共显现条件采用工程现有的位、字、权限等级编码。

状态数据在源中出现两次。两张表都是先状态后语言。第一张逐项保存状态编号、文字、字号和文字色。扩展表还保存字体、背景色、前景色、框色、填充样式及保留字段。两个表之间的 16 位索引对应已保存的预览语言。读取时交叉核对两套活动字段，写入时同步更新；已有状态的保留字和未改动的预览数据从该对象自己的源快照保留。新增状态以已有结构生成，已有状态编号和文本可以独立更改。现有画布模型按每种语言管理一套外观，源中各状态存在独立外观且彼此不同时，保留进入原厂源文件编辑器的路径。

针对原厂双语配色样例，专项把位置、字地址、数据类型、移动方式、速度、英文文字和字号同时更改并增加第三态。将编辑结果写为 SM 并重开后逐项比较，再从这份已修改的 SM 恢复原属性，全文件重新命中原 SHA。新增工程的重开检查使用 Lite 读端；本轮没有在原厂 V5.1 窗口中打开新文件。

原厂 `state3-regrown.sm` 保留预览状态 1，`private.head.0` 和预览子项的文字可直接从原件分别读出。写回时同步实际被预览的行；编辑其他行时保留该预览，缩减状态数时将预览定位到仍存在的末行。专项另测了“KEEP-2”留在唯一状态，以及将它改为与原厂单态样例相同的“0”。在已有快照和无快照新建两种路径下，未注册语言的文字、样式、框色，以及被所有语言覆盖后无法单独存回的基准字体或框色，10 个反例全部返回明确诊断。

## 设备消息表

`--compile-native-message-table 输入.sm 新建文件.dat` 读取原厂 SM 或 KSP 中的单消息画面。输出按工程语言顺序，为每种语言依次写完所有状态。每条 104 字节的前四字节依次为文字红、绿、蓝分量和零。原厂 V5.1 在 `0x821AAD/ABB/ACB` 分别调用 Qt 的蓝、绿、红 getter，计算 `(B << 16) | (G << 8) | R`，在 `0x821AD3` 写小端 32 位。九份冻结编译的文字恰好是黑色。受控的非黑色 `#1234AB` 写为 `12 34 AB 00`，输入颜色的 alpha 不占用第 4 字节。

从偏移 4 开始是 100 字节的文字槽。`0x821B01` 调用 Qt4 `QString::toLocal8Bit`。简体中文 Windows 下，Lite 使用 CP936。原厂在 `0x821A1C–0x821A46` 清零整个槽，然后复制至多 100 个编码字节，在 `0x821A48–0x821A65` 将 26 个双字写入输出并推进 104 字节。因此 100 个 ASCII 字节可以填满整个槽，101 个会截到前 100 个。98 个 ASCII 加“中”刚好写满，99 个 ASCII 加“中”只保留它的首字节 `D6`。源 SM 仍保存完整文字。Lite 对内嵌零或无法无损编码为 CP936 的文字返回诊断。

在双语两态原件中，四个槽依次是“中文零”、“1”、“EN-ZERO”、“1”，“中文零”编码为 `D6 D0 CE C4 C1 E3`。一、二、三态单语分别输出 104、208、312 字节，双语两态输出 416 字节。冻结资料中 9 次原厂编译的整个 Message.dat 均已复现。

## 模拟器消息表与原厂窗口状态

在命令结尾加 `--simulator-session fresh` 或 `--simulator-session download-defaults` 可改为生成整个 SimMessage.dat。文件由 512 字节的小端文件头和紧接的完整 Message.dat 组成。实现范围为 800×480 的单页单消息工程，模拟器头还要求消息表长度可用 16 位数表示，且没有独立图库和宏。已有输出不会被覆盖。

| 文件偏移 | 生成方式和证据 |
| --- | --- |
| 0、2 | 单消息样例头首字节为 1，偏移 2 的 LE16 等于后续文字表总字节数。 |
| 404、408、412 | 三个 LE32 来自 V5.1 下载窗口状态。安装原件中的设置函数分别向全局对象的 `+0x824/828/82C` 写入布尔值，窗口初始化路径将它们置 1。整块复制起点为 `+0x690`。本批原厂日志中，每个独立进程首次编译取三个 0，后续使用默认下载选项的编译取三个 1。 |
| 428、432 | 此类单对象画面各为 LE32 的 1。原厂类型 35 分支调用 `0x62B498`，在 `0x62B644` 增加第一个计数，在 `0x6445B3` 增加第二个计数，后者由 `0x644254` 写入全局对象。 |
| 436 | 控件 RGB565 所需字节数，小端 32 位。原厂通过 Qt4 的 `QGraphicsItem::sceneBoundingRect` 读控件包围框，对正宽高各加 0.5 后截为整数，在 `0x62B632–0x62B642` 相乘、乘二并累加。`0x644262` 存入全局对象 `+0x844`。原厂 200×100 的九份记录均为 40,000。 |
| 512 起 | `0x644984–0x6449AD` 将消息体复制到输出缓冲区 +512，把 128 个双字复制到前 512 字节。在已对照的单消息设置下，其余头字节为零。 |

对照时先从五份原厂进程日志取编译顺序、标签及输入 SHA，再生成候选文件，最后读取原件比较。首次状态 5 份、后续状态 4 份，9/9 完整文件相同，包括 512 字节文件头。选择会话的依据不含目标文件字节。针对另一尺寸的受控 KSP，再从 SM 生成模拟文件并核对偏移 436。其他画面布局、多个消息控件以及用户单独改动三个选项的组合仍待原件复验。
