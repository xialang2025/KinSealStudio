# V122 刻度在普通画布中的打开、编辑与原格式保存

原厂六份类型 31 刻度工程现在均可在普通画布打开并另存。全部经 `.sm → .ksp → .sm` 后与原件逐字节相同，覆盖默认、方向向下、水平置顶、最大最小同为 0、六根主刻线及每两根主线间四根副线。六份均实测改名、移动后保存再重开。其中五份还将范围从 0–100 改为 1–101。另有含刻度、二维码、消息的重建混合工程通过整档还原，单改刻度名称时只改变对应原生名称字段。[六份原厂 SM 和混合工程对照](样例/V122刻度普通画布源档复验_20261128.json)

## 从原厂子图元恢复画布对象

原厂刻度自身没有独立的整控件矩形字段。默认工程把整张图拆成一根主轴、四根主刻线、四个标签、三根副刻线，共十二个子图元。Lite 把线段端点叠加各自的 `stroke.3/.4` 原点；把文字矩形 `text.head.0–3` 叠加 `text.tail.10/.11` 原点。求全部端点和文字矩形的包围范围，六例都得到 x=160、y=120、宽 200、高 100。浮点计算将默认右缘表示为 359.99999999999994，取回原厂整数边缘时计入这个偏差。六根主刻线的工程有 18 个子图元，四根副线的工程有 21 个。[刻度源读写](../../src/native_scale_source.cpp.inc)

| 原生字段 | 本次核对的含义 |
| --- | --- |
| `private.0/.1/.3` | 六例第一项均为 1，且保存完整值标签。后两项给出方向文字及边缘选择。右侧样本的选择码为 2，顶部为 3；对应 Lite 右侧 3、顶部 0 |
| `private.6/.8/.11` | 六例第 6 项均为 0，缓存标签均为整数；另外两项通过改变主刻线数和副刻线数确认。非零小数位仍需单变量验证 |
| `private.9/.10/.12` | 最大值与最小值的十进制 QString，以及 0/1 方向。原厂上下两个对照同时改变方向字符串和方向数值 |
| `private.7/.15/.17` | 两个颜色字符串和字号文本。六份原件两颜色相同，并与实际线条/标签颜色一致；标签使用宋体，字号与字体缓存互相核对 |

## 写回规则

移动时，各线条和文字的场景原点叠加相同位移，所有子图元的本地几何保持原生字节。改名写入 `group.metadata-name`。调整方向或范围时，Lite 按主刻线数量及方向算出每个整数标签。右侧刻度使用同一对象中已保存的同位数文字宽度。改变最大字符宽度、缺少相应缓存宽度或水平标签需要重新居中时，程序提示保存为 KSP。原厂左侧和底部布局、其他字号的排版，以及全新拓扑仍需确定原厂布局规则。[专项回归](../../tests/verify_native_scale_source.py)

默认向上与向下是两份独立的原厂保存。双向修改后，原厂有意义的八个差异字段全部重现，分别为四个缓存标签、两处标签宽度、方向文字及方向数值。全工程逐字段核查还定位到原厂两次保存之间另有两个取值不同：休眠字段 `common.58.3` 和末尾路径 `trailer.settings.0`。Lite 保留本次输入的两个原值。

测试对每份原厂源各尝试修改主刻线数量、副刻线数量、字号及超出已有字宽的新范围，24 次均拒绝且未发布输出。另构造触控、显现、通知及替换缓存字体四种源文件，均拒绝映射为普通画布。本专项覆盖已有原生快照的读写。独立新建刻度的原生子图元生成、上下左右全部布局、原厂软件重开当前生成件，以及设备背景的字体栅格化仍待验证。昔日原厂实物下载基线已有归档。[原厂属性及历史现场结果](../刻度手册实现与验收.md)
