# V122 单灯介质归档的复开规则

原厂保存的单灯工程重新打开后，介质里的 `upLoad.knr` 记录了这次打开后的控件状态。在 11 份原厂工程上，Lite 的独立归档和完整介质编译均已与各自的原厂压缩文件逐字节一致。样本含双态、多态、闪烁、16 位、32 位和字位监视。每个样本都用当次日志中的工程 SHA-256 绑定原始路径。[11 份原厂文件、路径及逐件回执](样例/V122单灯复开11份压缩归档复验_20261128.json)

## 输入与字段

1. 使用 V122 单普通画面、单对象，`object[0].type = 10`、`switch.mode = 4`。传入 `--native-opened-project` 和原厂当次打开的完整 Windows 工程路径。目录和文件名进入归档尾部，输入 SM 保留原字节。
2. 对 `common.58.0` 的大端 32 位权限枚举，原厂构造函数在 VA `0x65795E` 或 `0x657D9A` 初始化为 0。读入时 `0x65723E`、`0x657570` 至 `0x65757E` 仅接受值 0 和 1。其余值保留构造结果 0。用原厂机器指令分别执行了 0、1、2、`0x12345678`、`0xFFFFFFFF`。
3. `switch.22c.0`、`.1` 和 `.4` 是 Qt 布尔字段。其序列为 `bbqqbq`。重新读写后每个布尔字段占一字节，零为 `00`，其余值为 `01`。原厂读端 `0x697F71` 起调用 QtCore 的布尔流操作。其间的三个 QString 保留各自的线序。
4. `switch.254.6` 是地址结构中偏移 3 的原始字节。原厂的地址读取见 `0x5776B7` 至 `0x5776C4`。V122 分支 `0x698020` 至 `0x698032` 转到 `0x6993D3`，将这个字节是否非零写入 `switch.248.0`。控制试验同时把原选择器改为相反值，检查整个归档。原厂机器指令另覆盖了地址字节 0、1、2、128 和 255。
5. 默认开关 SVG 的子图元以 Qt 4 的整数自然尺寸 `123 × 58` 建立边界。两个图的 SVG 宽分别为 123.82 和 123.822，高均为 58.961。原厂对图元类型 13 调用 `QGraphicsItem::sceneBoundingRect()`（VA `0x505296`），将矩形坐标按 double 写出。若原图元宽高和父矩形相符，分别计算 `(父宽 / 123.0) * 123.0` 和 `(父高 / 58.0) * 58.0`，写入大端 `pixmap.4/.5`。两次 binary64 运算都影响结果。例如高 60 的存储值为 `404E000000000001`。用 59、73、117 三个额外高度复验，并检查自定义图片及独立子图高度 42.25 保留原值。[两张原厂 SVG 的文件位置](V122指示灯渐变与固件逐帧核验_20261128.md)
6. `lamp-multi5-flash2-r1` 的源工程保存了第 2 状态，同次原厂介质记录第 0 状态。原厂通过 `0x6980F6` 读入状态成员 `+0x284`，预览选择过程 `0x69AFD9` 至 `0x69AFE8` 把选定的状态号写回该成员。新归档用第 0 状态的 `switch.294[0].1` 填充 `pixmap.0`，用 `switch.290[0][0].1/.4` 填充 `font.family` 和 `text.head.4`，并将 `switch.274.1` 置 0。样本中得到 OFF 图片、空指针字体（`FFFFFFFF`）和文本 `OFF`。复制 QString 原字节可保留空指针和长度为零两种表示。此项限于新旧状态均使用默认 SVG、单语言、颜色字号样式相同、旧预览确实匹配原选中状态的工程。
7. 所有对象字段按原始偏移从后往前写入，随后完成页面名、图库处理，用 Qt 级别 9 压缩。压缩流前有四字节大端未压缩长度。11 份压缩成品长度为 1,126 至 1,241 字节。

## 复验与范围

在项目根目录运行以下命令。两个参数分别指向本次生成的 Lite 程序和指定版本的原厂 EXE。省略 `--native-exe` 可只运行原档对照和受控改值测试。加入该参数时，Python 环境还需 pefile 和 Unicorn。

```powershell
py -B tests/verify_native_lamp_media_reopen.py --exe build/amz070w01r/KinSealStudioLite.exe --audit-previous --native-exe "G:/01_Professional/触摸屏/金玺/KinSealStudio_Setup_V5.1/Installed/KinSealStudio5.1.exe"
```

两个入口分别为 `--build-native-media-snapshot` 和 `--compile-native-media-parts`。断言比较包含压缩头、压缩流在内的整个 `upLoad.knr`。无上下文或只指定目录时，逐字段复验对象仍保留源字节。普通 USB 编译的归档解压后等于输入 SM。全部试验使用本地文件和离屏 Qt。[可重复执行的专项测试](../../tests/verify_native_lamp_media_reopen.py)

使用 `--audit-previous` 重跑了第八次总表中 58 个已编译、有原厂打开路径且 KNR 不同的工程。11 个单灯工程消除差异，其余 47 个工程的完整压缩流仍与原厂不同，逐工程结果收在回执的 `previousDifferingArchives` 中。该集合内 42 个含几何字段差异的工程，已有原厂读写路径及堆字段的分析。不同文字样式、语言或自定义图库参与的状态切换，以及同一画布包含多个指示灯的工程，尚缺对应的原厂成品对。[第八次逐工程总表](样例/V122显示控件第八次逐工程与逐文件复验_20261128.json) · [原厂图元构造与读写规则](V122介质图库次序与原厂运行字段_20261128.md)
