## 已实现的字段

下表中的路径相对于单个图表根对象。字段序号由 V122 读写顺序固定。QString 采用大端 32 位字节长度及 UTF-16BE 字符；坐标和圆环范围采用大端 IEEE 754 双精度。原厂的 Qt 颜色结构使用颜色模型字节和大端 16 位分量。

| 内容 | 柱状图 | 仪表 | 圆环 |
| --- | --- | --- | --- |
| 活动监控地址 | `private.2` 文字镜像和 `private.3` 完整地址 | `private.2` 和 `private.34` | `private.1` 和 `private.10` |
| 实测类型 | I16 | I16 | U16 |
| 位置 | 两个矩形的 `rectangle.9/10` | 各层 `ellipse.pos.0/1`、`text.tail.10/11`、`stroke.3/4` 同步平移 | `ellipse.pos.0/1` |
| 已支持尺寸 | 两矩形的右下角，柱矩形上边缘等于新高度一半 | 与原厂 200×200 刻度布局对应 | 方形宽高写入 `ellipse.4/5` |
| 已支持颜色 | 柱色／底色的十进制 `R+G+B` 放在 `private.9/10`，对应两矩形的 `rectangle.6` | 保留原厂指针、刻度和表盘配色 | `private.9` 与 `ellipse.0` 同时写入同一颜色 |
| 已支持范围 | 保留原厂默认显示／源范围 | 保留原厂默认范围 | 最小、最大值为 `private.12/13`，已验证 U16 |
| 模式结束字段 | `private.66` | `private.38` | `private.14` |

三种形态均支持改名、整数或半像素平移和 LW0–LW4095 本地监控地址。地址镜像与完整地址结构必须一致，源文件的地址家族、站号、字类型和原厂属性都参与核对。导入通过重建缓存图元和私有属性验证两段原始字节。与现有原厂样本存在额外差异的组合会保留在源文件编辑器可处理的范围，普通画布在转换前给出诊断。柱状图的朝向、两极柱、动态源范围、仪表刻度重排或缩放、圆弧模式、显现权限和外部 PLC 源地址仍需各自的原厂单变量样本。

## 怎样验证逐字节一致

1. 三份原厂默认记录分别经普通导入、KSP 保存、导出 SM，整份文件逐字节相同。另去掉快照，从空工程的模板生成各自形态，重开后核对名称、监控地址、尺寸和完整图表属性。
2. 三组编辑采用原文件中没有出现过的数值，包括 LW127、LW128、LW129，半像素原点 (173.5, 140.5)，柱状色 `#123456`、底色 `#89abcd`，圆环色 `#abcd12` 和圆环范围 9 至 345。专项脚本独立按 QString、双精度和 Qt4 QColor 编码，在原厂源文件逐字段施加预测替换，再将整份预测文件与 Lite 输出逐字节比较。三份编辑文件长度为 4,240 B、6,229 B、3,759 B，涉及的字段预期分别为 17、34、12 项。这里的独立预期由原厂字段规则推导；这些新取值没有另一份原厂 UI 保存文件作直接对照。
3. 在另一份空白原厂工程里同时加入三个已编辑图表，生成 7,940 B 的 SM。独立核对控件列表计数前的整个文件前缀及第三个控件 Z 顺序后的整个后缀，均与空白宿主原字节相同。重开后三种形态和活动属性均正确。
4. 对每种形态各设置一次不一致的地址镜像、各要求一次未覆盖的数据类型，六次均拒绝，并核对已存在的输出文件内容保持完整。
5. 尝试从当前未提升的 Windows 令牌在独立后台桌面启动未修改的原厂 V5.1。系统返回 `ERROR_ELEVATION_REQUIRED (740)`。原厂 EXE 的应用程序清单要求管理员令牌。本轮现场原厂进程的重开／再保存，以及实物屏显示均待验证。[可重复执行的专项脚本](../../tests/verify_native_chart_source.py) · [双版本回执](样例/V122三形态图表源工程复验_20261128.json)
