# AMZ070W01 固件中的系统页地址及 V122 静态表格编译

本次新增两类可以直接从原厂 SM 编译的配置。其一是 HMI 输出当前画面序号、PLC 输入切换画面序号使用本地 LW 的首行，其二是带有已记忆页名的纯图像表格。前一类有六份独立的原厂保存源和十二次原厂编译，上一发布版对六份源全部返回配置不支持。后一类使原有 248 源集合中的七份表格通过编译。[逐例字节、固件指令和文件摘要](样例/AMZ系统页地址与静态表格文件复验_20261128.json)

## SysPara.dat 的两个 40 字节地址行

AMZ070W01.bin 的 SHA-256 为 `7f625b7a967c1ecc0ff5db1fba4d6ed68cb1d9474216e87009395f1d53a88db5`。固件在 `0x80072098–0x800720B8` 将系统文件偏移 352 和 752 起的两个 400 字节区分别复制到两个运行数组。PLC 扫描在 `0x8004FD50–0x8004FD64` 计算行号乘 5 再乘 8，读取该行首字节，与 1 比较。HMI 当前页上报在 `0x800A801C–0x800A8080` 检查首行启用位，取普通页记录的页编号，再把行起点加 4 当作地址描述符传入公共写入口。复核脚本将选取的 ARM 指令逐个对照原始 BIN 的文件偏移和机器码。[固件汇编](../../firmware_analysis/amz070w01-disasm-20261119/full_disassembly.asm) · [固件伪代码](../../firmware_analysis/amz070w01-disasm-20261119/decompiled_pseudocode.c)

下表中 HMI 状态行起点为 352，PLC 控制行起点为 752。原厂样本和写入规则覆盖首行内部 LW 地址。

| 相对位置 | 字段 | 已复现的写法 |
| --- | --- | --- |
| +0，1 字节 | 行启用 | HMI 取源 `config.13c.0`，PLC 取 `config.188.0`。关闭为 0，开启为 1 |
| +4，1 字节 | 地址空间 | 本机地址写 0。两个地址记录分别为 `config.140`、`config.18c`，源中的 `.1` 也为 0 |
| +5，1 字节 | 本机寄存器类型码 | 原厂选择 LW 后，源记录的 `.2`、`.6` 均为 1，输出字符 W，十六进制 57。PLC 尚未选择的默认行两个值均为 0，输出下划线 5F。HMI 关闭已配置的 LW321 后仍保留 W |
| +6，1 字节 | 源地址记录中的站号值 | 取 `.3`。原厂默认 LW0 为 0，在地址窗口选定 LW321、LW789 后为 100，即 64 十六进制 |
| +12 至 +15 | 寄存器地址 | `.4` 是十进制地址文本，`.0` 必须等于 LW 加同一规范十进制文本。输出小端 32 位数。LW321 为 `41 01 00 00`，LW789 为 `15 03 00 00` |

地址字段宽度可由读端交叉核对。PLC 的 `0x8004FD8C` 从地址描述符 +8，即行内 +12 读取一个 ARM 32 位字。HMI 传入相同布局的地址描述符后，`0x80083070–0x8008307C` 也以 32 位装载该地址，并取类型字节交给本地寄存器路径。PLC 行后面另有固件启动时清零的运行字段。每个源文件中的其他配置和这些字段的历史字节仍计入整文件比较。

原厂 V5.1 的 AMT070W124 单页历史样本覆盖两行关闭、HMI 开启 LW0、HMI 改 LW321、HMI 关闭保留 LW321、PLC 开启 LW0、PLC 改 LW789。每种状态各有两次原厂输出。Lite 的普通编译和介质散件编译均重建这两个首行的 16 个字段字节，24 次逐件比较共 384 个字节全等。4,998 字节系统文件的 24 次整件比较分别有 173 至 176 个字节不同。真实 AMZ 固件提供读端证据，AMZ 型号的组合工程另经电脑版编译测到 HMI LW65535 与 PLC LW0 同时生效的**文件编码**。两个型号的实屏上报、切页和通信时序仍待现场验证。[受控原厂保存与重开数据](../stage2-system-io-evidence/README.md)

实现校验本地 LW 区间 0–65535，并交叉核对地址文本、寄存器类型、站号和其余系统快照。只移除已理解的可变字段后，本次配置的 936 字节摘要为 `457a4f7ddf257d18588d566a678a72904f46cdffa1d6489e3de3be9b84cb85d1`。可达范围仅含已核的本地静态画面配置，其他 IO 行、活动宏、外部端口等继续按各自的编译条件检查。源中两个字段宣称不同站点或地址时拒绝编译。当前公共入口从原厂源快照取值，Lite 工程树独立创建的 I/O 配置节点及其写回仍需各自验证。[源配置写入逻辑](../../src/native_system_settings.cpp.inc)

## 八种纯图像表格与两种原厂会话状态

原厂 `table-flags-0-r1` 与其余七个网格工程的系统配置只差三个源字段。其一是 `config.head.12` 从 null 变成当前页名，另两项为 `config.200.7` 及 `config.240.7` 从 1 变为 7。七个源的完整配置摘要均为 `2c9d9ef3322d35d79d24112f89911d1522e81d213218292714a1617e39349e64`。将七次原厂编译的系统段分别与 mask 0 比较，整份各差 48–110 字节。去掉 28 个原厂时钟字节及此前 278 对同源原厂重编中独立观察到的 172 个曾变化位置，其他 4,798 个位置七份都相同。该证据用于识别此配置下的单个纯静态表格，整文件相等仍按 4,998 字节判断。[系统段同源变化](SysPara系统参数与编译时钟逐字节复核_20261128.md)

对每种横线、竖线、外框组合，均有完全相同的原厂源文件和两次独立编译目录。原厂在创建后直接编译时，网格线包含右端或下端像素。保存、关闭、重新打开后，横线止于右端之前一列，竖线止于下端之前一行。有外框时，外框覆盖该像素，两个输出相同。八组中有三组在创建与重开时产生不同的完整页图，分别对应 mask 1、2、3。无外框的 4×4 表格中，横线、竖线、二者同时开启分别相差 3、3、6 个末端像素。[原厂两种栅格的历史验收](../阶段5_静态表格设备背景编译与差分验收.md)

默认磁盘编译使用保存后重开状态。对已核的单表格可以传 `--native-created-drawing`，重放原厂创建态。两条编译入口、两种状态和八个开关组合共 32 次实际编译。每次均逐字节比较 `SheetPixel.dat`、`PicLenPara.dat`、`AddrPara.dat`，合计 96 次整文件对照，无动态控制或动态图段。另一路从源工程的颜色、几何、行列和线开关直接计算两种状态的完整 RGB565，原厂构建目录仅用于最后比较；16 份重编码后的背景和 16 份长度表逐字节相同。冻结 248 工程的旧基准选取了创建态目录，因此使用默认重开方式时保留这三份页图的实际差异。[独立栅格与两条编译路径复验](../../tests/verify_amz_local_page_io.py)
