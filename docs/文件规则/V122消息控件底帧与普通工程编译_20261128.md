# V122 消息控件底帧与普通工程编译

Lite 的普通工程编译可以将单页、单个消息控件的原厂 SM 或编辑后的 KSP 写成磁盘文件。`--compile-project` 生成控制参数、图帧及 `Message.dat` 等文件。`--compile-native-media-parts` 还生成 `SimMessage.dat` 和介质元数据。原厂参照为提交 `e3b72657` 中的九次 V5.1 编译，原工程机型为 AMT070W124；AMZ070W01 固件的运行代码提供独立的字段读取证据。[逐工程回执](样例/V122消息九工程普通编译_20261128.json) · [复验程序](../../tests/verify_native_message_device.py)

## 文件和控件尺寸

九份原厂单消息工程分别覆盖默认值两次、单态、三态、左移速度 5 和 10、U32、双语不同字号及位与等级联合显现。每个工程的画面为 800×480，控件外框为 `(160,120,200,100)`。

| 编译成员 | 实际读取及产生方式 |
| --- | --- |
| `SheetPixel.dat` | 九份原厂页图解压后相同。上边与左边共 1,279 个黑色像素，另外 382,721 个像素为 RGB565 `C6FF`。消息控件没有把文字或底框画入页图。 |
| `ControlPixel.dat` | 每个控件单独产生一幅无文字的底图。原厂单帧有 20,000 个像素，边框上下各 4、左右各 8，合计 3,072 个 `E71C`。内框 184×92 有 16,928 个白色 `FFFF`。原始 40,000 字节按小端 RGB565 写入，LZO 压缩为 215 字节，复用页图压缩缓冲尾部补齐到 224 字节。 |
| `PicLenPara.dat` | 200 页的三组页表占 2,400 字节，随后仅有一个 12 字节图帧索引，小端三个 32 位数为 0、224、215。原厂双语工程和三态工程也都只有这一幅底图。 |
| `ControlPara.dat` | 每个控件 640 字节。原厂同一默认工程前后两次编译的整条记录已有差异。Lite 写入已确认的活动字段，逐工程保留与原件相异字节的数目和首差位置。 |
| `Message.dat`、`SimMessage.dat` | 每语言按状态顺序写文字和颜色，每槽 104 字节。介质模拟表多一个 512 字节头。五份原厂进程日志提供 fresh 和 download-defaults 的选择依据。详见[消息表规则](V122消息显示源档与双消息表_20261128.md)。 |

底图和文字位置使用将要保存的 SM 中的子图元。消息背景矩形的局部几何是两个对角点，文字子项是局部 x、y、宽、高，加上各自的平移得到屏上矩形。原件背景局部点 `(8,4)–(192,96)` 与文字局部矩形 `(8,4,184,92)` 给出同一个边界。普通编译检查这两个矩形相合、坐标为整数且位于外框内，再生成像素和控制参数。控件可移动、缩放；受控样例移到 `(79,30)`，尺寸改为 250×150，文字矩形应得到 `(89,36,230,138)`。

## 640 字节控制参数

| 偏移 | 编码及证据 |
| --- | --- |
| `0x00`、`0x04–0x13` | 消息类型为 35，此类原件的前三个附加标志为零。几何依次为 x、y、宽、高，均为 LE16。紧随其后两个 LE32 为解压帧起点和总长度。 |
| `0x15`、`0x1E`、`0x1F`、`0x22` | 位与等级显现样本分别为 `01 01 02 05`。0x15 启用显现，0x1E 是有效位状态，0x1F 存等级减一，0x22 的位 2 和位 0 分别选位与等级。0x94 起为本地位槽，+1 为 ASCII B，+8 为 LE32 位号。 |
| `0x100–0x107` | 单字节数据类型 0/1 表示 U16/U32，下一字节为消息目录中的对象索引，单消息为 0。其后三个 LE16 依次为状态数、移动方式和速度。V5.1 在 `0x8217C8–0x821806` 写入这些字段。 |
| `0x108–0x10C` | 固件 `0x80076D68` 使用此处的运行计数、选中态及滚动位置。读取文本时按 `(语言×状态数+选中态)×104` 定位记录。 |
| `0x110–0x11F` | 四个 LE32 依次为文字场景 x、y、宽、高。V5.1 通过 Qt4 `sceneBoundingRect` 取得几何，在 `0x8216FA–0x8217BF` 对各分量加 0.5 再截为整数。AMZ 绘制路径也独立读取了这四个字段。 |
| `0x120` 起 | 本地监视字取地址标志 0、ASCII W，+8 是 LW 的 LE32 地址。此次普通编译保留本地字和双字的跨度校验。 |
| `0x144–0x15B` | 六个 LE32 的语言字号槽。原厂在 `0x821816–0x821825` 清零六个双字，在 `0x821891–0x821895` 将对应语言的有符号 16 位字号扩展为 32 位存入。AMZ 固件在控件工作区同一位置按语言索引取字号。九份原件分别对照了 16 及双语的 16/24。 |

## 兼容范围

普通编译支持 1～128 状态、最多六种语言，且同一消息的文字表长度需要能放入 LE16。支持本地 LW 监视、本地 LB 或等级显现、固件对应的静止和左右移动模式。当前离线图像范围为白色纯色内框、灰色边框与原厂宋体预设字号。每语言的文字可使用不同 RGB；消息表中第 4 个颜色字节清零。七种原厂预设字号为 12、16、24、48、64、96、192。其他底框填充、外部 PLC、显现字比较、多个对象混合及不对齐的子图元仍需原厂对照。

原厂 `load.kns` 的正常和双语样本都携带 `Message.dat` 和 `SimMessage.dat`。这批原厂日志明确记载只调用 USB 下载菜单的编译阶段，未点击传输。普通磁盘导出的消息段可以接受结构检查。屏上滚动、PLC 实时取值和真实 USB 消息段仍需另外核验。[固件取行和走马灯验证](../控件功能逻辑--固件/显示与交互控件/消息显示.md)

## 九个工程的整件结果

每次编译均以对应原厂目录中的 18 个参考成员为分母，源 SM 单独核对 SHA。两个候选 EXE 分别生成了相同的验证回执。磁盘导出和介质散件的覆盖如下。

| 正式入口 | 工程数 | 全文件相同 | 同名但字节有差异 | 原厂目录有、此入口未生成 |
| --- | ---: | ---: | ---: | ---: |
| 普通工程磁盘导出 | 9 | 77 | 31 | 54 |
| 普通介质散件导出 | 9 | 116 | 28 | 18 |
| 合计 | 18 次编译 | **193** | **59** | **72** |

两条入口都复现了全部 9 份页表、地址表、图像索引、页像素、控件底帧和消息表。介质入口另有 9/9 份 `SimMessage.dat`、9/9 份 `load.bin` 和 8/9 份 `upLoad.knr` 全文件相同。普通工程磁盘入口的 `upLoad.knr` 为 5/9。两入口各有 9 份 `AlarmPara.dat`、`ControlPara.dat` 和 `SysPara.dat` 尚有字节差异；其中控制记录每个相差 136～149 字节。散件导出与完整归档是不同的生产入口，散件回执将 `Usbload.bin`、`load.kns` 按该目录实际缺件列出。每份回执同时记录额外生成的文件。
