每个 Lite 文件的长度都与其选定原件相同。页表为 72 字节，系统参数为 4,998 字节，报警参数为 47,840 字节，控件参数按工程为 640 或 1,280 字节。

冻结提交 `e3b72657` 中有 437 个同时保留原厂输入 SM 和比较用散件的编译目录，对应 248 份不同源文件。首先以第八轮清单固定选定目标及差异文件名，再从 Git 取出输入和原件，验证输入的 SHA-256 后使用 `--compile-project` 生成输出。221 个工程中，126 个有相同源文件的第二份原厂编译产物，95 个在这份档案中仅有一次。其余 27 个不在第八轮成功编译的集合中，未纳入本表。[第八轮选定目标](样例/V122显示控件第八次逐工程与逐文件复验_20261128.json)

对每个输入，先以 Git 源文件对象标识查出相同输入字节的所有编译目录，再要求选定目录和另一个目录的四种散件中至少有一种在两边都存在、内容不同。这样可分辨原件复制与不同运行产物。每一组都对 Lite 实际写出的完整文件进行字节比较，计入尾部长度之差。所有备选原件都取自冻结 Git 对象。本批次有第二份同源归档的目录均可证实编译结果不同。也没有出现第二次编译中全部缺少待比文件的情况。逐工程回执保留了选定目录、所有同源目录、可证实独立结果的文件名、整件哈希、命中目录、首个差异偏移及字节数。

## 页表第 59 字节

46 份页表均等长，唯一差异都在从零计数的偏移 59。Lite 写出的全部 46 份页表的 SHA-256 与此前专项实测记录逐项相同。以凹五边形为例，输入 SM 的 SHA-256 为 `d7323b84dab5da56c624fe2fa12c976a389dfec39a42483083543d0c62e22936`。原厂创建后立即编译，72 字节页表的偏移 59 为 `0F`。原厂重新打开这份 SM 后再编译，该处为 `00`，其余 71 字节相同。Lite 实际导出的完整页表与重开后的原厂文件相同，SHA-256 为 `9ddd74c4c47d461ab48cb089cf1037b36769c35f8e6e5a830eab23b1381e1c90`。[原厂写入路径与重编反例](V122普通画面SheetPara编码与对齐字节_20261128.md) · [此前 46 份页表实测回执](样例/V122介质图库次序与原厂运行字段_20261128.json)

17 次命中证明 `00` 确实出现在这些工程的另一份原厂输出。6 个有重编但未命中的工程中，最接近的原厂备选页表与 Lite 仍差 1 个字节。余下 23 个工程需要补取同一输入的原厂重编。若目的是还原指定历史原件的每个字节，46 个工程仍需取得偏移 59 的当次取值，或找到能独立预测它的输入条件。

## 其他三个参数文件

在有第二次原厂编译的工程中，对每个工程选取与 Lite 差异字节数最少的同源备选件。系统参数最少仍差 138 至 169 个字节，报警参数最少仍差 2,208 至 3,560 个字节，控件参数最少仍差 122 至 154 个字节。这些数值是各工程的最小距离范围，已把所有未遮蔽的字节计入。确定各偏移的含义仍需核对写端、运行时输入和原厂重编反例。[系统参数与编译时钟](SysPara系统参数与编译时钟逐字节复核_20261128.md)
