# 未完成几何图元的 SM 互通和设备编译

2026 年 11 月 28 日使用 40 份原厂 V5.1 工程及各自同轮编译文件对照。样本从 Git 修订 `e3b72657` 的原始目录读取。普通工程编译、介质散件编译和受控编辑均调用发布版。各回执记录 EXE 的 SHA-256。

## 存储和绘制规则

| 原厂类型 | 记录 | 份数 | 实际编译行为 |
| --- | --- | ---: | --- |
| `0x10028` 自由直线 | 0 个 Qt 路径元素 | 18 | 保留对象、笔和原始位置。绘图层无像素 |
| `0x10027` 折线 | 0 个 Qt 路径元素 | 2 | 与空自由直线相同 |
| `0x10026` 多边形 | 1 个顶点 | 18 | 单点无像素。其中 1 份另有完整三点多边形，仍绘出 12,554 个相对空页变化的像素 |
| `0x10026` 多边形 | 2 个不同顶点 | 2 | 按闭合路径的笔画绘制退化的边。两份原厂样例均改变 248 个像素 |

原格式使用大端 Qt 数据流。空路径保留图元自身的平移，单点多边形保留顶点坐标和图元平移。Lite 的 KSP 以专有图形字段 `nativeDrawingDraft: true` 保存上述原厂形态。未标记的普通图形沿用原有点数校验。模型保留全部草稿。编译页面时只从临时绘制列表中移除没有可见像素的草稿，工程归档仍含原对象。

两点边沿用多边形线宽 1 的覆盖率计算及 RGB565 量化。实测原边端点为 (598,358) 与 (700,400)。编译器校验归一顶点为有限值、换算后为两个不同的整数设备坐标，并检查线型、颜色和相邻对象干涉。小数平移的两点边会报告不支持。两份原厂样本共用同一条边，更多斜率和贴屏边界的原厂像素实测仍待补充。

## 改动后的工程如何验证

1. 40 份源均经直接导出，随后经 SM → KSP → SM 再导出，两次均与输入文件全字节相同。每份都验证了平移和改名后的重读。删掉草稿标志后，编译器均拒绝对应非法点数，目标目录未创建。
2. 另选空路径、单点、两点及含三点完整图形的混合页各 1 份。平移 (7,9) 并改名后，逐原厂字段对照，仅两个坐标字段和名称字段变化。四张图各 768,000 字节 RGB565 完整相等。两点图的对照图由原厂 248 个变化像素整体平移得到。
3. 删除原 SM 快照后，分别生成零点自由线、零点折线、一点多边形、两点多边形四份新 SM。四份都由 Lite 重读了名称、位置、类型和完整图形属性，并通过设备编译。
4. 使用未修改的原厂编辑器和独立桌面尝试打开这四份新 SM。Windows 对四次启动均返回 740，原厂进程未创建。新生成文件在原厂 UI 中的实际打开结果待具备管理员令牌的后台测试环境核实。

## 复验

使用包含 Qt 离屏平台插件的匹配版本 Qt 安装，将 `QT_QPA_PLATFORM_PLUGIN_PATH` 指向其 `plugins/platforms` 目录。下面的 `--scratch` 指向已存在的测试目录。每份工程的中间文件在该目录内创建并在测试结束时删除。

```powershell
py -3 tests/verify_native_drawing_drafts.py build/amz070w01r/KinSealStudioLite.exe --scratch Z:/测试临时目录 --receipt Z:/测试临时目录/geometry-usb.json --controls
py -3 tests/verify_native_drawing_drafts.py build/amz070w01r/KinSealStudioLite.exe --scratch Z:/测试临时目录 --receipt Z:/测试临时目录/geometry-media.json --media
```

`--require-all` 可启用全部文件名和全部字节严格相等的退出状态。常规几何回归要求五个几何相关散件完整一致，介质模式另要求 `upLoad.knr` 完整一致。任何 `SheetPara.dat` 的第 59 项以外的差异也会使常规回归失败。整文件相等计数在两种模式下都不屏蔽字节。
