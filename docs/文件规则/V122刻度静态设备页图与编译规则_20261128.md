# V122 刻度的设备页图和普通工程编译

原厂将刻度轴、主副刻线和文字烘焙到 SheetPixel.dat。单个刻度占用普通页面的静态图像，编译后没有 ControlPara.dat 或 ControlPixel.dat。当前设备入口接受位于 800×480 页面内、字体为 16 像素黑色宋体、水平置顶或垂直置右的已验证缓存形式。工程和介质编译走同一栅格生成路径。[生成代码](../../src/native_scale_raster.cpp.inc)

## 从 SM 到 800×480 页图

1. 先将当前编辑模型写成 V122 源对象，重新解析刻度的当前子图元。移动、改方向或修改受支持的量程后，写端更新标签及几何。每根线读取两个局部端点并分别加上该线的场景平移，每个标签读取自身文本矩形和独立平移。按源中的顺序在底图上绘制。
2. 对水平或垂直的 1 像素实线，坐标 v 的已验证栅格换算为 `floor((64*v+31)/64)`。两个整数端点都包含在覆盖范围内。副刻线样本里，纵坐标 133.505747… 实际落在第 133 行；直接四舍五入会画到第 134 行。样例覆盖反向、等范围、6 根主刻线和 4 根副刻线的原厂输出。这一公式的适用范围是本批轴向刻线。
3. 文字使用当前 Windows 系统的 SimSun 单色字形。生成时在内存设备上下文中选择字体，核实实际字高 16、上升部 14、数字字符步进 8，并读取单色字形。右侧标签按源矩形左缘对齐。顶部标签将实际文本宽度在矩形内居中。纵向用矩形中心四舍五入后减去 8 得到字形位图顶行。字体、笔型或对齐字段与已验证样式不符时返回诊断。
4. 背景和文本进入已有 RGB565、LZO 页图编码器。普通工程和介质编译都使用同一份页图。用原厂的页条目和压缩长度核对 SheetPara.dat、PicLenPara.dat，纯静态、无外部扫描的页面对应原厂地址表。

## 原厂逐件复核

从冻结的原厂版本 e3b72657 取出六份不同 SM 及每次编译的原件。两个编译入口均生成相同的 SheetPixel.dat、SheetPara.dat、PicLenPara.dat、AddrPara.dat，合计 48 次整文件比较。AMZ070W01 固件读取每张页图并解压，两个入口分别比较 2,304,000 个像素。另将默认刻度改向并移动 7×9 像素，保存前的 KSP 和重开后的 SM 分别编译，均得到以原厂反向页为依据计算的同一张图。[回归脚本](../../tests/verify_native_scale_raster.py) · [逐件回执](样例/V122刻度静态设备页图逐件复验_20261128.json)

本轮验证在电脑上运行。冻结的实物回执属于原厂编译工程。本轮 Lite 输出未下载到触摸屏，其他字号、色彩、左侧和底部布局、叠放次序和超出缓存字宽的排版还需独立原件。[原厂实物基线](../刻度手册实现与验收.md)

## 默认刻度在创建与重新打开时的七个端点

同一份默认刻度 SM（SHA-256 `1502f0404df7133cfd71b6a4b847f9815ae17323bb355fdaf4bd96635f61c2d4`）有三个独立的原厂编译记录。创建刻度后立即编译，压缩页图为 5,048 字节。原厂在另两个进程中打开这份 SM 再编译，均得到 5,047 字节，两个压缩文件相同。打开后的两份 `upLoad.knr` 解压后都只改了 `config.head.12` 和 `trailer.settings.0`。创建和打开时的八条线在原厂场景记录中有相同的矩形与变换。因此仅凭 SM 或其子图元无法判断对应哪次编译。[创建日志](https://github.com/xialang2025/KinSealStudio/blob/e3b72657c8be107392cb1a5d090dc9071cbe4a87/docs/stage4-evidence/scale/native/native-probe-scale-default-r1.json) · [第一份重开日志](https://github.com/xialang2025/KinSealStudio/blob/e3b72657c8be107392cb1a5d090dc9071cbe4a87/docs/stage4-evidence/scale/physical/scale-lifecycle-r1/native-probe-scale-lifecycle-r1.json) · [第二份重开日志](https://github.com/xialang2025/KinSealStudio/blob/e3b72657c8be107392cb1a5d090dc9071cbe4a87/docs/stage4-evidence/scale/physical/scale-native-baseline-r1/native-probe-scale-native-baseline-r1.json)

三份页图经 AMZ 固件解压后，创建态的七个点为黑色，重开后为背景色 RGB565 `C6FF`。以左上角为 (0,0)，四根主刻线的右端是 (241,128)、(241,156)、(241,185)、(241,214)，三根副刻线的右端是 (180,142)、(180,171)、(180,200)。主轴和文字像素相同。

完整介质编译使用已有选项 `--native-opened-project 原厂打开的完整路径.sm` 明确指定重开上下文。只有单个默认向上的右侧刻度满足此次端点规则。编译器检查 200×100 的整数场景几何、0–100 范围、4 根主刻线、每间隔 1 根副刻线、16 像素黑色宋体，以及十二个子图元的拓扑、样式和几何。相对原点的八条线及四个文字矩形都与原厂默认排版吻合时，七根水平刻线只绘制到右端点的前一个像素。垂直主轴仍包含两个端点。无此上下文、只填目录、其他拓扑或已修改的子图元仍沿用前文的绘制方式。
