# V122 工程图片和原厂动画的设备帧编码

## 图片显示

对照集来自 Git 提交 `e3b72657` 的 `docs/stage4-evidence/picture/native/compiled/`。固定原厂目录分别为 `picture-static-red`、`picture-multiple-time`、`picture-multiple-bit`、`picture-multiple-numeric`、`picture-distinct-red-green`。五份输入覆盖单图、两行引用同图、两行引用不同图、时间、LB 和 LW 切换。时间样本的预览状态为 1，两行都引用红图。双色样本预览第 0 行。

| 位置 | 格式及作用 |
| --- | --- |
| 控制记录开头 | 每个对象占 640 字节。图片类型字节为 15，五份原厂样本 +3 均为 1。+4、+6、+8、+10 分别是小端 16 位 x、y、宽、高。+12、+16 为小端 32 位未压缩像素起点与总字节数。 |
| +0x100 至 +0x10B | 六个小端 16 位数依次为显示模式、切换条件、当前状态、状态数、计数器、间隔。单图模式为 0，多图为 1。时间、位、字三个条件的设备取值分别为 0、1、2。AMZ 固件 `0x80075964` 分别走计时回绕、按位选帧、按数值选帧的分支。 |
| +0x10C 起 | LB、LW 两个已核实例的内部地址空间为 0，下一字节为 ASCII B、W，+0x114 是小端 32 位地址。内部地址没有外部 PLC 扫描项。 |
| 页图和图帧 | 原厂样本的控件矩形为 (160,120,200,100)。解开 `SheetPixel.dat`，框内恰有 20,000 个红色 RGB565 像素。图像控件另向 `ControlPixel.dat` 按状态行次序写 LZO 压缩的独立帧。每帧小端 RGB565 原始长度为 40,000 字节，红、绿纯色的压缩长度均为 185，按 32 字节对齐后各占 192 字节。 |
| 图像索引 | `PicLenPara.dat` 前 2,400 字节为页索引，随后每幅动态图有三个小端 32 位整数，依次为编码 0、补齐长度、真实压缩长度。补齐字节复用已核实的压缩工作区尾部。 |
| 介质元数据 | 五件原厂 `load.bin` 都是 233 字节。在同样的 COM1 驱动选项下，含已使用 PNG、未使用 PNG 或两幅已使用 PNG 的五份工程均写空 `assetPairs`。两份本地地址工程的系统对话框配置指纹与另外三份不同。须逐项验证本地地址及完整已知配置指纹。 |

已通过两条正式编译入口生成各自的页图、控件图流、图像索引、页表和地址表，合计 50 个原厂整文件。介质入口额外比对 5 个 `load.bin`，共 55/55 全等。抽查控制记录的几何、帧偏移/字节数、显示模式、状态数、间隔和内部地址等 40 字节，两个入口均完全匹配。完整 640 字节控制记录仍有 107～118 字节差异，记录的可复现部分和整件差异分别计数。

## 原厂 GIF 工程

原厂 V122 工程可将 GIF 拆成一个 PNG 帧表，工程图库记录仍标作 `GIF`。两份原厂源的表体均长 241 字节，开头的三个小端 32 位整数为 2、12、126，后接两个完整 32×24 的 PNG。帧表中没有原始 GIF 的逐帧延时与循环扩展。Lite 逐帧检查偏移、PNG 边界、解码尺寸和资源预算，将表的原始字节保存在 KSP 的动画池与控件绑定中。普通画布显示首帧，属性页可点「下一帧」查看各帧。原始 GIF 文件仍可用原来的动画试播。

设备类型为十进制 34。+0x100 保存帧数，+0x108 是播放门控，+0x10A 是有效状态，启用低电平的 LB17 样本值为 0。未启用时原厂默认源为 0xFF00。+0x10C 起为本地位地址，原厂两件的 +0x10F 均为 1，+0x114 记录地址。两种原厂编译的控件帧都按红、绿顺序写入，原厂页图保留底色。固件分派和原始 GIF 中的延时证据见[原厂 GIF 运行分析](../控件功能逻辑--固件/显示与交互控件/GIF显示.md)。

## 验证与边界

两份原厂 GIF 工程均通过普通画布迁移到 KSP，再导出逐字节相同的 SM。在每份工程中另移动 7 像素，改为 LB25 高电平有效，再次保存和迁移均能读回修改，且保留原始帧表。对两份原件分别破坏第二帧起点，导入均拒绝。另用主编辑器的离屏预览打开默认工程，只交换帧表中的红绿两帧再打开一次，两张截图中恰有 20,000 个像素由红变绿，对应完整的 200×100 控件。

把原厂冻结的 `probe-red-green.gif` 解为两个 32×24 的 RGB 帧，可独立重建这一对原厂 PNG。它们的 IHDR 均为 8 位 RGB，pHYs 横纵均为 3,780 像素/米，首行使用 Sub、后续相同行使用 Up，IDAT 使用 6 级 Deflate 和 4 KiB 窗口。对原始红绿两帧重新计算 PNG 压缩数据与区块 CRC 后再写小端目录，结果与两份 SM 中的完整 241 字节表相同。这条校验覆盖纯色的受控输入。

两份 GIF 的 USB 和介质输出又核实了 22 个整文件。共 7 份原厂源、14 次编译、77 个图流、页表、索引、地址表或介质元数据整件相同。GIF 的两份完整控制记录仍各有 140、144 字节差异，首差分别在十进制偏移 23、76。逐个工程和文件的 SHA-256 及记录差异见[逐工程回执](样例/V122图像与动画七工程设备复验_20261128.json)。

复验命令在项目根目录执行。测试使用提交号读取独立原件，逐个比较完整文件，另校验已编辑和无效输入。工作区建议指定带 Qt 离屏插件的 SDK 环境或使用已有私有桌面。

```powershell
py -3 tests/verify_native_picture_device.py build/amz070w01r/KinSealStudioLite.exe
```

当前设备编码涵盖不透明原尺寸 PNG 和可缩放的纯色 PNG。透明合成、多色图像缩放、系统 KVG、显现条件、静态闪烁、与其他对象重叠以及真实 PLC 地址需更多同源原厂编译件。原厂动画支持保留原始帧表及编辑已有控件的几何和本地播放条件。新建动画图库、替换原厂资源、原始 GIF 转原厂表时的 PNG 编码及屏上帧间隔仍待验证。此次测试通过磁盘导出，不涉及触摸屏下载。
