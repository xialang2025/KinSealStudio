# V122 数值、ASCII、时间显示器的 640 字节控件记录

Lite 增加了 `--export-native-value-record-fields <输入.sm或.ksp> <新文件.json>`。它根据当前工程属性生成每个已核实字段的设备字节和偏移，适合复核设备文件写端。输出带有原厂记录长度 `recordBytes=640`、实际覆盖字节数、属性名及 `completeRecord=false`。文件中未给出值的偏移仍待核实。命令只接受新的 JSON 文件名，拒绝覆盖现有文件，也拒绝以 `.dat` 命名。现有五种页面和图像散件另有独立的编译入口。[字段生成实现](../../src/native_value_record.cpp.inc) · [五种散件的编码规则](V122数值ASCII和时间显示器五种散件复验_20261128.md)

## 输入范围

本轮针对 800×480 普通单页单控件、整像素坐标和默认纯色外观。原厂输入取自普通默认和双语字号 24 两种 V122 源配置。对于带原生快照的工程，沿用显示器散件的源字段检查，拒绝未核实的隐藏模式。数值和 ASCII 只接受本地同一 LW 监控和输入地址。数值仅覆盖 I16。ASCII 限默认编码、默认字节交换，输入修改和自动换行关闭。时间支持三种对齐、日期/时间/星期独立开关、九种日期和四种时间格式。启用外部连接、宏、动作、显现门限、非默认样式等选项时，命令返回具体原因。当前完整工程的设备编译仍须另外验证。

## 从编辑属性写入设备字节

下表偏移从零开始，以十六进制表示。几何均是段内连续四个小端无符号 16 位整数，顺序为 x、y、宽、高。每份均先写共同几何，还需把相同矩形写入类型私有位置。RGB 三字节的顺序均为红、绿、蓝。

| 内容 | 时间（17） | ASCII（16） | 数值（12） |
| --- | --- | --- | --- |
| 控件类型 | `000=11` | `000=10` | `000=0C` |
| 公共几何、第一帧解压偏移和全部帧原始字节数 | `004`、`00C=0`、`010=宽×高×2` | 同时间 | `004`、`00C=0`、`010=宽×高×6` |
| 私有几何 | `10E` | `11C` | `11E` |
| 字号索引，小端 16 位 | `118`，字号依次为 12、16、24、48、64、96、192 | `128`，字号依次为 16、24、32、40、48、64、96、192 | 同 ASCII |
| 前景 RGB、背景 RGB | `120`、`124`。前景占完整四字节，最高字节为 00 | `130`、`134` | `138`、`13C` |
| 专用属性 | `108/109/10A` 各 1 字节，分别为日期、时间、星期。默认未启用触控/显现，`014/015=00` | `12A` 字符数，小端 16 位 | `12A/12C/12E` 分别为总位数、小数位、数据类型，小端 16 位。高、低限色 RGB 在 `140/144` |
| 其他格式 | `10C` 对齐，居中写 1、左写 2、右写 0。`11A/11C` 写日期和时间格式索引，各为小端 16 位 | | `148/150` 写增益/偏移，`168/170` 写输入上/下限，均为小端 IEEE 754 binary64 |
| 本地地址描述符 | | 监控在 `138`，输入在 `1A4` | 监控在 `178`，输入在 `250` |

每个已验证的 LW 描述符仅输出开头的两个字节 `00 57`，以及其起点加 8 处的小端 32 位十进制寄存器编号。样本中多个其他地址描述符字节会随原厂运行变化。字节表不会把这些位置补成零。原厂默认时间源同样有三次独立编译，首次与另外两份完整控件文件分别差 111、134 个字节。[重复原厂编译的完整偏移清单](样例/V122数值ASCII和时间显示器五种散件复验_20261128.json)

## AMZ070W01 实际指令验证

1. 对每个待测时间记录，把 640 字节放入仿真内存，在运行对象设置类型 17，执行固件 `0x800AA9D0` 构造分支。证实它从输入复制 `0x278` 字节，输出对象的最后 8 个试探字节未被复制改写。随后进入组 5。复制长度只说明这一分支搬运的范围。
2. 以第 0 帧运行 `0x8004718C`。在调用位图接口 `0x80048658` 前检查寄存器与栈，实测位深 16、行字节数为宽×2、宽高正确，像素指针选中单控件页面的首帧。有关图帧解压后实际像素的证据见前一份五散件复验。
3. 注入 RTC 共享结构的时间 2026-11-20 星期五 16:07:05，进入 `0x80078EA8`。由真实指令格式化至 `0x8007916C`，取拼好的字符串。星期采用 AMZ 的英语星期表。例如日期在前、选星期和时分时，得到 `2026/11/20 Friday 16:07`。英文星期和只显示日期都有固件自身的尾随空格。
4. 继续执行绘制参数读取。固件在 `0x8007916C` 从记录 `0x120` 一次取完整 32 位前景色。`#234567` 应读为 `00674523`。`0x800791A4` 开始读取私有矩形，`0x800791D4` 选择对齐，传给绘制接口的居中、左、右参数依次为 `0E/0C/0D`。坐标 (49,63)、尺寸 147×87 的右下角实参为 (196,150)。

复验在六份不同原生 SM、十二次实际原厂编译上逐个检查所有导出的字段。时间每份 45 字节，ASCII 每份 47 字节，数值每份 89 字节，各有四份原件，共 724 个字段字节全部相同。编辑验证另有 39 个时间配置，包括 9×4 日期与时间组合、仅时间、仅星期和仅日期。每个编辑配置都将其余未覆盖字节分别置为 `00` 和 `A5` 再执行上述固件路径，加上四份原厂时间记录，每套构建共有 82 次实际 ARM 运行。编辑测试使用独立生成的字段，原厂记录另外对照。另有 ASCII 的字符数、地址、颜色和几何编辑，以及数值的增益、偏移、上下限、颜色、数字位数和地址编辑。[验证脚本](../../tests/verify_native_value_records.py) · [原厂记录和逐组合实测回执](样例/V122三种显示器控件字段与AMZ时间读端_20261128.json)

两套 EXE 均通过上述原件、固件和拒绝用例。最终生产候选 SHA-256 为 `7fe72c519bb6683f498b9f1e20801010fab1a504813a63d1345388d1cc1efab3`，干净构建为 `752ce6ce9a876a7ad20b7a65d0eb523ffaf09d6435e10081e00d650b04ec5357`。两个地址不一致、非 I16、半透明和试图覆盖已有结果均被拒绝，原目标内容保持完整。
