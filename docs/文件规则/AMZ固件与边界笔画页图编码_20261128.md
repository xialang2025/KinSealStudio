# AMZ070W01 固件与 V122 页图的边界笔画

AMZ070W01 的背景解码函数接收已经绘好的页图。固件能核验压缩索引和实际显示像素。上位机如何处理源坐标、笔帽和编辑会话，还要对照原厂绘图库及同源工程。两份边界工程各有创建后直接编译与保存重开后编译的原厂目录。每一对目录中输入 SM 的 SHA-256 相同。[原厂目录、固件和 Qt4 的 SHA-256](样例/AMZ边界画线与固件像素复验_20261128.json)

## 坐标与绘制顺序

1. V122 存储路径顶点和图元平移。取一像素方形笔帽、无箭头的两点实线。设两个原始整数点之差为 `(dx, dy)`，笔画在任一坐标轴上的半宽投影为 `(|dx| + |dy|) / (2 × hypot(dx, dy))`。当笔画延伸到画布左边界或上边界外，保存源可出现相应坐标轴上的共同平移。Lite 要求两点之差仍为整数、最小顶点与几何边框之差等于上述投影；轴向折线另外要求水平或竖直。原始 SM 和 KSP 中的小数保留，只在绘制时量化。
2. 这类平移恰为半个像素时保持低位整数，超过半个像素时沿该轴前进一格。对于从 (0, 0) 到 (200, 100) 的自由线，两个方向平移约 0.670820393 后，首个点为 (1, 1)。对于从 (130, 0) 到 (130, 120) 的竖线，纵向平移 0.5 后，从 y=0 起绘制。页图首行本已为黑色。
3. 在刚画完的原厂编辑器中，当前笔画保留方形笔帽，包含主轴末端。保存重开后，原厂使用平头笔帽，排除该像素。默认编译采用重开状态。磁盘入口可显式传入 `--native-created-drawing`，重放单个静态表格或已支持的非微小两点实线。多个图元不共享一个可由 SM 确定的历史绘制状态。此选项不会写进工程。
4. 压缩索引首个 LE32 是第 0 页 `SheetPixel.dat` 的输入字节数。本组静态单页的 `PicLenPara.dat` 长 2,400 字节。固件在 `0x8004E168` 的背景读取路径把默认压缩页送入 `0x800AB414`。复验在 Unicorn 中运行该原件的 ARM 指令，输入压缩页，核对正常返回及 768,000 字节 RGB565 输出。复验使用的固件 SHA-256 为 `7f625b7a967c1ecc0ff5db1fba4d6ed68cb1d9474216e87009395f1d53a88db5`。[固件读取路径](../../firmware_analysis/amz070w01-disasm-20261119/AMZ070W01固件工程解析与PLC通信总报告/AMZ070W01固件工程解析与PLC通信总报告.md)

## 可复核结果

- 自由线刚绘制时末端为 (201, 101)，保存重开时末端为 (200, 100)。边界竖线在 y=120 的像素同样随会话状态变化。两份原件、两种编译入口、两种历史状态共 8 次对照，各自整份 `SheetPixel.dat` 和 `PicLenPara.dat` 都相同。各 SM 经 KSP 再导出也逐字节相同。
- 用原装 QtGui4 在独立 Windows 桌面绘制 12 组水平、竖直、正负斜率、反向和较陡或较缓的两点线。启用一像素黑色实线，关闭抗锯齿，在独立路径上分别调用 FlatCap 和 SquareCap。对适用的自由线及折线，共 36 幅 Lite 页图经固件解压，整帧 RGB565 与 Qt4 对照相同。另有 6 项负向检查，覆盖单点任意小数、重复选项、多对象历史重放及大边框内的微小线段。[测试程序](../../tests/verify_amz_firmware_page_images.py) · [发布版逐帧结果](样例/AMZ固件页图发布版复验_20261128.json)
