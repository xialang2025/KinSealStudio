# V122 图片显示和二维码的原厂源工程格式

本次逐字节比较以原厂 V5.1 写出的 8 份图片显示工程、6 份二维码工程为基准。14 份工程都通过了原厂源文件 → Lite 可编辑工程 → 导出原厂源文件的全文件字节比较。在每份工程中移动控件，再通过 Lite 重新导入，坐标和控件属性均能读回。原厂编辑器重新打开 Lite 新建工程，以及设备端编译的 DAT 和最终下载包，分别需要独立对照。

## 串行化规则

该区沿用 Qt 4.8 QDataStream 默认大端格式。QString 以四字节长度记录后续 UTF-16BE 字节数，长度 0 和 0xFFFFFFFF 分别编码空串和空值。原厂工程内可有多处与设备显示无关的休眠字段。未编辑字段直接复用原跨度，不按当前编辑器默认值覆盖。

| 类型 | 顺序与取值 | 编辑后要同步的副本 |
| --- | --- | --- |
| 15 图片显示 | 公共容器后依次为当前预览状态、模式、单图条件开关、状态切换来源、地址串、结构化地址、状态数、切换间隔、休眠字节与短整型、状态行数、状态行 | 校验预览状态有效以及两个状态数一致。状态行按名称、资源标识或原厂路径、图库类型（32 位）、从 0 起的状态号（16 位）顺序存储 |
| 15 工程图库 | 图库类型 0，两处资源名相同，PNG 原字节从工程图片库读取。活动缓存子图元 0x10018 带图片标识、双精度坐标和尺寸 | 更换或重排状态行要同步预览子图元的图片标识；变更图库类别要换成匹配类型的子图元 |
| 15 系统图库 | 图库类型 1，记录文件名、原厂 KVG 路径。缓存子图元类型 13 | 对已有工程保留原路径，显示时可定位内置 ExternAdd 图库。遇到未经核实的新外部 KVG 路径，保存返回明确错误 |
| 15 动态切换 | 原厂 0、1、2 对应时间、位状态、数值。Lite 模型内部的数值和位状态枚举顺序相反 | 活动地址的纯文本和结构化地址一起改。多图模式带独立的休眠单图条件位 |
| 52 二维码 | 监视地址字符串、说明 QString、32 位字符长度、结构化地址、缓存参数、末尾字节交换和字符集各一字节 | 地址字符串和地址结构联动。说明始终由工程层写作 UTF-16BE。ASCII/GB2312 切换改变运行时编码选项 |
| 52 画布缓存 | 背景矩形 0x1000F，随后为类型 13 的二维码 KVG 图元 | 平移更新场景坐标和原已存在的坐标镜像。缩放仅改相应轴的尺寸 |

## 可重复验证

在项目根目录执行以下命令。测试脚本从 Git 历史 e3b72657 取回原厂样本，按随附清单核对 SHA-256，临时输出写入 build 下的独立目录，退出时清理。若样本已在本机独立目录，可添加 `--fixtures <目录>`。Windows 命令行程序后台运行，验证过程无须操作桌面。

```powershell
py -3 tests/verify_native_image_sources.py build/amz070w01r/KinSealStudioLite.exe
```

每个样本都会比较初次往返的整个 .sm。测试统一平移 (+11, -7)，对 6 个二维码样本同时修改中文说明、字符长度、换序、字符集和监视地址，对两幅不同 PNG 的图片样本交换状态并改用 LB17。重新迁移后逐项核对属性，最终再次保存并与编辑过的文件逐字节比较。

另已从两个无原厂快照的 AMZ070W01R 控件工程生成图片显示、二维码 .sm，各自重新导入后属性一致。实际原厂静态 PNG、取消编辑、两状态、三状态、时间、位及数值切换、字符长度 0 和 255、中文说明以及两种字符集的输入文件名与 SHA-256 均见[样本清单](./样例/V122图片和二维码原厂样本_20261127.json)。

## 用原厂独立编辑结果核对生成的字节

从同一份原厂默认二维码工程出发，在 Lite 中分别只改指定二维码属性，另外取 5 份由原厂编辑器独立保存的对应变体，比较两份档案的每个字节。所有变体的工程尾部都保存了各自运行目录 `trailer.settings.0`。此处目录不同，各档案实际比较结果如下。

| 原厂变体 | 二维码私有区 | 全工程出现实际差异的字段 |
| --- | --- | --- |
| 中文说明，ASCII | 全部字节相同 | 工程目录 |
| 中文说明，GB2312 | 全部字节相同 | 工程目录 |
| 字符长度 0 | 全部字节相同 | 工程目录 |
| 字符长度 255 | 长度、地址和有效配置字节相同 | 工程目录，两个原厂缓存整数 `qr.tail.2` 和 `qr.tail.3` |
| 字节交换 | 换序、地址和有效配置字节相同 | 工程目录，同上两个原厂缓存整数 |

默认工程中两个缓存整数是 192 和 832，在长度 255 的变体中是 3276895 和 3014708，在换序变体中是 6881327 和 6357101。它们的生成含义仍待确认，Lite 在已有工程中逐字节保留原值。回归脚本仅在这 5 项“独立变体”比较中根据清单报告上述字段差异，覆盖其余全部字节；前述 14 项未改工程和编辑后再存的全文件比较均含全部字段。

### 两个整数的写入来源

以下虚拟地址属于上文 SHA-256 固定的 32 位 V5.1 安装原件。同一类虚表地址 0x01444588 下，写、读函数指针分别位于 0x0144462C、0x01444630。

| 操作 | 代码位置 | 验证到的值流 |
| --- | --- | --- |
| 创建外观页 | 0x00ADA5AD 至 0x00ADA5CB，0x00AD7B74 | 分配 0x70 字节，调用外观页构造。该构造初始化页内 +0x18 的 QString 和 +0x24 的颜色对象，没有给两者之间的 +0x1C、+0x20 显式赋值 |
| 创建二维码 | 0x00AD89B7 至 0x00AD89C9，0x00AD8250 | 新建标志为 1，跳到 0x00AD82F8。此分支设置 KVG 路径和图片类型 1，没有写这两个整数 |
| 编辑已有二维码 | 0x00AD82B5 至 0x00AD82C4 | 打开已有对象时，把对象 +0x150、+0x154 复制到页内 +0x1C、+0x20 |
| 确认属性 | 0x00AD78C4 至 0x00AD78CD，0x00ADB628 至 0x00ADB666，0x00ADD042 至 0x00ADD04E | 取外观页两个整数，按原值经过属性暂存块 +0x28、+0x2C，存回对象 +0x150、+0x154。长度和换序另外处理 |
| 保存与读取 | 0x00ADBD5D 至 0x00ADBDC9，0x00ADE0B0 至 0x00ADE0C2 | 保存把两个值送到 +0x264、+0x268，再用整数字段逐个写入。原厂读取执行对应反向复制 |

长度 255 样本的两个字段以大端字节表示为 `00 32 00 5F` 和 `00 2E 00 34`；换序样本为 `00 69 00 2F` 和 `00 61 00 6D`。它们恰好可读成 UTF-16 字符片段。已检查的构造、新建、属性和存盘路径都没有从字符数、换序或编码推导这两个值。Lite 保存已有档案采用原档案值，新建采用原厂默认种子的两个值。

针对 5 个独立属性变体，回归还从各自原件开始，把属性改回默认值并保存，重新导入，然后恢复变体属性再次保存。最终要求全部文件字节与各自原件相同，包括工程目录和这两个整数。此项专门验证真实编辑操作中是否丢失原档案的缓存。

## GIF 仍需单独核验的内容

原厂类型 34 的单图元缓存、地址、图片键、宽高和结尾字段已有结构跨度。已检查的两帧 GIF 工程将动画保存成私有小端帧表。该资源共 241 字节，前三个 32 位数为 2、12、126，后接 114 和 115 字节的两个独立 32×24 PNG。源 GIF 的帧延时及循环选项在此帧表中没有对应值。现阶段不能用这份证据恢复原始 GIF 流或确认设备播放时序。

原厂 GIF 默认、取消图库、取消主窗口、LB17 播放条件四份 .sm 均已通过完整结构读取和原厂源工程窗口对应的无改动另存，四次输出都与输入文件逐字节相同。四份同时通过工程改名后重新解析，标题为 GIF-REF.sm。普通画布的 GIF 图元语义导入和设备编码仍待完成。
