# V122 的 AlarmPara.dat 和 AlarmMuti.dat

从 251 份不同的 `.sm` 逐字段生成报警参数，再与 443 个原厂编译目录比对。431 个目录的多语言报警表均能从源独立生成完整的零字节文件。其余 12 个目录包含活动数位报警，其中 1 个同时包含两组四级条件报警。已还原标志、计数、扫描周期的低字节、使用状态、阈值、部分画面引用以及消息排列。本次可从 SM 独立生成的字段已全部与相应的原厂字节比较。[逐项回执](样例/V122报警段与多语言表逐字段核验_20261128.json)

## 两个参数块

V5.1 安装原件的报警写端在 `0x0091299F` 连续拷贝 `0x260C` 个 32 位字，在文件偏移 `0x9830` 处续写 `0x8AC` 个 32 位字，最终输出 `0xBAE0` 字节。固定长度包括当前工程未使用的记录。下表位置均以零为起点，多字节数为小端。源字段路径来自 Lite 对原厂 Qt 大端流的解析。

| 文件位置 | 从源到输出的规则 |
| --- | --- |
| 数位块 `0..38959` | 数位报警行数取 `config.ec.0`。偏移 0 写是否启用，偏移 4 写两字节行数。行数非零时，偏移 1 写扫描周期 `config.ec.1` 的低 8 位，偏移 3 写 `config.d0` 的低 8 位。末尾四字节写源单字节 `config.134.1` 的零扩展值。 |
| 数位行 `44 + 76 × r` | 第一语言的 `config.108[r × L].0` 写行内 +0。+2、+4 是跳转和跳回的两个小端 16 位索引，来自 `config.100[r]`、`config.104[r]` 的名称查找。未匹配返回 `0xFFFF`。工具输出已在原厂样本中核实的“未使用”情形。行内 +24 开始的 50 字节存第一语言消息，长度不足清零。L 为已启用语言数。 |
| 条件块 `38960..47839` | 条件报警组数取 `config.124.0`。块内 +0 写是否启用。启用时 +1 写组数，+2 写扫描周期 `config.124.1` 的低 8 位，块内最后四字节写 `config.134.0` 的零扩展值。未启用时不能据此推定末尾四字节为零。 |
| 条件组 `38960 + 44 + 276 × g` | 每组中四级条件从组内 +20 开始，步长 64。取第一语言 `config.138[g × L][级]`。每级的 +0 保存源 `.1` 的使用状态，+1 保存源 `.0` 的数据类型低字节，+4 写从源 `.3` 数字文本转换的 IEEE 754 小端双精度，+12 起的 50 字节写源 `.2` 消息，长度不足清零。 |

原件 SHA-256 为 `305592b4e4bc1b15a707c7bc832c31f27ca0958b97f9c79a5b50ac6df49e907c`。测试可选核对原件的 11 处指令。受控条件样例有两个数位报警、两组条件报警，每组四级。第一组第一级的报警消息是 `COND-LOW`，其阈值文本 `-123` 编译为 `00 00 00 00 00 C0 5E C0`。这份原厂样例共复核 606 个参数字节，两个数位报警而无条件报警的样例各复核 120 个参数字节。两个尾部标志以 0 为当前原厂样本值，位标志设为 1 的情况另有源码受控测试。

## 多语言表的排列和长度

`AlarmMuti.dat` 使用连续的 50 字节槽。数位报警按“行 → 语言”排列。紧接着的条件报警按“组 → 语言 → 四级条件”排列，包含空消息和未使用的行。长度为 `50 × L × (数位行数 + 4 × 条件组数)`。在双语两行原厂页上，四槽依次是 `ALM1`、空、`ALM2`、空，文件长 200 字节。单语两行、另有两组条件的样例长 500 字节。

原厂调用 Qt 的 `QString::toLocal8Bit`。工具默认采用简体中文 Windows 的 CP936，其他 Windows 代码页可显式指定。原厂活动样本消息内容为 ASCII。中文双字节跨槽边界另按这条写入指令做了受控测试。

- 参数块中的第一语言消息先清空整槽，再按本地编码写入前 50 个字节。包含结尾编码残片的情况也按字节截断。
- 独立多语言表按固定 50 字节写槽。编码不足 50 字节时，本工具确认的范围包括消息内容及结尾 NUL。同一份原厂 SM 重编得到的短消息槽在这个范围之后仍会变化。
- 若源编码长 49 字节，内容与 NUL 正好占满整槽。长 50 字节或以上时，直接写前 50 个字节。只有所有槽都能确定时工具才发布完整文件。用实际 SM 的两行文本分别改成 49 和 59 字节，并经 Lite 重新解析后，独立写端输出预期的 100 字节。短消息或字段图与源摘要不符时，测试均保留了已有输出。

## 同源编译的全文件边界

437 个目录有可直接配对的原厂输入。另有 6 个既有原厂测试目录的日志分别记下了编辑后 SM 和两项报警输出的 SHA-256，已逐项核对。日志里的编辑器属于历史测试副本，本次对写入代码的静态核对采用安装原件。431 个无数位报警目录中，整个数位块的 38,960 个字节实测全为零。写端在未启用时明确写入的字段单列在工具结果中。其余整块零值是这批运行的观察值。

437 个目录按同源分组得到 148 个重复编译组，组内共 278 对。278 对 `AlarmPara.dat` 均有差异，每对有 172 至 2,544 个不同字节。仅用相同 SM 无法同时重现这两份不同的输出。活动地址的完整设备编码、已启用跳转目标的正例、非 ASCII 消息的原厂对照以及其余会话相关字节仍待验证。因此工具仅输出可验证字段，普通设备下载沿用已有预检和已验证的默认段。
