# 新建 KSP 刻度写入 V122 SM 及设备页图

在普通画布中新建受支持的刻度后，可以直接保存为原厂 `.sm`。新建 KSP 与其生成的 SM 均可经普通编译、介质编译生成设备页图。验证覆盖右侧默认、右侧向下、顶部、等值 0、六根主刻线和四根副刻线六种原厂布局。六种布局分别用两种输入、两条编译路径与各自对应的原厂编译散件比较。四件均逐字节相同，合计 96 次整件比较。[逐件回执](样例/V122新建刻度的五种原厂对象体与宿主隔离验证_20261128.json)

## 新建时如何生成对象

资源来自原厂 V5.1 留存的五份 V122 工程。测试用从零计数的字段边界切取原文件，并与资源完整比较。起点是 `object[0].type` 的首字节，终点是 `object[0].private.17` 的结束位置。仅对象自身进入资源。父页面、工程参数、其他控件、外层可移动位和层级值均由当前宿主生成。五份合计 13,279 字节。[写端实现](../../src/native_scale_draft.cpp.inc) · [原厂对象体](../../resources/native-scale)

| 原厂来源 | 类型 31 对象字节 | 用途 |
| --- | ---: | --- |
| `scale-default.sm` | 2,237 | 右侧默认四根主线、每间隔一根副线。向上、向下均可从此对象生成 |
| `scale-position-top.sm` | 2,237 | 顶部位置，不同的文字居中方式和线段方向 |
| `scale-equal-zero.sm` | 2,225 | 单个数字宽度的标签，允许在相同字宽和缓存布局中调整值 |
| `scale-main6.sm` | 3,147 | 六根主刻线 |
| `scale-sub4.sm` | 3,433 | 四根副刻线 |

读取器先按 V122 读取类型 31 及其完整私有记录，再核对末字段确实落在资源末尾。从对象体计算已有线段端点、标签尺寸和属性后，使用与已有刻度相同的写回函数应用当前名称、场景位置、方向和范围。主轴、主副刻线、文字宽度及末端排版须与已核定的布局兼容。当前基线尺寸为 200×100，字体为 16 像素黑色宋体。尺寸变化、左/下布局、其他颜色或字号、非零小数位、负值及尚需重排新字宽的范围会返回诊断。具体判断按实际子图元状态执行。[既有刻度源字段规则](V122刻度普通画布源档复验_20261128.md)

## 原厂原件与新输入

- 将六份原厂 SM 转成编辑模型，彻底去除原快照，再用 KSP 普通保存为 SM。五份生成的完整对象体与原厂原件逐字节相同。向下样例使用默认对象重建方向。其原生方向码、方向文字及标签均与向下原件相同，唯一差异字段是两次原厂保存值本就不同的休眠 `common.58.3`。六份结果再次在 Lite 的普通源入口打开，名称、坐标、尺寸及刻度属性均相同。
- 另外从不含原生快照的 KSP 新建一页，页名为“自建刻度实验”，位置 (73,61)，范围 4–104，方向向下。保存并重开后含 200×100 刻度，再次保存的整份 SM 逐字节稳定。用同设置的空宿主逐字段比较，除对象数量外，582 个宿主字段相同。在保存后的宿主追加一根位于 (366,210)、范围 1–101 的六主线刻度后，原先的第一个对象体及宿主字段仍然相同。
- 新建的原厂六种布局分别对照 `SheetPixel.dat`、`PicLenPara.dat`、`AddrPara.dat`、`SheetPara.dat`。对每种布局，4 条组合路径均未生成动态控件参数或图帧，AMZ070W01 原固件解压后的 800×480 RGB565 像素与原厂基线相同。额外的新建 4–104 工程四条路径的这四个文件也分别相同。[专项测试](../../tests/verify_native_scale_drafts.py)

本轮生产版确认追加的第 13 层刻度可保持锁定。冻结的干净构建使用更早的工程对象模式，显式拒绝 `object.locked`，取消该字段后仍可按第 13 层添加刻度。两种模式均核验宽度、字号、边缘、主线数、小数位、颜色、最大值及负最小值这八种超出已证范围的编辑，均返回失败且不产生残缺原生文件。

原厂 GUI 在本轮后台启动时遇到 Windows 错误 740，需要提升权限。因此报告中的“重开”指 Lite 的普通 SM 入口。原厂依据来自真实保存的对象体和编译文件。此验证未操作实物触摸屏。
