# Usbload.bin 可独立重建的字段

在 441 份历史原厂 KNS 及当前 AMZ 安装目录的 1 份原厂 KNS 中，`Usbload.bin` 均长 1,704 字节。每份归档都用自身的伴随散件和嵌入工程作对照。下表中的数值字段均为 32 位小端，偏移从零开始。这 442 份均为单普通页工程。另从原厂安装器取得六页 AMZ101W01 的归档，四个散件长度、六个页长、固定字段和时间字段均通过，总计 443 份。

| 偏移 | 原厂写入规则 | 本轮实测 |
| --- | --- | --- |
| `0x004` | 取本地时间自午夜的整秒 `s`。Windows 原厂 Qt4 用 `qsrand(s)` 初始化后取一次 `qrand()`，结果为 `((214013 × s + 2531011) >> 16) & 32767` | 225 份等于 ZIP 时间记录的秒，216 份等于该秒加一。余下 1 份等于写文件时间的前一秒 |
| `0x00C` | 常量 123，原厂指令在 `0x00641334` | 442/442 四字节相同 |
| `0x0F8` | `SheetPixel.dat` 实际字节长度 | 442/442 四字节相同 |
| `0x0FC` | `ControlPixel.dat` 实际字节长度，缺少该文件时为零 | 442/442 四字节相同 |
| `0x100` | `AddrPara.dat` 实际字节长度 | 442/442 四字节相同 |
| `0x104` | `PicLenPara.dat` 实际字节长度 | 442/442 四字节相同 |
| `0x388 + 4 × 页序号` | `trunc(2 × 页面宽 × 页面高)`。宽高取普通页的双精度字段 | 442/442 第一项相同。多页循环见原厂写入器，多页介质仍待原件核对 |

原厂函数 `0x00641168` 在 `0x006416CF–0x00641729` 取当前时间、计算秒、调用 `qsrand` 和 `qrand`。安装的 `QtCore4.dll` 中两项导出分别跳转到 C 运行库的种子和取数函数。ZIP 的 DOS 文件时间精度为 2 秒。唯一未落在这两秒内的原包记录为本地 `07:46:58`，从原字段计算出的相邻候选时间是 `07:46:57`。这给出可复现的输入值，历史进程的精确调用时刻没有日志可查。

四个文件长度分别在 `0x006418FD`、`0x0064184A`、`0x006419A2`、`0x00641A47` 写入。原厂按普通页序号在 `0x00641BC1–0x00641C1C` 计算页大小。它在 `0x00641C2A–0x00641C49` 复制整个 0x6A8 字节的内存结构，随后以这个长度交给写文件函数。独立生成整文件还要确定其他字段的来源和与特定构建有关的字节。原厂同源重复编译的 148 组中，这个文件均出现过整文件差异。[同源双编译证据](原厂编译字节复核_20261127.md)

## 重跑核验

在项目根目录运行下列命令，最后一个参数可以替换为实际原厂归档路径。`--git-revision` 会从 Git 对象库提取该版本的归档，不需还原旧编译目录。程序逐字段重算并直接比较四字节编码，输出每个 ZIP 的 SHA-256、元数据文件 SHA-256、差异偏移及与 DOS 时间的关系。原厂媒体、工程和设备均以只读方式对待。

```powershell
py -3 tools/verify_native_usb_metadata.py --exe build/amz070w01r/KinSealStudioLite.exe --git-revision e3b72657 --report usb-metadata-check.json "G:/01_Professional/触摸屏/金玺/KinSealStudio_Setup_V5.1/Installed/compile/load.kns"
```
