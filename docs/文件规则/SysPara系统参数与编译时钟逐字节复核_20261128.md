# SysPara.dat 的系统设置与原厂编译时钟

AMT070W124 的 13 次原厂系统参数编译涵盖 7 份不同的 SM。旧发布版对这 7 份全部返回配置不支持。现在这些输入可从设备工程和离线介质两个入口编译。26 份生成文件与对应原件在本次验证的 4 个设置字节全部相同，整文件相同数为 0。现场声音和屏保动作另待实屏观察。[逐例对照](样例/SysPara系统设置离线复验_20261128.json)

## 已接入编译器的系统设置

下表依据原厂单变量保存、重复编译、恢复基线及 V5.1 写入指令。文件偏移从 0 开始。

| 源字段 | 编辑器取值 | SysPara.dat 写入规则 | 原厂写入指令 |
| --- | --- | --- | --- |
| config.head.5 | 屏保等待时间，0 至 60 分钟 | 偏移 3 写入值的低八位 | 0x905D5D 至 0x905D65 |
| config.head.6 | 闪烁周期，1 至 50 个 0.1 秒 | 偏移 4 写入值的低八位 | 0x905DDF 至 0x905DE2 |
| config.head.8 | 触摸声音，0 或 1 | 偏移 8 写入源字节异或 1，声音开写 0，关写 1 | 0x905E06 至 0x905E12 |
| config.head.14 | 初始用户等级，1 至 8 | 偏移 22 写入值的低八位 | 0x905F8A 至 0x905F92 |
| config.flags.1 | LW 编辑器地址十六进制显示，0 或 1 | 单变量原厂组中没有观察到稳定的系统段差异。Lite 保留源字段，系统段编码沿用对照结果 | 原厂开与关各有编译对照 |

设备编译先验证五个值的取值范围，再以默认值计算其余配置的摘要。生成设备段时使用输入源实际保存的四个系统值。另外支持两种来自参数设置窗口、未分配串口的完整配置摘要。这两种配置只接受空页或无显现、无触控条件的静态文本，并要求工程宏及宏调度为空。两种归一后的配置摘要分别是 2e4607316f881af776e1bc9d5992c28cbb4253d4fe2a948627587fe5908bc282 和 31f411f41c760b5fdb97ee4c21a361c54fe21ca5a4ca2da79e9bbbffab60fa39。

13 个原厂用例包括三次默认或恢复，以及五项设置各两次编译。另将屏保、闪烁和等级同时设为 60、50、8，关闭声音并开启十六进制，设备输出中只改变四个指定字节。负例包括五项参数各自的界外值、未恢复的串口配置、静态文本的显现条件，以及仍引用外部串口的休眠地址。各例状态列入专项回执。这些结果覆盖从 V122 源快照编译。Lite 自有配置节点、其他串口、完整的多页配置及各机型运行效果仍需分别验证。

## 4,998 字节如何组成

未修改的 V5.1 编辑器 SHA-256 为 305592b4e4bc1b15a707c7bc832c31f27ca0958b97f9c79a5b50ac6df49e907c。输出例程在 0x90519D 至 0x9053DF 依次拼接准备好的块，最后以常数长度 0x1386 写文件。以下区间含首尾，长度总和为 4,998。分块依据是原厂写出过程，部分块的来源结构仍需逐字段解释。

| 文件字节 | 长度 | 写出时的依据 |
| --- | ---: | --- |
| 0–99 | 100 | 首组系统选项，包含表中的 4 个设备设置 |
| 100–323 | 224 | 编译器准备的整块数据，复制前清零其中相对偏移 3 和 4 |
| 324–351 | 28 | 七个连续的 LE32 本地日历与时间分量 |
| 352–751 | 400 | 一组系统 I/O 记录，首行有原厂单变量对照。[HMI 状态对照](../stage2-system-io-evidence/README.md) |
| 752–1151 | 400 | 另一组系统 I/O 记录，包含 PLC 控制首行 |
| 1152–1307、1308–1319、1320–2091 | 156、12、772 | 三次连续块复制 |
| 2092–2131、2132–2151、2152–2171 | 40、20、20 | 分别写出三个区块，最后一块按列表数量走条件分支 |
| 2172–2177 | 6 | 编译时语言索引 LE16、语言数量 LE16、配置对象 +0x29C 的低 16 位 LE16 |
| 2178–4737、4738–4867、4868–4997 | 2,560、130、130 | 最后一次 640 个双字复制及两次 130 字节复制 |

437 个有原 SM 和系统段的历史目录中，352 与 832、392 与 792、432 与 752 这三对起点各自的 40 字节均全等。启用系统 I/O 的独立对照表明首行地址可以单独变化，故这些样本中的重复只适用于已测配置。相同 SM 的 148 组原件组成 278 对。扣除 28 个时钟字节后，278 对仍分别有差异。对这些余量，需要查明生成时的其他输入或找到对应构建的状态记录。

## 本地时钟与相邻文件时间

原厂在 0x90608D 与 0x906096 先后读取 QDate::currentDate() 和 QTime::currentTime()。0x9060AB 至 0x906132 将返回值拆成整数。0x9051DC 至 0x9051F1 在偏移 0x144 一次写入 7 个双字。七项依次是秒、分、时、星期、日、月、年。星期一为 1，星期日为 7。原厂分开采样日期与时间。跨午夜时两次调用可能取到相邻日期两侧的值，目前样本未观察到这种情况。

明确知道该次原厂采样的本地日期和整秒时，介质散件入口可接受 --native-compile-time。日期完整到秒，采用公历，不含毫秒或时区转换。示例使用受控复验日期。

~~~powershell
.\build\amz070w01r\KinSealStudioLite-20261128.exe --compile-native-media-parts 工程.sm 新介质目录 --native-compile-time 2000-02-29T23:59:59
~~~

复验了 441 个历史归档、安装目录 AMZ070 和六页 AMZ101，共 443 个原厂包。每个包都先按系统段 ZIP 日期构造相邻整秒候选，再比较 28 个字节。224 份系统时钟比 ZIP 字段晚一秒，218 份同秒，另 1 份早一秒。ZIP 的两秒分辨率只能提供候选。用 USB 描述文件独立推回的另一处随机数播种时间，348 份与系统时钟同秒，94 份晚一秒，1 份晚两秒。两个时刻需要分别记录。生产接口另测了闰日、周日、日期越界、小时越界、额外时区标志与不规范宽度。[逐归档记录](样例/SysPara日期时间与编译语言原厂复验_20261128.json)

## 编译时使用的语言

原厂在 0x905320 至 0x905353 从编译时系统对象同步当前语言、语言数量，再写入偏移 2172、2174。443 个 KNS 的两个 LE16 均与同包 KNR 中 Qt4 原厂源身份记录的当前语言和语言数量一致。437 次能配对独立输入 SM 的编译中有 434 次直接与输入源一致。相邻偏移 2176 的两字节另有来源。0x91B446 至 0x91B456 将配置对象 +0x29C 写入源字段 config.29c，0x907F53 至 0x907F5C 取同一配置位置并截断为 16 位，0x90535C 至 0x905362 将其写入系统段。此字段在 437 个配对的系统段中均为零。其业务用途与非零原厂样本仍待查证。

另 3 次静态文本测试的输入 SM 记载两种语言、当前语言索引 1。每次编译的独立窗口日志都记录语言列表为中文和 English，实际选中索引 0。3 份系统段和 3 份 KNR 均使用 0。核对时还用同一原厂日志中的 SM 摘要、系统段摘要确认日志与文件来自同一次编译。现有 Lite 默认从源或 KSP 的启动语言生成该字段。复现这些例外需要一并还原当次编辑语言及受其影响的源快照和绘制状态。

### 从窗口日志独立预测 437 次编译的四个语言字节

复验工具用原 SM 的 SHA-256 和编译标签关联原厂运行日志。在主窗口的可见 `QComboBox` 中筛选第一个语言是“中文”的列表，若有第二项则要求为“English”。同一份日志的所有可用快照必须对当前序号和语言数给出唯一的读数。找到读数时，从窗口选项写入两个小端 16 位数；缺少读数时，从输入 SM 的身份记录取当前语言序号和语言数。预测使用的输入不含 KNR、系统段内容或原厂系统段摘要。产生预测后，再核对日志中记录的编译输出 SHA 和实际四字节。

437 份均命中。其中 31 份有可绑定的窗口语言读数，28 份与输入相符，3 份覆盖输入索引；406 份用输入 SM 的登记值命中。这样可以在本批样例中独立解释偏移 2172–2175。其他工程中缺少窗口观测时，源文件无法显示用户在编译前是否临时切换过语言。[31 条日志与完整预测汇总](样例/SysPara同源残差与窗口语言交叉复验_20261128.json)

### 278 对同源重编的其余变化

用源文件的 SHA-256 分组，共有 148 个重复组、278 对原厂输出。下表统计各区段中至少出现过一次变化的位置数，以及在一对文件中该段有多少字节不同。对每一对单独去掉时钟，剩余差异为 40 至 160 字节。合并全体共有 172 个不同的位置，全部在三个复制块内。

| 文件偏移（含首尾） | 区段内曾变化的位置数 | 有差异的文件对 | 每对差异字节数 |
| --- | ---: | ---: | ---: |
| 0–23、24–99 | 0 | 0/278 | 0 |
| 100–323 | 84 | 278/278 | 25–83 |
| 324–351，本地时钟 | 5 | 278/278 | 1–5 |
| 352–751，第一组系统 I/O | 37 | 278/278 | 4–33 |
| 752–1151，第二组系统 I/O | 51 | 278/278 | 10–47 |
| 1152–4997，包括编译语言区 | 0 | 0/278 | 0 |

这里的稳定性只对相同 SM 的成对重编成立。主动改变系统选项、语言和系统 I/O 会改动相应业务字段。机读回执保留每个变化偏移出现的对数、每对差异数量的直方图，并按原厂写出块分别统计后半部分。[逐偏移分布](样例/SysPara同源残差与窗口语言交叉复验_20261128.json)

### 使用同包的其他散件能还原多少

在具有成对原 SM 的目录里，先将源 Git blob 按摘要排序，隔项分到发现集和留出集。同一源的各次编译都在同一集合。对反复变化的位置搜索其他文件固定偏移的相等字节。搜索要求发现集至少有四种不同取值，排除了总为零等恒定条件。报警段用 217 份发现、220 份留出；在两组均匹配的候选有八个。再用 443 个完整介质包验证，其中有 12 个系统段 SHA 从未出现在前述 437 个目录中。

| SysPara 字节 | 供比对的 AlarmPara 字节 | 443 包匹配 | 12 个额外系统段匹配 |
| --- | ---: | ---: | ---: |
| 191、195（分别比较） | 46743 | 各 443/443 | 各 12/12 |
| 370、850 | 46154 | 各 442/443 | 各 11/12 |
| 371、399、799、851 | 46155 | 各 442/443 | 各 11/12 |

现装七寸 AMZ070 原厂包给出后六个偏移的反例。前两个字节在 278 对中各有 114 对发生变化，给定同一次原厂 `AlarmPara.dat` 时，可按表还原本批次这两个位置。原厂报警段本身也随重编而变化，现有证据尚缺这些值从 SM 独立产生的来源。以相同的固定偏移和多值条件比较 `SheetPara.dat`、`load.bin` 和 `Usbload.bin`，未得到可在其源留出集中复现的新候选。更复杂的计算和未纳入比较的资源仍可能提供线索。

## 复验入口

系统设置专项使用冻结的原厂源、设备文件和字段边界。时钟专项可传入其他原厂 KNS 重跑。使用便携程序运行离屏专项时，测试环境应提供与发布 Qt 匹配的 offscreen 平台插件。

~~~powershell
py -3 -B tests/verify_native_system_settings.py build/amz070w01r/KinSealStudioLite-20261128.exe
py -3 -B tests/verify_native_system_clock.py --exe build/amz070w01r/KinSealStudioLite-20261128.exe 原厂七寸.kns 原厂六页.kns
py -3 -B tests/verify_native_system_residuals.py --receipt 系统差分复验.json 原厂七寸.kns 原厂六页.kns
~~~
