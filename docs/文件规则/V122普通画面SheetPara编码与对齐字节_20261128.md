# V122 普通画面 SheetPara.dat 的 72 字节记录

在 443 份原厂归档上，使用 SM 和该次编译的逐页控制记录重建画面表，369 份整文件相同。其余 74 份各有 1 个字节不同，全部位于页内偏移 59。比较按完整字节序列执行。归档中共有 448 张普通页，覆盖两个已安装型号的 800×480 和 1024×600 工程。443 次中有 431 次使用同目录原始 SM，另外 12 次使用归档中的源快照。257 个不同的源 SHA-256 参与比较。[逐归档 SHA 和全部差异位置](样例/普通画面参数整文件复核_20261128.json)

## 普通页记录

原厂安装版 V5.1 可执行文件 SHA-256 为 `305592b4e4bc1b15a707c7bc832c31f27ca0958b97f9c79a5b50ac6df49e907c`。普通页构造函数位于 `0x00A5DAF4`。下表偏移从零计数，多字节整数均为小端。文中的页字段名称来自 V122 SM 结构检查器。

| 页内偏移 | 编码规则及证据 |
| --- | --- |
| 0、1 | 页对象内偏移 `+0x50` 的字节、`+0x9C` 整数的低八位。源写端 `0x00A61A90`、`0x00A62B4A` 分别写为 `head.17`、`tail.13`。普通页类型为 0，样本的第二字节为 1。 |
| 2、3 | 当前页生成的动态控件条数占一个字节，原厂普通页路径在 `0x00A5EE3C` 将偏移 3 单独置零。每个动态控件占 640 字节。 |
| 4 至 6 | `0x00A5EE70–A5EE9F` 把该页编号 QString 以十进制转整数后写低八位，随后把偏移 5、6 置零。源编号是 `head.19`。 |
| 7 至 46 | `0x00A5EEC5–A5EEDD` 清零 40 字节，再由 `0x00A5EEF7` 调用 Qt 4 的 `QString::toLocal8Bit()`。在 `0x00A5EF25–A5EF41` 复制本地编码结果的前 `min(长度,40)` 字节。若刚好 40 字节，槽内没有额外终止符。最后一字节可以是双字节汉字的前半部分。本次简体中文 Windows 的 ACP 为 936，原厂“画面1”写为 `BB AD C3 E6 31`。SM 的 `head.18` 保存完整 UTF-16 名称。 |
| 47 | 页名 40 字节槽和后续两字节对齐字段之间的间隙。上述页名清零和复制止于 46，尺寸写入始于 48。本批记录该位均为零。 |
| 48、50 | `QGraphicsScene::sceneRect()` 的宽和高分别加 `0.5f` 后向零截断，取低 16 位。两处写入地址为 `0x00A5EDE1`、`0x00A5EE35`。已核普通页宽高为正数。 |
| 52 至 55 | 普通页路径在 `0x00A5EEA5/A5EEAE` 写两个零值 16 位整数。 |
| 56 至 58 | 从页对象 `+0xB8` 写入 16 位整数，对应 `tail.2`；从 `+0xA0` 写入一个开关字节，对应 `tail.1`。原厂 SM 写端位于 `0x00A61CFE–A61D22`。写入普通页记录的两条指令位于 `0x00A5EF81` 和 `0x00A5EF8D`。 |
| 59 | 单字节开关和两个字节对齐的后续索引之间的间隙。原厂普通页构造时未对这个位置赋字段值。Lite 采用确定的零值。 |
| 60、62、64、66 | 四个 16 位页动作索引初始化为 `0xFFFF`。原厂在偏移 58 开关激活且存在候选项时进入后续查找流程。独立工具只接受开关关闭的样本。 |
| 68 至 71 | 该页控件图像解压后的字节总数。原厂 `0x00A5EF43–A5EF4E` 写编译器计数器，复验从该页每个 640 字节控制记录的 `+16` 取 LE32 并累加。 |

## 偏移 59 的反例

普通页栈记录的起点为 `ebp-0x30C`。在 `0x00A5F535–A5F544`，原厂先清理另一个 1,000 字节的输出缓冲区。随后 `0x00A5F546–A5F550` 将页记录的 18 个双字整体复制过去，连同对齐间隙一起覆盖输出缓冲区。前一步的清零无法决定页记录未赋值位置的内容。

冻结提交 `e3b72657` 中，下列两组独立编译具有相同的输入 SM、源快照 KNR 和 `load.bin`。同组的页图、地址表、图长索引和可选控制散件也相同或同时缺省。每组两份 `SheetPara.dat` 的长度均为 72 字节，且都只有偏移 59 不同。

| 原厂重复编译目录，均在 `docs/stage2-evidence/native/compiled/` | 同组输入 SM 的 SHA-256 | 两次取值 |
| --- | --- | --- |
| `final-system-flick11-r1-fresh`、`final-system-flick11-repeat-fresh` | `45c1911caf175a63b2d68ff27fabf7c5955b395afc671c5e2591b8571e9d0697` | `0E → 06` |
| `final-system-hex-on-r1-fresh`、`final-system-hex-on-repeat-fresh` | `ccdb06f668d40fdfa30bf1128892327bb988f57cb831eaa70be79eb4ab84fdae` | `06 → 0E` |

这些输入相同的工程对应不同的历史目标字节。指定要重建的某一次历史输出时，需要独立记录该次复制前的对齐字节。当前回执将这 74 份全部计为不相同。

## 页名修改与双向工程回归

实际编译原版 Lite 的两个 KSP 测试时，改名后的旧单文本页和普通矩形页仍写出“画面1”。同一页导出为 SM 后，编译还会因启动和屏保页名包含在配置摘要中而被拒绝。修复后，普通编译和旧单文本入口按原厂 40 字节规则写入名称。源快照保留完整标题。原厂配置写端 `0x00905D23–905D3E`、`0x00905FB8–905FD3` 分别用 `config.head.4`、`config.head.11` 调用 `0x00902530`。该函数比较页对象 `+0x48` 名称，返回列表内的索引。唯一普通页的两个引用和源尾页名都与本页一致时，两次命中索引均为 0，配置指纹据此归一。引用其他页面会被拒绝。

专项核对使用普通静态文本和矩形两条编译路径，分别测试默认页名、短中文混合页名和在汉字首字节处达到 40 B 的长页名。KSP 和 SM 两种输入合计 12 份产物，逐份比较完整的 72 字节，同时测试 12 个修改了单个页引用的拒绝反例。旧单文本专用入口另测三种页名。设备工程编译的现有范围仍为普通单页 000。多页文件对照是下方独立页表工具的验证范围。

## 复跑

下面的离屏命令使用与发布程序匹配的 Qt 平台插件。独立工具接受编辑器实际打开的 SM 和该次编译为每页生成的控制记录。每页传入一个 `--page-controls`，空页传入 `-`。默认对照原厂简体中文代码页 936，其他原厂环境可显式指定 `--encoding`。遇到所选代码页不能编码的字符时，独立工具报告错误。

```powershell
$env:QT_QPA_PLATFORM_PLUGIN_PATH = 'G:/01_Professional/QT6/Installed/6.12.0/mingw_64/plugins/platforms'
py -3 -B tools/native_sheet_records.py build/amz070w01r/KinSealStudioLite-20261128.exe 工程.sm 新画面表.dat --page-controls ControlPara.dat
py -3 -B tests/verify_native_sheet_pages.py build/amz070w01r/KinSealStudioLite-20261128.exe
py -3 -B tests/verify_native_sheet_records.py build/amz070w01r/KinSealStudioLite-20261128.exe 原厂单页.kns 原厂六页.kns --require-all
```
