# 指示灯设备编码核验

日期：2026年11月9日；修改标记：`//20261109-8`。

## 结论与证据边界

指示灯属于大类10、子类型4，复用按钮的显现权限头和图像资源，只有监视地址，没有位写入或字运算的操作地址。新编码器位于 `KinSealStudio/src/native_lamp_control.h/.cpp`，仅本模块新增，未改既有位按钮或字按钮编码器。

本目录保存10个真实原厂界面创建、保存后再由原厂离线编译的有效样本，以及3个明确标记 `product-` 的产品生成源工程经原厂重新打开、离线编译的样本。逐文件SHA256、原厂活动字段、屏蔽区域和来源分类见 `lamp-corpus-audit.json`。较早 `lamp-multi5-u16-r1/r2/r3.sm` 是失败的空白工作副本，不能充当指示灯正例。

本轮使用普通Frida、原厂Qt getter、已有Ghidra反编译记录及离线LZO解码，没有REA MCP Evidence ID。所有原厂GUI在新建的私有Windows桌面中运行，未切换输入桌面、未发送真实键鼠输入、未调用USB。原厂沙盒运行副本SHA256为 `38100BF47294342119560DADFBD6A35D6AB51180C0EEAF4B7B21517BEA20ED89`；安装原件为 `305592B4E4BC1B15A707C7BC832C31F27CA0958B97F9C79A5B50AC6DF49E907C`。这两个文件仅启动管理员令牌检测处0x7c4..0x7c6不同，运行副本不是字节相同的原件；旧调查已保存对应字节与启动函数解释。本轮没有修改安装目录。

## 原厂UI补充事实

- 通过真正点击多态组的复选方框，状态数范围变为2至32，外观页选择状态范围是0至状态数减1。仅调用Qt `setChecked` 而未触发clicked会留下256的构造默认上限，不应误记为可用UI范围。
- 位监视和多态监视两处“与操作地址相同”始终禁用。Win32 `IsWindowEnabled` 对此Qt4程序返回值不可靠；本轮使用 `QObject::property("enabled")` 获取真实Qt状态。
- 通用页宏指令整个 `groupBox_macro` 禁用；权限页“通知”整个组禁用。新设备编码器拒绝启用宏、通知、触控条件和按压时间，避免把只读指示灯变成写入控件。
- 多态组启用后标题变为“多态指示灯”。选择状态2时，“从0状态复制文字属性”和“从0状态复制外形”均可用。
- 新建位地址监视显示禁用的bitIndex15，但首次保存默认值是0；切换字地址后即使未再编辑bitIndex也保存15。字地址手动调整到7的样本保存并编译为7。位地址情况下bitIndex是无效草稿，修改外观后原厂可能保留15，不能强行把它当运行位序。
- 双态、多态两组都未勾选时按确定，原厂实际保存及编译为mode2、U16、状态数2、LW0；并不生成mode0。产品对话框确认时按此归一，设备编码器拒绝未确认mode0。
- 状态4写入 `RETAIN-STATE-4` 后，将多态状态数5降2再升5，重新选状态4时文本为空；原厂删除被缩减的外观。过程getter记录见 `lamp-retention-r1-before-shrink.json`、`lamp-retention-r1-shrink2.json`、`lamp-retention-r1-reexpand5-state4.json`。
- “使用同一段文字”是整个开关控件共用的标志。原厂在状态0勾选后切状态2、4均保持勾选；在状态2取消后回到状态0也变为取消。闭环getter见 `lamp-samelanguage-global-r1-state0-on.json`、`state2-on`、`state4-on`、`state2-off`、`state0-off`。源codec代理确认对应单一 `switch.tail.4` 布尔值，不能把每个状态的相反选项同时写回原厂源。
- 状态2点击“不使用图片”后，路径框禁用但仍保留 `switch_ON.kvg` 文本；切状态0时其路径仍可编辑且保持 `switch_OFF.kvg`。该按钮改变图片子对象类型，不等同于清除路径草稿。真实原厂源为 `corpus/lamp-multi5-state2-noimage-r1.sm`（SHA256 `CA24B20330B6CCC47C032C6BA43107215935DD0B2535166F027CF38F896C9A5D`）；勾选共用文字的原厂源为 `corpus/lamp-multi5-state0-samelanguage-r1.sm`（SHA256 `5330A7C4DA26B5C51AAEC6B59D30C9F541BC8DD0A9B804A196552BE9F69FE441`）。这两份补充源未编译，不计入上文10份原厂编译正例。

## 640字节设备记录

以下字段来源于已有 `FUN_00695030` 子类型4分支、`FUN_00693f68` 公共监视块，以及本轮真实UI样本的原厂导出。完整活动掩码见审计JSON。

| 偏移 | 活动字段 |
| --- | --- |
| 0x000 | 大类10 |
| 0x004..0x00b | 位置和尺寸，四个LE u16 |
| 0x00c、0x010 | 解压图像偏移和总字节数，LE u32 |
| 0x015、0x018、0x01b、0x01e..0x01f、0x022、0x034等 | 共享显现权限字段，沿用已验证按钮公共头 |
| 0x106 | LE u16子类型4 |
| 0x108、0x109 | 所有状态共用的终端3D和透明效果 |
| 0x10a、0x10b | 逻辑状态0、状态1的闪烁标记 |
| 0x180 | 监视地址类型：0位，1字 |
| 0x181 | 同操作地址标志；原厂指示灯UI不可用，固定0 |
| 0x184 | LE u32监视模式：1双态，2多态 |
| 0x188 | LE u32字的位，仅双态字地址监视时有效 |
| 0x18c | LE u32多态数据类型：0为U16，1为U32 |
| 0x190 | LE u32逻辑状态数，双态2、多态2至32 |
| 0x198 | 36字节监视地址记录；已验证活动字节为相对0、1、2、5、8..11 |
| 0x1bc | 全局共用文字标志：0按各语言存图，1所有语言共用一套状态图像 |

原厂指示灯不赋值0x10c..0x17f的按钮操作联合体，此处包含随进程改变的栈残留。新编码器清零该区域，不复制无意义“操作地址”。多态的0x188以及双态的0x18c也是无效草稿，不参与活动字段比较。0x104..0x105等未初始化字节同样不作常量。未证实的尾部字段保持零，不把原厂脏值当功能。

监视地址的相对字节5始终为0。`FUN_0057bb54` 地址转换只给已知地址字节赋值；源地址结构的rawLength用于扫描收集，36字节地址输出没有独立的宽度活动字节。原厂U16源工程 `switch.254.7` 是1，U32是2；产品源codec和扫描器需同步该两字宽度。相对字节4出现的08不是宽度字段，不应照抄。独立编码器还检查本地0至4096范围，U32末字不得超过4096；外部两字完整边界由总编译预检验证。

## 图像顺序和闪烁

| 情况 | 原厂图像顺序与数量 |
| --- | --- |
| 双态无闪烁 | ON（逻辑状态1）、OFF（逻辑状态0），2帧 |
| 双态仅OFF闪烁 | ON、OFF、OFF隐藏文本帧，3帧 |
| 多态N状态 | 状态0、1、2……N-1，N帧 |
| 多态状态0或2勾闪烁 | 仍N帧，所有图像流与无闪烁版本完全相同 |
| 两语言多态 | 第一语言完整0..N-1，然后第二语言完整0..N-1 |

默认120×60原厂双态rawBytes28800，多态5状态72000；双态OFF闪烁43200。多态2状态勾闪烁仍28800。多态5状态勾状态0仅改变头部0x10a，勾状态2不产生新的设备闪烁字段，两者的 `ControlPixel.dat` 均与无闪烁样本完全相同。新软件保留全部外观草稿，按原厂格式只写前两个闪烁标志，多态不擅自增补图像。这并不证明屏端多态文本闪烁可用。

原厂编译最终产品混合两语言源的SHA256为 `CEADE2A22F6FFB33FDFDB71FC2DC395781D6D39068DC78F4B07112EE83382358`，其监视源宽度已修正为2；旧 `product-mixed-multilingual-r1` 含早期宽度1，不能用作最终U32宽度正例。有效输出为 `corpus/product-mixed-multilingual-r2-compiled`，4条640字节记录，包含静态文本、位按钮、字按钮和多态指示灯。指示灯140×70、5状态、2语言，rawBytes196000。解码后全工程18帧，其中8..12为中文状态0..4，13..17为English `STATE 0`..`STATE 4`；PNG08、13、17已目视核对，顺序与字节数一致。

补充的无图与共用文字组合源为 `source-analysis/product-lamp-noimage-samelanguage.sm`，4953字节、SHA256 `DE269318A9B6D30232648967552CB4144133485DD92A5405AC73DC2A50319E92`。已在原厂私有桌面重新打开并离线编译，输出为 `corpus/product-lamp-noimage-samelanguage-r1-compiled`。原厂记录为大类10/子类型4/mode2/状态数5/0x1bc=1，位置40,40、180×60。虽工程有中文和English两语言，共用标志令原厂只生成5帧，rawBytes108000；这与共用标志关闭时的两语言10帧不同。`FUN_00695030` 明确把源对象0x22f写入输出0x1bc，且原厂false样本该字节为0，因此新编码器按活动状态共同的sameLanguage写该位，并以1套图像计算长度；不一致的活动状态标志被拒绝。

组合样本解码目录为 `frames-noimage-samelanguage-r1/`。状态0、2、4 PNG已目视核对，文字分别为 `STATE 0`、`STATE 2`、`STATE 4`；状态2为灰色矩形且没有图库边框或橙色ON图案，RGB565颜色只有0xa514背景10585像素和0x0000文字215像素。该5帧通过0x1bc=1供所有项目语言共用，无需复制第二语言图片。整个补充流程仍未调用USB。

图像审计JSON和PNG目录为 `frames-default/`、`frames-dual-flash0/`、`frames-multi5/`、`frames-multi5-flash0/`、`frames-multi5-flash2/`、`frames-product-mixed-r2/`。这些是编译输出解码证据，不是实物屏截图。

## 独立测试与只读复核

独立Release测试记录见 `native-lamp-tests.txt` 和 `native-lamp-tests.xml`，覆盖10个原厂UI导出活动字段、上述无图/共用文字组合原厂导出、2至32状态和1/8语言边界、共享显现权限、只读外部地址角色，以及未验证功能和错误长度的事务性拒绝。最终应为77通过、0失败。

只读复核检查了不修改原对象、失败不覆盖输出、只读地址标志、清除操作联合体、全局外观字段一致性、图像数量及偏移溢出和局部边界。发现极端十进制ULL_MAX字符串可能令原加法检查回绕后，已先报告主代理，再改为有序上界与减法检查，并补相应拒绝测试。最终无本模块新增阻断问题。

本模块不接触USB，不覆盖用户触摸屏内容。实机下载、监视值联动、显现权限和屏端多语言切换由主代理继续验收，不以原厂离线编译或传输ACK替代屏端运行确认。
