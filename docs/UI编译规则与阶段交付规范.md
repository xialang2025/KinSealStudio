# UI编译规则与阶段交付规范

维护日期：2026-11-14。适用对象：KinSealStudioLite当前AMT070W124-L800X480R后端，800×480。本文补齐阶段0～7已交付切片及阶段8逐批实施的规则；后续每完成一个阶段性任务，必须在同一提交内同步维护本文和该任务专项报告。阶段5整体仍未完成。

本文的“UI编译”指界面属性经过工程模型、校验、渲染及段编码成为设备数据的过程。主窗口布局属于编辑器界面规则，不会直接编成屏端控件。可编辑、可保存、可导出原厂源、可生成设备数据、可下载和实屏功能正确必须分别记录。

## 1. 规则和证据的使用方法

| 层 | 输入与输出 | 通过要求 |
|---|---|---|
| D 规格 | 手册/原厂界面 → 字段及联动表 | 默认、范围、单位、活动条件、确认/取消/重开有来源，未知项有问题ID |
| U 交互 | 菜单/属性/画布操作 → 草稿或模型事务 | 相同操作产生已核结果；取消不插入对象、不改变工程 |
| P 持久化 | typed模型 → `.ksp`；另列原厂`.sm` | 保存重开、复制、撤销及语言切换保值；原厂源支持独立核定 |
| R 渲染 | 模型+资源 → 属性预览/画布图 | 字体、颜色、坐标与状态使用同一语义；预览一致不自动证明设备像素一致 |
| C 设备编译 | 不可变工程快照 → 设备段、图帧、索引 | 同范围原厂B/S/M对照；所有活动字段可表达；负向明确拒绝 |
| T 传输 | 指定EXE/工程/包 → 目标接收 | 段、提交及重启分别有回执；USB ACK不证明显示与触控 |
| E 实屏 | 外部刺激 → 屏幕/触控/寄存器/时序 | 目标固件和实际刺激、观测一一绑定 |

`describeProjectCapabilities()`的`candidate`仅表示有资格进入实际导出/编译流程，后续资源、地址、宏等校验仍可能拒绝。弹窗中若指出“尚未恢复设备编码”“属性未核定”，应按属性路径修正规格或补C实现；不能通过增加虚构数据、跳过校验或只画预览消除提示。

## 3. 阶段1：模型、文件与源格式规则

### 3.1 身份、页面和语言

- 页、对象、组、宏、连接和配置使用稳定身份；数组下标和原厂源偏移不能代替身份。图层稳定排序，同层保持原相对顺序。
- 当前活动页的`pageName/pageWidth/pageHeight/objects`是唯一活动存储；其它页保存在`inactivePages`，通过`pageOrder/allPages()`枚举。切页先存当前模型，不能丢隐藏页内容。
- `activePageId`用于编辑，`startupPageId`用于启动；编辑语言与`startupLanguage`也独立。切换编辑页/语言不修改设备启动选择。
- 显式启动页必须存在且为普通页；显式启动语言必须登记。语言重排按名称迁移功能13目标；删除仍被引用的页、语言或宏时拒绝。
- 复制重建对象/组/页身份并重映射内部引用。跨工程资源按内容核对，语言/连接不兼容或宏同名异内容时拒绝，不能静默改绑。

### 3.2 解析、保存与迁移

- 加载先在临时候选中完整校验，成功后才替换当前工程；保存先校验，再用`QSaveFile`提交。错误输入、保存失败或取消保留旧文件和当前有效工程。
- 使用最低可表达schema。阶段1实现1～9；阶段4扩展后当前能力声明为`KSP-schema1-to9-and11-to12`。不能由此推断schema10或未来版本可加载。
- 旧schema3～8的空宏表`[]`可无损迁移成`{}`；非空数组、null、schema9错误数组不按同一例外放行。
- 未知活动键、错误字段类型、非规范Base64、坏图、重复身份、悬空引用、超资源预算、无效源快照继续拒绝；扩展保存不等于未知功能已实现。
- `.ksp`是JSON工程；`.sm`为原厂typed源格式。扩展名守卫独立，禁止把JSON写到`.sm`路径冒充源导出。
- 原始源span/snapshot用于保全已核信息；opaque body不允许任意改写。完整多页typed读取消费到EOF，只证明结构解析，不等于多页语义导入、导出或设备C已支持。

### 3.3 当前后端边界

单普通页、已核型号、800×480、1..100对象、1..8语言进入C候选；多页、窗口/键盘/Logo、未恢复活动配置整份拒绝，不能只截当前页成功。五类源输出与静态图形设备输出使用独立门槛：本次6类静态图形的C不自动开放其完整`.sm`。

证据：[阶段1验收](阶段1工程模型与验收.md)、[语言接续修正](stage1-language-evidence/README.md)。实现：`project_model.*`、`native_project_codec.*`、`project_capabilities.cpp`、`device_compile_plan.cpp`。

## 4. 阶段2：主窗口与配置进入编译的规则

- 菜单和工具栏共用QAction及启用条件；无工程时禁用对象编辑和下载。文本输入内的剪贴板/撤销保持局部操作，不误触画布。
- 新建向导先收集草稿，确认才建工程；打开先完整解析候选，再处理旧工程未保存内容。保存失败或另存取消阻止关闭。
- 工程历史为完整事务，包含隐藏页、资源、宏和配置；导航不构成内容修改。保存点独立，撤销离开保存点变脏，重做回到保存点清脏。
- 系统参数UI已保存屏保0..60分钟、闪烁1..50×0.1秒、触摸声、默认等级1..8、LW进制；原厂快照工程该部分只读。含活动系统配置节点的工程在源/设备出口拒绝，不能把UI已保存理解为SysPara已生成。
- 默认COM1 Modbus说明与地址编辑器存在，不代表COM2、其它PLC协议或任意连接已具有设备驱动后端。
- 主窗口三行工具栏、停靠、树、工具箱、状态栏按原厂几何和图标资源恢复。主窗口外观数据不写成ControlPara；状态栏内存统计仅能取真实编译结果，未编译时留空。

证据：[阶段2验收](阶段2主窗口与工程配置验收.md)、[主窗口外观验收](主窗口外观复刻验收.md)。主窗口原厂坐标以该报告1353像素客户区样本为条件，不泛化到所有DPI/窗口尺寸。

## 5. 阶段3：画布、资源与渲染规则

### 5.1 坐标和事务

- 持久坐标为页面像素，缩放50/100/200%只影响视图；控制柄大小使用Qt逻辑像素。命中、拖动与缩放先逆映射场景坐标，再做页面边界校验。
- Esc/右键/切工具/切页完整取消活动创建；移动/缩放取消恢复原几何。资源暂存独立，成功落框一次提交；取消不留资源或空对象。
- 对齐、等尺寸、等间距和图层命令使用已核参考策略，无效操作不新增历史；原厂选择顺序、DPR及全部边界手势仍有未决，不能自动声称完全一致。

### 5.2 文本与图片

- 画布、属性预览和设备使用共用的文本/图片语义。字号为页面像素；整数用`setPixelSize`，小数按`fontSize*72/logicalDpiY`换点，不能先截断。记录实际字体替换及Qt版本。
- 工程池`pictures[name]`与状态内嵌`picturePng`分别保留。替换/重命名只同步名称和旧字节同时匹配的状态；同名异内容不能误覆盖。删除被显式引用或名称引用的图片时拒绝。
- PNG完整解码，单图源字节上限16MiB，尺寸1..4096；不可变源像素以原字节SHA256缓存，总预算32MiB。合成帧不能漏掉几何、语言、状态、字体等输入。
- RGB565帧每行写有效`width*2`字节；Qt的行填充不能进入设备流。按像素解码对照，压缩字节不同可以解释，但活动像素不同不能用压缩差异掩盖。
- 原厂Qt4与产品Qt6对线帽、曲线扫描、图库渐变和字体可能有差异。R共用渲染不足以推导C整帧相等，必须建立同输入对照；本次圆角矩形使用独立设备栅格模块。
- 动态文本重叠、透明动态覆盖、刷新顺序及触控优先级未闭合范围保留编译拒绝。上层文字透明合成不能只靠预览看起来正确就放行。

证据：[阶段3验收](阶段3画布资源与一致渲染验收.md)。

## 6. 阶段4：控件编辑与编译注册规则

阶段4共41项（31类控件、9类基础图形、1类表格）。已处理41项指已有实现复核、编辑切片或明确阻塞已登记；不等于41类均有C/T/E。各项状态见[逐控件进度](阶段4逐控件进度.md)及对应手册实现报告。

每个新控件必须有独立typed属性、默认/范围校验、属性草稿、确认后放置、双击回填、保存重开、复制和撤销路径。预览和画布使用相同属性解释。没有设备编码的活动对象必须被整体编译拒绝，不能改成普通文本/图片后报“成功”。消息、刻度、二维码、数据/配方类等26个新增动态类仍按各报告保持设备映射未恢复。

新增控件注册顺序：工具箱稳定命令ID → 属性编辑器 → typed模型/JSON校验 → 共用绘制 → 源能力 → 设备计划 → 独立编码/图帧 → 包核验。各层分开验收，不能仅因继承同一父类就复用另一类型设备联合体。

### 8.1 路径与坐标绑定

归一坐标映射为`(x + point.x*width, y + point.y*height)`。C要求映射后为整数且在屏内，不能先取整再静默接受小数。水平/垂直的carrier宽高至少1，对应归一轴分量可为0。两端点输入需检查原厂实际path count与sceneTransform；编译容器存在而对象路径为空不能算有效语料。

线段重叠采用当前几何相交守卫；表格/闭合矩形扩展右/下端像素后检查相交和边缘接触。该保守限制保障当前已证合成范围，不代表原厂所有对象均不允许重叠。

### 8.2 圆角矩形定点设备栅格

原厂实际QtGui版本为4.6.3，后端为Raster；无抗锯齿。独立生成本地`addRoundedRect(...,10,10,AbsoluteSize)`路径与宽1/SquareCap/BevelJoin描边，再由`device_roundrect_raster.cpp`扫描。生产不加载原厂DLL或拷入原厂像素。

1. 本地路径加整数场景平移后，截断到26.6坐标。
2. 三次曲线用整数中点递归细分；长弦以两控制点叉积距离和≤16×曼哈顿弦长判平，短弦用控制点曼哈顿距离和≤16；最大深度32。
3. 有向边先按Y升序整理并保留绕向，加入半像素偏置，求覆盖行；交点以16.16计算，最终向下取整，并保留native tie减1。
4. 每行交点排序，按path的winding/odd-even规则累计填充；X裁剪到0..800，Y限0..479。
5. 先白填充后黑描边，以活跃QPainter的`fillRect`写跨度，不能同时直接改正在绘制的QImage存储。

Qt6直接重放同路径差37像素，描边路径再填充差49；这些失败候选与后端排除证据均保留。默认整帧768000B SHA256为`1b3ae9051931ab0a5e6a80f8326636b4e8d65a2e360206e6773ca788691b9a82`。本算法只在表中范围放行，不能由单家族0差异自动开放所有曲线。

## 9. 总编译、图像、扫描与包规则

### 9.1 不可变计划及失败事务

`prepareDeviceCompilePlan`对工程快照校验，稳定排序并冻结对象，保存`sourceSnapshot`。每次拒绝记录pageId/objectId/property/value/reason。计划和payload均在候选中完成，失败不覆盖调用方先前有效输出。`buildProjectPayload`执行类型/地址/宏/资源完整校验后才生成正式产物；旧单文本入口不能绕过新类型守卫。

### 9.2 背景和动态图流

- `SheetPixel`是页面背景，与动态`ControlPixel`分开；背景本帧为800×480×2=768000B。背景边界和默认色遵循既有后端，不得单凭截图重绘模板。
- 每动态图按最终语言/状态/正常或隐藏文本角色分配帧；原始帧字节数为w×h×2。每帧独立LZO压缩、解压回验并补齐至32B，记录实际压缩长和补齐长。
- `PicLenPara`含三组页面数组（单页仍保留2400B头）和每图12B索引；帧顺序决定长度、压缩偏移及ControlPara.rawOffset/rawBytes。偏移为解压流偏移，不能误用压缩文件偏移。
- `SheetPara`计数/总量、控制记录数量、帧数量及累积rawBytes必须交叉一致。只有静态图形时没有ControlPara/ControlPixel，PicLenPara为2400B，不生成空动态占位记录。
- 同一模型源的B原字节、S容器结构、M解码语义分别对照。LZO编码非唯一；允许压缩字节不同，但不得放过活动像素/字段差异。Sys/Alarm/Usbload/load/upLoad同源不稳定区仍未知，没有整段忽略资格。

### 13.2 坐标、覆盖和混色

独立直边积分候选按以下顺序产生fill/stroke覆盖：本地move/line闭合 → 26.6截断 → 乘4至每像素256单位 → 有向边先Y后X网格分割 → floor有理插值 → 单元格累计`cover=Σdy`、`area=Σ(x0local+x1local)*dy` → 按行累计绕向 → 计算边界/间隙覆盖 → 按Winding/OddEven折返并夹取0..255。负数插值必须向负无穷取整；不能依赖C++有符号整数除法的向零行为。曲线标签不属于本算法范围。

`macros[name]`是QString源码，`macroIds[name]`可带稳定ID；KSP源码和原厂SM编译状态不同。原厂SM源码为UTF16BE QString；普通源码变化后导出重置已核编译完成标志和代码，保留未变记录。非零地址变量、未知依赖/启动标志继续拒绝；不把换扩展名当源格式互通。

指示灯/功能按钮的宏组在原厂禁用，当前UI、模型、源与设备出口均按已核各类型门禁；普通bit/word绑定不能推广到全部控件。离线模拟始终不执行宏，phase8新增编辑/编译不自动改变该规则。

### 22.2 既有ADS输入与容器规则

SDK选择顺序是KINSEAL_ARM_SDK→QSettings armSdkDirectory→程序旁arm-sdk；不是原厂路径默认结论。既有required共15项：armcc.exe/.dll、armlink.exe/.dll、fromelf.exe/.dll、Include/macrolib.h、glib.h、math.h、stdio.h、stdlib.h、script_amzlib.a、guilib70_amz.a、licenses/LICENSE.DAT、Lib/armlib/c_a__un.l。缺项在运行工具前拒绝；不复制许可证到C盘，不再发行SDK。

每宏将QString转当前系统ANSI并要求无损往返，临时文件名macro_000.c等不使用用户宏名。每个宏依次armcc `-O2 -g+ -cpu ARM920T -I SDK -I SDK/Include -c -o file.o file.c`；armlink指定RO/RW/entry/map/symbols/libpath与两已核库；fromelf `-c -bin -output file.bin file.axf`提RAW。AXF须ELF32 LE ARM、入口Macro_Entry在RO首地址、allocated RW/ZI均落本宏1024B槽；RAW不能是ELF，不把AXF重命名BIN。

QMap名称排序是Lite设计，编译索引与按钮索引同源；原厂创建序/列表序/禁用过滤尚未全部核。目标仅当前AMT配置：RO首80520400(hex)，后续加alignUp(rawLen,400 hex)；RW=80440000(hex)+index×400(hex)。MarcoRun为1024B头：有效数u8、byte1=FF、100个flag为0、100个LE16长度，后面实际RAW连续串接，不做文件内1KiB填充。MarcoVar每宏904B且全零，仅表达零地址变量；flag未知位不制造。

既有保护为最多100宏，每源1Mi QString code units、单RAW≤65535B、含头总包≤0x20000B、每宏RW/ZI≤1024B。初始产品进程默认单步30s、总120s、诊断256KiB；这些是Lite保护，不能声称原厂宏执行时限。所有宏成功才替换有效package与索引；C成功只证明已核型号和工具输入，不代表HMI执行E。

| 超时 | 单次1..60000ms；batch总期限>=单次且<=120000ms | UI单请求总期限采用120000ms；均为产品配置，非原厂观测常量 |

写值按十进制逗号分隔，空项/非十进制/超范围拒绝；UI冻结值快照后worker再按相同builder复验。批次API接受1..256项并要求id唯一，所有项先验证后才创建端点。新枚举和多写values追加在旧结构末尾，保留旧调用；01/03/05/06已有范围继续有效。

### 24.4 队列、收帧、取消和关闭

标准帧按地址/数量大端编码，CRC16初值FFFF、反射A001、低字节先。完整读响应需站号、功能、字节数/长度、CRC吻合；写应答须回显地址和值/数量，异常帧单独报错，不接纳无关响应或多余粘包。逐字节/分段/CRC/异常/超时/断连/重连由transport既有及本批测试覆盖。原厂读位DLL数量有u16左移3位内部单位，不能把描述直接当标准bitCount。

一个batch单open、FIFO、单请求在途、无自动重试、不合并。前项确认结果保留；首错丢弃后续未发队列并关闭。尚无扫描/用户写/RMW优先队列，也未做runtime映射。写调用一旦尝试，失败/取消不能承诺远端回滚；receipt保留writeAttempted及remoteStateUnconfirmed，UI提示可能已到达但未确认。不能用本地改值或发送成功冒充PLC确认。

QSerialPort在worker创建/使用/释放，接收buffer512B，bytesToWrite归零才算本次发送完成。接收以RTU silence收尾：<=19200按3.5字符向上取整ms，>19200采用2ms；20ms是取消轮询切片，空切片不返回为协议无进度。该串口时序实现尚无实际端口验收。

总预算含factory；预取消、预验证失败、factory期间取消/耗尽预算均不open。打开后每次写前、读前后、最终接纳前复查cancel/deadline；迟到响应不得接纳成功。停止只设shared atomic，UI冻结输入而保留停止；reject延迟到worker收尾，owner直接销毁只取消，线程不捕获QWidget，finished回调带context，线程自清理。

receipt区分sessionInactive（状态机不再连接）、closeAttempted、closeConfirmed与closed（未打开或确认关闭）。关闭失败保留首错和未释放状态；预校验失败也给一致字段。注入端点标controlled scope、物理false；默认串口只有实际open成功才给physicalEndpointUsed，仍不确认HMI执行。GUI用同一文本块展示最大2000项读值，完整结构保留lastReport()，不因日志块上限删除开头状态。
