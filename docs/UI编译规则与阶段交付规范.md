# UI编译规则与阶段交付规范

维护日期：2026-11-14。适用对象：KinSealStudioLite当前AMT070W124-L800X480R后端，800×480。本文补齐阶段0～7已交付切片及阶段8逐批实施的规则；后续每完成一个阶段性任务，必须在同一提交内同步维护本文和该任务专项报告。阶段5整体仍未完成。

本文的“UI编译”指界面属性经过工程模型、校验、渲染及段编码成为设备数据的过程。主窗口布局属于编辑器界面规则，不会直接编成屏端控件。可编辑、可保存、可导出原厂源、可生成设备数据、可下载和实屏功能正确必须分别记录。

## 1. 规则和证据的使用方法

| 层 | 输入与输出 | 通过要求 |
|---|---|---|
| D 规格 | 手册/原厂界面 → 字段及联动表 | 默认、范围、单位、活动条件、确认/取消/重开有来源，未知项有问题ID |
| U 交互 | 菜单/属性/画布操作 → 草稿或模型事务 | 相同操作产生已核结果；取消不插入对象、不改变工程 |
| P 持久化 | typed模型 → `.ksp`；另列原厂`.sm` | 保存重开、复制、撤销及语言切换保值；原厂源支持独立核定 |
| R 渲染 | 模型+资源 → 属性预览/画布图 | 字体、颜色、坐标与状态使用同一语义；预览一致不自动证明设备像素一致 |
| C 设备编译 | 不可变工程快照 → 设备段、图帧、索引 | 同范围原厂B/S/M对照；所有活动字段可表达；负向明确拒绝 |
| T 传输 | 指定EXE/工程/包 → 目标接收 | 段、提交及重启分别有回执；USB ACK不证明显示与触控 |
| E 实屏 | 外部刺激 → 屏幕/触控/寄存器/时序 | 目标固件和实际刺激、观测一一绑定 |

`describeProjectCapabilities()`的`candidate`仅表示有资格进入实际导出/编译流程，后续资源、地址、宏等校验仍可能拒绝。弹窗中若指出“尚未恢复设备编码”“属性未核定”，应按属性路径修正规格或补C实现；不能通过增加虚构数据、跳过校验或只画预览消除提示。

权威入口：[总执行入口](../design_plan/00_复刻执行总入口.md)、[A05源与设备契约](../design_plan/A05_源格式与设备编译契约.md)、[逐控件覆盖矩阵](../design_plan/控件文档与实施覆盖矩阵.md)。历史报告中的旧限制保留当时含义；本表及后续专项报告按精确支持范围补充，不能把旧单文本限制覆盖到当前五类后端。

## 3. 阶段1：模型、文件与源格式规则

### 3.1 身份、页面和语言

- 页、对象、组、宏、连接和配置使用稳定身份；数组下标和原厂源偏移不能代替身份。图层稳定排序，同层保持原相对顺序。
- 当前活动页的`pageName/pageWidth/pageHeight/objects`是唯一活动存储；其它页保存在`inactivePages`，通过`pageOrder/allPages()`枚举。切页先存当前模型，不能丢隐藏页内容。
- `activePageId`用于编辑，`startupPageId`用于启动；编辑语言与`startupLanguage`也独立。切换编辑页/语言不修改设备启动选择。
- 显式启动页必须存在且为普通页；显式启动语言必须登记。语言重排按名称迁移功能13目标；删除仍被引用的页、语言或宏时拒绝。
- 复制重建对象/组/页身份并重映射内部引用。跨工程资源按内容核对，语言/连接不兼容或宏同名异内容时拒绝，不能静默改绑。

### 3.2 解析、保存与迁移

- 加载先在临时候选中完整校验，成功后才替换当前工程；保存先校验，再用`QSaveFile`提交。错误输入、保存失败或取消保留旧文件和当前有效工程。
- 使用最低可表达schema。阶段1实现1～9；阶段4扩展后当前能力声明为`KSP-schema1-to9-and11-to12`。不能由此推断schema10或未来版本可加载。
- 旧schema3～8的空宏表`[]`可无损迁移成`{}`；非空数组、null、schema9错误数组不按同一例外放行。
- 未知活动键、错误字段类型、非规范Base64、坏图、重复身份、悬空引用、超资源预算、无效源快照继续拒绝；扩展保存不等于未知功能已实现。
- `.ksp`是JSON工程；`.sm`为原厂typed源格式。扩展名守卫独立，禁止把JSON写到`.sm`路径冒充源导出。
- 原始源span/snapshot用于保全已核信息；opaque body不允许任意改写。完整多页typed读取消费到EOF，只证明结构解析，不等于多页语义导入、导出或设备C已支持。

### 3.3 当前后端边界

单普通页、已核型号、800×480、0..100对象、1..8语言进入C候选（空页规则见第48节）；多页、窗口/键盘/Logo、未恢复活动配置整份拒绝，不能只截当前页成功。五类源输出与静态图形设备输出使用独立门槛：本次6类静态图形的C不自动开放其完整`.sm`。

证据：[阶段1验收](阶段1工程模型与验收.md)、[语言接续修正](stage1-language-evidence/README.md)。实现：`project_model.*`、`native_project_codec.*`、`project_capabilities.cpp`、`device_compile_plan.cpp`。

## 4. 阶段2：主窗口与配置进入编译的规则

- 菜单和工具栏共用QAction及启用条件；无工程时禁用对象编辑和下载。文本输入内的剪贴板/撤销保持局部操作，不误触画布。
- 新建向导先收集草稿，确认才建工程；打开先完整解析候选，再处理旧工程未保存内容。保存失败或另存取消阻止关闭。
- 工程历史为完整事务，包含隐藏页、资源、宏和配置；导航不构成内容修改。保存点独立，撤销离开保存点变脏，重做回到保存点清脏。
- 系统参数UI已保存屏保0..60分钟、闪烁1..50×0.1秒、触摸声、默认等级1..8、LW进制；原厂快照工程该部分只读。含活动系统配置节点的工程在源/设备出口拒绝，不能把UI已保存理解为SysPara已生成。
- 双击「参数设置」打开「触摸屏参数设置」。按参考截图使用 625×627 的单页双栏内容区，左侧是型号、其它参数和上载，右侧是用户等级密码。目标型号和启动画面分别写入 `targetModel` 和 `startupPageId`，切换启动画面时保留当前编辑页。两者可与五项系统参数在同一草稿中确认。原厂快照中的型号、启动画面和系统参数只读。各画面的显示模式、屏保画面、报警声音、各级及最高权限密码和上载保留参考显示，权限栏中的固定文字为原厂默认示例。窗口不读取或写入工程密码，沿用原有 `SysPara.dat` 规则。
- 字段和默认示例核对原厂 V5.1 随附帮助中的 `SystemSetUp/mainframeManager/modelType.htm`、既有原厂系统参数样本和本次确认的窗口截图。位置、边框和输入色值按 Windows 100% 缩放对照。
- 默认COM1 Modbus说明与地址编辑器存在，不代表COM2、其它PLC协议或任意连接已具有设备驱动后端。
- 主窗口三行工具栏、停靠、树、工具箱、状态栏按原厂几何和图标资源恢复。主窗口外观数据不写成ControlPara；状态栏内存统计仅能取真实编译结果，未编译时留空。

证据：[阶段2验收](阶段2主窗口与工程配置验收.md)、[主窗口外观验收](主窗口外观复刻验收.md)。主窗口原厂坐标以该报告1353像素客户区样本为条件，不泛化到所有DPI/窗口尺寸。

## 5. 阶段3：画布、资源与渲染规则

### 5.1 坐标和事务

- 持久坐标为页面像素，缩放50/100/200%只影响视图；控制柄大小使用Qt逻辑像素。命中、拖动与缩放先逆映射场景坐标，再做页面边界校验。
- Esc/右键/切工具/切页完整取消活动创建；移动/缩放取消恢复原几何。资源暂存独立，成功落框一次提交；取消不留资源或空对象。
- 对齐、等尺寸、等间距和图层命令使用已核参考策略，无效操作不新增历史；原厂选择顺序、DPR及全部边界手势仍有未决，不能自动声称完全一致。

### 5.2 文本与图片

- 画布、属性预览和设备使用共用的文本/图片语义。字号为页面像素；整数用`setPixelSize`，小数按`fontSize*72/logicalDpiY`换点，不能先截断。记录实际字体替换及Qt版本。
- 工程池`pictures[name]`与状态内嵌`picturePng`分别保留。替换/重命名只同步名称和旧字节同时匹配的状态；同名异内容不能误覆盖。删除被显式引用或名称引用的图片时拒绝。
- PNG完整解码，单图源字节上限16MiB，尺寸1..4096；不可变源像素以原字节SHA256缓存，总预算32MiB。合成帧不能漏掉几何、语言、状态、字体等输入。
- RGB565帧每行写有效`width*2`字节；Qt的行填充不能进入设备流。按像素解码对照，压缩字节不同可以解释，但活动像素不同不能用压缩差异掩盖。
- 原厂Qt4与产品Qt6对线帽、曲线扫描、图库渐变和字体可能有差异。R共用渲染不足以推导C整帧相等，必须建立同输入对照；本次圆角矩形使用独立设备栅格模块。
- 动态文本重叠、透明动态覆盖、刷新顺序及触控优先级未闭合范围保留编译拒绝。上层文字透明合成不能只靠预览看起来正确就放行。

证据：[阶段3验收](阶段3画布资源与一致渲染验收.md)。

## 6. 阶段4：控件编辑与编译注册规则

阶段4共41项（31类控件、9类基础图形、1类表格）。已处理41项指已有实现复核、编辑切片或明确阻塞已登记；不等于41类均有C/T/E。各项状态见[逐控件进度](阶段4逐控件进度.md)及对应手册实现报告。

每个新控件必须有独立typed属性、默认/范围校验、属性草稿、确认后放置、双击回填、保存重开、复制和撤销路径。预览和画布使用相同属性解释。没有设备编码的活动对象必须被整体编译拒绝，不能改成普通文本/图片后报“成功”。消息、刻度、二维码、数据/配方类等26个新增动态类仍按各报告保持设备映射未恢复。

新增控件注册顺序：工具箱稳定命令ID → 属性编辑器 → typed模型/JSON校验 → 共用绘制 → 源能力 → 设备计划 → 独立编码/图帧 → 包核验。各层分开验收，不能仅因继承同一父类就复用另一类型设备联合体。

### 8.1 路径与坐标绑定

归一坐标映射为`(x + point.x*width, y + point.y*height)`。C要求映射后为整数且在屏内，不能先取整再静默接受小数。水平/垂直的carrier宽高至少1，对应归一轴分量可为0。两端点输入需检查原厂实际path count与sceneTransform；编译容器存在而对象路径为空不能算有效语料。

线段重叠采用当前几何相交守卫；表格/闭合矩形扩展右/下端像素后检查相交和边缘接触。该保守限制保障当前已证合成范围，不代表原厂所有对象均不允许重叠。

### 8.2 圆角矩形定点设备栅格

原厂实际QtGui版本为4.6.3，后端为Raster；无抗锯齿。独立生成本地`addRoundedRect(...,10,10,AbsoluteSize)`路径与宽1/SquareCap/BevelJoin描边，再由`device_roundrect_raster.cpp`扫描。生产不加载原厂DLL或拷入原厂像素。

1. 本地路径加整数场景平移后，截断到26.6坐标。
2. 三次曲线用整数中点递归细分；长弦以两控制点叉积距离和≤16×曼哈顿弦长判平，短弦用控制点曼哈顿距离和≤16；最大深度32。
3. 有向边先按Y升序整理并保留绕向，加入半像素偏置，求覆盖行；交点以16.16计算，最终向下取整，并保留native tie减1。
4. 每行交点排序，按path的winding/odd-even规则累计填充；X裁剪到0..800，Y限0..479。
5. 先白填充后黑描边，以活跃QPainter的`fillRect`写跨度，不能同时直接改正在绘制的QImage存储。

Qt6直接重放同路径差37像素，描边路径再填充差49；这些失败候选与后端排除证据均保留。默认整帧768000B SHA256为`1b3ae9051931ab0a5e6a80f8326636b4e8d65a2e360206e6773ca788691b9a82`。本算法只在表中范围放行，不能由单家族0差异自动开放所有曲线。

## 9. 总编译、图像、扫描与包规则

### 9.1 不可变计划及失败事务

`prepareDeviceCompilePlan`对工程快照校验，稳定排序并冻结对象，保存`sourceSnapshot`。每次拒绝记录pageId/objectId/property/value/reason。计划和payload均在候选中完成，失败不覆盖调用方先前有效输出。`buildProjectPayload`执行类型/地址/宏/资源完整校验后才生成正式产物；旧单文本入口不能绕过新类型守卫。

### 9.2 背景和动态图流

- `SheetPixel`是页面背景，与动态`ControlPixel`分开；背景本帧为800×480×2=768000B。背景边界和默认色遵循既有后端，不得单凭截图重绘模板。
- 每动态图按最终语言/状态/正常或隐藏文本角色分配帧；原始帧字节数为w×h×2。每帧独立LZO压缩、解压回验并补齐至32B，记录实际压缩长和补齐长。
- `PicLenPara`含三组页面数组（单页仍保留2400B头）和每图12B索引；帧顺序决定长度、压缩偏移及ControlPara.rawOffset/rawBytes。偏移为解压流偏移，不能误用压缩文件偏移。
- `SheetPara`计数/总量、控制记录数量、帧数量及累积rawBytes必须交叉一致。只有静态图形时没有ControlPara/ControlPixel，PicLenPara为2400B，不生成空动态占位记录。
- 同一模型源的B原字节、S容器结构、M解码语义分别对照。LZO编码非唯一；允许压缩字节不同，但不得放过活动像素/字段差异。Sys/Alarm/Usbload/load/upLoad同源不稳定区仍未知，没有整段忽略资格。

### 13.2 坐标、覆盖和混色

### 22.2 既有ADS输入与容器规则

SDK选择顺序是KINSEAL_ARM_SDK→QSettings armSdkDirectory→程序旁arm-sdk；不是原厂路径默认结论。既有required共15项：armcc.exe/.dll、armlink.exe/.dll、fromelf.exe/.dll、Include/macrolib.h、glib.h、math.h、stdio.h、stdlib.h、script_amzlib.a、guilib70_amz.a、licenses/LICENSE.DAT、Lib/armlib/c_a__un.l。缺项在运行工具前拒绝；不复制许可证到C盘，不再发行SDK。

每宏将QString转当前系统ANSI并要求无损往返，临时文件名macro_000.c等不使用用户宏名。每个宏依次armcc `-O2 -g+ -cpu ARM920T -I SDK -I SDK/Include -c -o file.o file.c`；armlink指定RO/RW/entry/map/symbols/libpath与两已核库；fromelf `-c -bin -output file.bin file.axf`提RAW。AXF须ELF32 LE ARM、入口Macro_Entry在RO首地址、allocated RW/ZI均落本宏1024B槽；RAW不能是ELF，不把AXF重命名BIN。

QMap名称排序是Lite设计，编译索引与按钮索引同源；原厂创建序/列表序/禁用过滤尚未全部核。目标仅当前AMT配置：RO首80520400(hex)，后续加alignUp(rawLen,400 hex)；RW=80440000(hex)+index×400(hex)。MarcoRun为1024B头：有效数u8、byte1=FF、100个flag为0、100个LE16长度，后面实际RAW连续串接，不做文件内1KiB填充。MarcoVar每宏904B且全零，仅表达零地址变量；flag未知位不制造。

既有保护为最多100宏，每源1Mi QString code units、单RAW≤65535B、含头总包≤0x20000B、每宏RW/ZI≤1024B。初始产品进程默认单步30s、总120s、诊断256KiB；这些是Lite保护，不能声称原厂宏执行时限。所有宏成功才替换有效package与索引；C成功只证明已核型号和工具输入，不代表HMI执行E。

### 24.4 队列、收帧、取消和关闭

标准帧按地址/数量大端编码，CRC16初值FFFF、反射A001、低字节先。完整读响应需站号、功能、字节数/长度、CRC吻合；写应答须回显地址和值/数量，异常帧单独报错，不接纳无关响应或多余粘包。逐字节/分段/CRC/异常/超时/断连/重连由transport既有及本批测试覆盖。原厂读位DLL数量有u16左移3位内部单位，不能把描述直接当标准bitCount。

一个batch单open、FIFO、单请求在途、无自动重试、不合并。前项确认结果保留；首错丢弃后续未发队列并关闭。尚无扫描/用户写/RMW优先队列，也未做runtime映射。写调用一旦尝试，失败/取消不能承诺远端回滚；receipt保留writeAttempted及remoteStateUnconfirmed，UI提示可能已到达但未确认。不能用本地改值或发送成功冒充PLC确认。

QSerialPort在worker创建/使用/释放，接收buffer512B，bytesToWrite归零才算本次发送完成。接收以RTU silence收尾：<=19200按3.5字符向上取整ms，>19200采用2ms；20ms是取消轮询切片，空切片不返回为协议无进度。该串口时序实现尚无实际端口验收。

总预算含factory；预取消、预验证失败、factory期间取消/耗尽预算均不open。打开后每次写前、读前后、最终接纳前复查cancel/deadline；迟到响应不得接纳成功。停止只设shared atomic，UI冻结输入而保留停止；reject延迟到worker收尾，owner直接销毁只取消，线程不捕获QWidget，finished回调带context，线程自清理。

receipt区分sessionInactive（状态机不再连接）、closeAttempted、closeConfirmed与closed（未打开或确认关闭）。关闭失败保留首错和未释放状态；预校验失败也给一致字段。注入端点标controlled scope、物理false；默认串口只有实际open成功才给physicalEndpointUsed，仍不确认HMI执行。GUI用同一文本块展示最大2000项读值，完整结构保留lastReport()，不因日志块上限删除开头状态。

## 27. 位按钮：编译字段与运行消费者的对应规则（2026-11-15）

### 27.1 UI、源字段与设备字节

### 27.2 记录装载与运行覆盖

固定SHA的原厂离线模拟器`0x4542E0`以640B源槽取type10记录，将前448B复制到`0x14D22C60+index×0x624`。仅在复制瞬间前448B同偏移，剩余192B和运行对象尾部没有等价性。随后操作地址+5被清零，地址槽+0xC/+0x1C成为double缓存等；不能以运行转储回写静态配置。

四操作由`0x40F3B0`分派。已见正常链为显现/触控判断→主写helper→可选通知helper→同址缓存→宏请求→匹配控件缓存。route0写本地，route1/2入队；不能把调用次序解释为PLC确认次序。点动主地址单独登记释放队列，释放写0，所见释放helper不重复通知/宏，也未重查权限；全部取消事件是否调用释放仍待证。

### 27.3 不同消费者的兼容性守卫

该模拟器触控函数`0x44DA20`对字段`+0x21`只按精确0/1/3解释位、等级和二者组合；其它值默认返回1。显现有相似分支。它未读取现代字比较/容差字段。所见通知路径只按位值式通知处理，未按现代字通知字段分派。按压路径则因硬编码`0x72<0x75`在正常函数入口必被跳过，常量业务含义未知。

### 27.4 ARM 消费者：文件字段怎样变成行为

固定安装包固件SHA256 `74d510f150dc8edadf8e967bdb3c00ca5790ca68b9da6f906125a5234a485c24` 另用Direct Ghidra/Capstone静态分析。运行步长0x5C8、基址0x80146B34，与PC的0x624分开；ARM完整记录装载映射尚未定位，不能套用PC的复制函数。入口0x8007F13C先按压登记/再入，再检查可见缓存0x286和触控权限；读取0x114低字节，0/1/2/3调用SET/RESET/JOG/TOGGLE。编译器仍输出合法LE32枚举，不因消费低字节放宽畸形输入。

## 30. 工程树与串口设置的保存和编译边界（2026-11-22）

工程树以连接记录的 `channel` 归属 COM1 或 COM2。协议记录的 `id` 用于地址绑定，树标签从 `profileId` 对应的驱动目录取得。空端口仍可打开「连接设置」。

串口窗口提供连接属性和协议属性。两个窗口的默认波特率为 9600，校验为 NONE，数据位为 8、停止位为 1。COM1 默认通信方式为 485，COM2 为 232。恢复默认先更新窗口草稿。取消保留工程，确定作为一次工程事务。

工程地址使用稳定连接 ID，例如 `@plc-1:4x24` 对应该站的零起始 PDU 偏移 24。双字低字在前是 Lite 的当前约定，每个 RTU 寄存器内部仍按高字节在前传输。相同读范围共用一次轮询，跨字值从同一响应取齐。内部 LB/LW 属于本次模拟内存。

接入基础位按钮、字按钮、指示灯、静态文本、内置语言/等级操作和基础只读数值显示。外部字按钮支持写定值和已接入的键盘输入，位按钮支持设置、复位和切换。外部点动、寄存器位写入、组合通知、加减与绕回暂未接入。运行时保留一个待确认的写命令。线圈切换会重新读线圈，再发送取反值。监视控件依据通过 CRC、站号、功能和长度检查的读回应答刷新。写入超时或断线时停止轮询并清除远程值，需由用户重新连接。失败写入无自动重发。

在线模拟使用当前画面的工程配置和资源。KSP、SM、设备数据段继续由原有保存和编译入口产生。原厂外部模拟程序、DLL ABI 与 HMI 固件执行另行验收。单次 RTU 诊断入口位于「工具 → 兼容工具 → PLC 串口诊断」。

待验范围包括真实串口与独立 PLC 从站、6x／10x 等其他地址族和协议、多站多端口、画面间导航、带原厂不透明快照的工程、更多控件与采集／报警／宏运行。见阶段7执行清单。 [阶段7](../design_plan/08_阶段7_离线与在线模拟.md)

Windows 私有桌面运行模拟界面、运行时、Modbus、串口会话和阶段9界面五组测试，共 566 项通过。受控从站记录覆盖站号、零起始地址、CRC、切换前读取、功能 16 双字写入、超时后缓存失效、重新连接及 Esc 释放。现场物理从站仍待核。

### 40.1 写入确认后的读回

收到 PLC 的写入应答后，清除同一地址空间内覆盖该写入范围的旧读值。双字写入会同时清除重叠的整字、双字和寄存器位缓存。相同偏移的输入寄存器属于独立地址空间，已有数据仍可使用。轮询优先读回受影响的范围，再继续其他扫描或处理下一次写入。等待新值期间，依赖这些地址的触控权限按数据未确认处理。

Windows 私有桌面四个在线模拟定向用例通过。受控从站延迟双字读回时，确认了单字、双字、寄存器位和依赖权限的变化。另在写帧已经发送、应答尚未到达时点「断开 PLC」，确认提示写入未确认、释放端口、清除远程值，重连按读回更新且没有补发写帧。

## 41 水平翻转和垂直翻转

编辑工具栏和菜单使用 `action_h` 与 `action_v`。无选中对象时两项禁用并显示灰色图标。选中后，水平翻转左右反射，垂直翻转上下反射。多选或组合内的每个控件围绕自己的边框中心翻转，保留位置、大小、层次、组合和地址。同方向再次点击复原。每次操作产生一条撤销记录。

KSP 在控件记录中按需保存布尔字段 `flipHorizontal` 和 `flipVertical`，缺省为 false。画布、离线或在线模拟支持范围内的控件和键盘预览共用这一变换。线段及路径的命中区域和编辑手柄随已绘制方向反射。拖动端点时，将编辑后的顶点映回控件原有坐标。选择框和设备触摸矩形保持控件边框。

设备编译将翻转后的文本和已支持的按钮状态写入像素数据，背景及上层文本分别绘制。已支持的线段、折线和多边形先反射归一坐标，再通过原有编译校验。带设备 3D 边框的按钮、其余形状和其他尚未支持编译的翻转控件会给出提示。原厂 SM 导出遇到翻转标志时提示改用 KSP。旧单文本模板入口遇到翻转时提示使用通用工程编译。

Windows 私有桌面工作流 72 项通过，覆盖按钮置灰、实际点击、像素方向、端点编辑、撤销重做和 KSP 重开。单独的画布撤销用例通过。独立检查位图按钮的 RGB565 状态图和翻转静态文本的设备包，确认上传快照保留标志。未翻转静态样例的 10 个设备段与上一版逐字节相同。本轮验证至离线设备包，实屏效果留待核对。

## 42 多选手柄与对齐参考

在画布按住 Ctrl 逐个选择对象时，最后加入选择的对象用黑心白边小方块标记，其余选中对象用白心黑边小方块标记。四角和四边中点都显示手柄，每个手柄以视口的 5 个逻辑像素绘制，随画布缩放保持大小。取消参考对象后，最近选中的剩余对象接替。框选或全选一次加入多个对象时，按场景稳定顺序确定参考。同位置的手柄优先绘制参考对象的样式。

左、右、上、下、水平居中、垂直居中以及等宽、等高、等宽高统一以实心手柄对象为参考。参考对象的位置和尺寸保持原值。水平等间距和垂直等间距需要至少三个对象，继续按排列方向固定两端，并均分相邻对象边缘之间的间隔。

选择顺序和手柄只存在于画布。仅改变选择不产生撤销记录。对齐产生的坐标和尺寸按原有字段保存、撤销和编译。设备编译继续读取控件几何和属性。随包 AMZ 静态样例通过设备包校验，10 个设备段与上一版逐字节一致。

Windows 私有桌面工作流 73 项通过，覆盖 Ctrl 点选、取消参考对象、左对齐、等宽和 125% 缩放下框选。画布专项 46 项通过，覆盖其余对齐、等间距和组合布局。另有两项原厂 SM 往返用例缺少 `canvas-half-centered-saved-r3.sm` 和 `canvas-nested-locked-saved-r1.sm`，待样本恢复后复跑。

## 43 Windows 构建目录的 Qt 运行依赖

Qt Kit 提供编译和链接所需的头文件、导入库及部署工具。Windows 启动 `KinSealStudioLite.exe` 时，还要能加载同一套 Qt 的运行时 DLL 和平台插件。缺少 `Qt6Core.dll`、`Qt6Gui.dll`、`Qt6Svg.dll` 或 `Qt6SerialPort.dll` 时，应用在入口函数执行前就会失败。平台插件位于 `platforms/qwindows.dll`。如果提示已经找到 `windows` 却初始化失败，可用 `QT_DEBUG_PLUGINS=1` 查看 Qt 实际找到的插件路径及加载错误，核对版本、架构和插件依赖。

在 Windows 本机用带 `windeployqt` 和 `qtpaths` 的 Qt Kit 构建应用。每次重新链接 `KinSealStudioLite` 目标后，CMake 从所链接的 Kit 部署 Qt DLL、Windows 平台插件和编译器运行库，并写入应用目录的 `qt.conf`。同一 Kit 按部署工具的增量规则更新 DLL，以便同时链接测试目标。更换 Qt Kit 时使用相应的构建目录。运行时请保留 EXE 旁的 DLL 及插件子目录。已有部署文件被移走时，重新构建并链接应用可恢复。

本机 AMZ 构建目录在清除 Qt 和 MinGW 运行路径的后台环境中，部署前返回 `0xC0000135`，部署后 `--release-info` 成功并从应用目录加载 `platforms/qwindows.dll`。同一构建的 AMZ 静态样例编译及验包通过。此步骤只部署 PC 应用依赖，设备数据格式沿用已有规则。

## 44 V5.1 功能审查中的源文件与运行规则

受支持的 AMT 单页普通画面，原厂 SM V122 的页编号由 `page.head.19` 保存为三位十进制 QString。原厂空白单页样本的值为 `000`，三页对照样本的第三页为 `009`，页尾映射仍记录集合索引。Lite 导入后用整数保留非零编号，旧 KSP 缺省页号仍解释为零。写回仅更新已解析的编号字段，核对重读后的页号，再交付文件。

源互通允许单页编号 `000` 至 `999`，其余已支持字段和拓扑校验继续执行。AMT/AMZ 现有设备编译的普通画面仍要求编号 `000`。设备能力检测和源发行资格分别判断。原始快照带非零编号时，设备默认配置和启动语言派生也会拦截。多页、窗口和键盘的 native 写回需要对应布局与引用证据。

离线模拟中的基础只读数值显示使用本地 LW 读值。显现与触控权限按启用位、字、等级条件取交集，零有效条件放行。独立测试覆盖模拟帧和权限，实际设备 C/T/E 范围见本轮审查。图表属性的圆弧预览、报警入口、工具栏和反选是 PC 编辑操作。相关记录见 [全面审查报告](V5.1功能全面审查_20261125.md) 和 [未闭合清单](V5.1功能未闭合清单_20261125.md)。

## 45 原厂功能入口深审、设备查询与 PLC 对照

原厂「底层版本号」的查询向唯一 USB 触摸屏发独立命令 0x26。帧为 32 字节，前缀为 17 字节 ASCII KinSealStudioKiss，命令后一个字节为 0，剩余保留字节补零。读取最多 32 字节，在返回范围内取 NUL 前的版本文本。AMZ 实机返回 24 字节，文本为 Version:122-2026.03.04。上位版本来自实际运行的 Lite。0x31 和 0x53 是另一组设备身份和参数查询，不能用于推导底层版本。两个查询先占用接口 0，完成或失败均回收句柄。 [USB 协议](文件规则/AMZ070W01R工程编译与USB下载.md)

AMZ 的 10/12/14 段样例分别核对静态、局部动态、旧普通宏的设备包与只读传输契约。契约中固件字段需区分本轮实物查询、不可观测值和用户指定值。批量包验证只覆盖编译与校验，真机传输时提交、重启与可见结果分别核验。

工程在线模拟使用原厂协议设置的 50–300000 ms 超时。PC 手工诊断的每笔超时 1–60000 ms，批次总上限 120000 ms。模拟从站独立核对 RTU 码、CRC、写后读回、从站异常与显式重连。旧写请求断开后保持未确认，重连重新读当前数据。

二维码有效监控区按有效字节数的上取整半数检查，255 字节占 128 个字。0 字节时原厂取数不访问寄存器，编辑期仍要求可解析的字基址。属性拾取、修改地址和带地址增量复制时校验完整跨度。既存工程可以打开以便修正旧的越界地址。待恢复的构造、像素段和地址表映射见 [本轮未闭合项目](V5.1深度排查未闭合_20261125.md)。

## 48 空白页、单文本可编辑源和 PC 模拟

1. 已核型号的 800×480 普通启动页允许 0～100 个对象，语言数为 1～8。空页仍要经过型号、配置、页面和资源检查。将页面背景栅格化为完整 800×480 的 RGB565 图像，像素数据解压后为 768,000 字节。零动态对象时动态记录计数为零。独立验包还要检查段、长度、索引和源快照。原厂零对象默认帧的 SHA-256 为 `208891b9a73f55179fa2311da841880df13ca04aaa9f3f7545c786468400a04f`。
2. 单个静态文字有两个需要验证的输出。屏上显示由字号、样式、选定语言、文字、位置和宽高生成的图帧决定。工程可编辑内容另写入 `upLoad.knr`。普通编译要保留自定义工程名、页名、控件名和可编码的文字外观。适用 AMT 原厂源路径时，解压结果与正常导出的 SM 逐字节比较，再重开验证。Lite 扩展或旧版静态文本里保留的操作地址草稿使用可以保全字段的 KSP 快照。AMZ 可编辑源支持范围以实际包标识为准。固定 TEST 诊断夹具继续单独进行字节回归。
3. 电脑模拟复用工程里的十类图形与刻度绘制函数，按图层、几何与翻转绘制。普通图形、图片、刻度和消息不占用按钮触摸目标。图片单图绘制第零行，位监视 0/1 选两幅图，数值监视按无符号 16 位索引取图并限制在末行。静止消息按 U16/U32 监视值的低 16 位取有符号索引，负值归零，过大正值取末行，按当前语言渲染。读值尚未确认时跳过对应帧，读数完整后更新。图片计时或闪烁与消息滚动仍有单独的时序限制。
4. 二维码空描述的属性预览和画布使用原厂图库里的默认图案，按目标矩形缩放。非空描述沿用文字编码预览。设备端动态二维码还涉及监视字节、交换、显现、重绘及段索引，本轮桌面绘制更改未开放这一设备记录。[二维码核对](二维码手册实现与验收.md)
