# 实屏宽度提示与下载生命周期排查

日期：2026-11-13。阶段4保持33/41项编辑切片交付，G06圆/椭圆暂停期间插入本次排查。

用户确认屏幕只显示“控件宽度不够，无法显示”，没有表头。诊断发现：用于阶段4原厂基线下载的验证脚本根据窗口“下载完成”文字提前结束，随后终止原厂进程，可能截断提交或重启后的USB调用，导致实屏继续运行旧画面。同源B工程的实际对照已复现并消除画面不更新。

## 实物对照

诊断A、B均为800×480单静态文本页，具有完整schema2属性；由Lite已验证的静态文本SM导出器生成，再由原厂软件编译和下载。没有使用Lite独立设备编码。四项清除/固件更新全部关闭，原始0x34参数为000000。

| 运行 | 完成规则及实际尾部 | 用户实屏反馈 |
|---|---|---|
| marker-a-r1 | 原UI规则加8秒观察；捕获提交ACK、重启写入和重启后读取-5 | 用户照片显示KS-DIAG-A-1113、STATIC TEXT ONLY、800x480，宽度提示消失 |

两轮B源SHA均为`08456dda36bd923e28c41d1dc9cb1336ffb7ea54d856ded57c41c93a2b90f1ca`；两轮SheetPixel.dat SHA均为`4d6be0b10d9025452c8e438d698ddc3409e8f2dd4dca799b5b607ffd5883e311`。观测钩子只记录原始USB调用，不改变缓冲区、返回值或等待时间。

旧B在重启写出约103毫秒后终止进程，最后一次读取只有enter，没有leave。修复B在重启后约427毫秒收到读取-5，随后观测到usb_close返回0，最后才终止进程。UI文字早于真实提交ACK和重启，不能作为结束原厂进程的条件。

## 修复与回归

`tools/native_usb_probe_lifecycle.py`在内存中构造硬件验证代码，保持用户主目录的阶段3脚本原样。只读取下载窗口m_table；每轮从独立事件游标开始，避免沿用旧轮次成功事件。`tools/usb_transfer_completion.py`配对enter/leave、检查完整写入、重组24字节识别回复，确认机型0x4C、设备参数、开始ACK、提交ACK、重启写入及其后读取退出；缺失、短写、截断、其他读取错误和清除选项不放行。重启后的-5仅在已确认开始、提交与重启写入的上下文内视为本机型已观测的正常断线，不泛化到其他错误或其他设备。

最初只等待重启写入的候选也被旧B实物对照否定：该轮已有完整重启写入，画面仍停在A。新增真实旧B回放后先出现失败，再补上重启后读取结束条件；最终18项标准库回归通过。实际生成的硬件调用点回放，旧规则0.5秒退出、新规则等待1.5秒后才完成；实物B随后确认正常显示。没有用固定sleep替代协议完成判定。

只读复核检查了生成脚本语法、请求/回复配对、事件轮次、识别重试、清除选项、短写与缺失回复、终止时序和输入SHA。未发现本次范围内的阻塞项。G06既有C++/Qt测试改动不属于本次修复；其首轮实际结果193+59+10通过、1项失败，失败为缺少原厂椭圆PNG输入，尚未交付。
