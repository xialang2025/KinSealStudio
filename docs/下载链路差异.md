# 下载链路差异与当前验证边界

当前已恢复命令的字节布局、状态机、十段数据对应关系和证据索引集中记录在 [AMT070W124-L800X480R USB 下载协议：已验证部分](AMT070W124-L800X480R_USB下载协议_已验证部分.md)。本文保留分析经过和实现边界。

## 已确认

- `model.dat` 将 `AMT070W124-L800X480R` 标为 AMT 系列、800×480、USB 支持；原厂 `modelInfo.dat` 中该型号的设备编号为 76，`USB=2`，`SerialPortDown=false`。其固件配置名为 `AMT070W124-L800X480R.bin`。
- Windows 将 `USB\VID_7365&PID_616C` 枚举为 `Smart Control Device`，类别由 libusb-win32 驱动提供。这是原软件的 USB 下载设备标识。2026年11月7日曾暂时未检出；2026年11月8日用户完成实屏下载后，设备已重新枚举且状态为 `OK`。早先看到的 CH340 COM10 不属于这条已确认的原厂 USB 下载路径。
- 原厂 USB DLL 的静态分析确认它通过 libusb 打开 VID/PID `7365:616C`、claim interface 0，并经 bulk OUT endpoint 1 写入。这里只证明底层传输入口存在。
- 原厂帮助说明 USB 下载需先让屏进入 USB 模式，然后通过“工具 → 下载工程 → USB下载”发送已编译工程，并建议下载前备份当前工程。
- 用户于 2026年11月8日确认，已在原生软件中下载本项目的 `CodexProbeTest.sm`，实物屏显示“TEST”。同日 Windows 再次枚举到状态为 `OK` 的 `Smart Control Device`（`7365:616C`）。这验证了固定静态文本工程借助原生软件的实屏下载链路。
- 2026年11月8日新增受限下载桥接：重写软件先导出经过严格校验的单文本 `.sm`，再通过独立后台桌面中的本机原厂隔离运行时编译和 USB 下载。后台直接运行桥接脚本，原厂窗口显示“下载完成”，脚本据此返回成功；一次函数跟踪期间下载超时，另一次设备暂时未连接，桥接会在失败或停滞时拒绝报告成功。此结果没有独立屏内读回。
- 同日，历史桥接版 `KinSealStudioLite-USB` 在独立后台桌面通过界面打开 `CodexProbeTest.ksp` 并触发“下载工程”，弹窗报告“原厂隔离运行时报告 USB 下载完成”。这只记录旧桥接调用链；当前 `KinSealStudioLite-Independent` 已改为直接访问系统 USB 驱动。
- 已用原厂隔离副本生成目标机型、800×480、单画面、一个静态文本的 `.sm` 工程及离线 `.kns` 包。本项目可在严格受限的固定单文本样例中导出 `.sm`；输出的“TEST”工程与已由原厂成功打开的样例逐字节一致。隔离副本重新编译该工程的 `.kns` ZIP 完整性检查通过，`upLoad.knr` 解压后包含 UTF-16BE 的“TEST”。
- 安装目录有原厂编译包 `compile\load.kns`、型号固件和若干 DAT 文件。这些内容用于分析参考；本原型没有改动它们。
- 对现有 `compile\load.kns` 的只读检查确认：它是标准 ZIP 容器，内部有 18 个文件，ZIP 完整性检查通过。16 个条目与当前 `compile` 同名文件逐字节一致；`SysPara.dat` 和 `AlarmPara.dat` 不一致，因此不能直接把当前散落的 DAT 文件当作该归档的完整快照。
- 归档内 `upLoad.knr` 的前 4 字节是大端序长度 `34941`，其余字节可用 zlib 解压，所得数据恰好 34941 字节；这与 Qt `qCompress` 容器结构相符。解压后的内部序列化字段仍未解析。
- 2026年11月8日新增长度和 SHA-256 锁定的固定 TEST 编译数据。新版程序通过 Windows 系统 `libusb0.dll` 独立枚举并打开 `7365:616C`，占用接口 0，向 bulk OUT `0x01` 发送命令与数据，从 bulk IN `0x81` 读取应答；不启动或加载原厂软件/DLL。单独进行的两条设备识别命令均返回与原厂抓包一致的 24 字节内容。
- 六轮目标设备抓包的完整传输都包含 30 条 32 字节命令和 10 个数据块。静态分析确认多个命令在原厂实现中仅写入前缀与命令码，未初始化的尾字节不属于稳定协议字段；新版将尾字节清零。`0x34` 带三个开始选项，`0x11` 带 4 字节小端程序长度；`0x1e` 的数据块在压缩工程前带 4 字节大端长度。
- 新版便携程序后台实机下载 `CodexProbeTest.sm` 时，所有预期应答（包含 `0x1b` 提交命令的 `'O'`）通过，最后的 `0x1a` 重启命令发送成功，进程退出码为 0。用户随后确认实物屏显示 **TEST**。下载后 Windows 仍将目标设备枚举为状态 `OK`。这验证了固定 TEST 工程的独立传输与屏端显示，不等于支持任意工程。
- 私有桌面还验证了当前独立版的界面入口：打开 `CodexProbeTest.ksp`，点击“下载工程”，界面报告“USB 传输完成”，并说明数据段、提交命令已获确认及重启命令已发送。后台窗口捕获保存在 `.scratch/kinseal-20261108/qt-download-result.bmp`。
- 2026年11月8日进一步建立单文本差分样本。`SheetPixel.dat` 是完整的 800×480 RGB565 帧的 LZO1X 压缩流；`PicLenPara.dat` 首四字节是该流长度的小端整数。`upLoad.knr` 是 Qt `qCompress` 快照，已定位三个 UTF-16BE 文本字段和两组坐标。相同原厂输入的重复编译中，这两个内容段稳定；另外三个系统段存在非确定性变化，本版暂沿用已验证的固定值。
- 使用 MIT 许可的 `lzokay` 实现 LZO1X 编码；原厂解码器能还原新版压缩的 RGB565 帧。Qt 6 的微软雅黑 12pt 渲染修正一像素纵向偏移后，AB12、AAAA 和位移后的 AB12 的解压帧与原厂样本逐字节一致。测试样本和比较数据位于 `.scratch/kinseal-20261108/corpus/`。固定 TEST 路径保持十个数据段逐字节一致。
- 新版后台独立下载位移后的 AB12，所有数据段、状态检查和提交命令获设备确认，重启命令已发送；用户确认实物屏正常显示 AB12，位置也正确。
- 本轮原厂隔离副本接受单字符、长英文、中文、空文本、90×30 与 240×90 文本框，以及两行和三行文本。新版按 UTF-16BE 序列化可变长度文字并同步修改三个长度字段和两组宽、高、X、Y 字段；短文本、中文、不同尺寸及多行的多个 800×480 RGB565 帧与原厂逐字节一致。`HELLOWORLD12` 有少量字距差异，150×50 时为 118 个像素，90×30 时为 51 个像素。
- 中文 `测试中文AB` 的 240×90 样例和三行文本均已由新版独立下载并获全部 USB 应答；三行样例从私有桌面界面入口触发。用户确认两者的屏上文字和位置正确。

## 尚未恢复

- 静态文本以外的控件在 `SysPara.dat`、`ControlPara.dat`、`ControlPixel.dat`、`SheetPara.dat` 等原厂文件中的完整字段映射、索引规则和校验方式。
- ZIP 内部各 DAT 文件和 `upLoad.knr` 的通用生成规则，以及任意画面数据如何独立编译为屏端可执行工程。当前只恢复了单静态文本的可变文字、位置与尺寸字段；其他段仍沿用已验证的 TEST 模板。
- 对其他机型、不同控件、极长文本、失败恢复、重试及大体积工程的 USB 兼容性。原厂的全部字体、字距及长度上限尚未穷尽比对。
- 从屏端读回工程、断电重启后保持显示，以及触摸交互的验证结果。当前“TEST”静态文本不包含触摸交互。

## 本版本的下载行为

状态栏只读取 Windows 即插即用设备枚举结果，查找 `7365:616C`。新版“打开工程”可以导入与已验证单文本模板逐字节一致、仅四字符文本字段不同的 `.sm`，保存时要求另存为 `.ksp`，不会覆盖原始 `.sm`；其他原厂工程仍不能导入。点击下载后，软件仅接受目标型号、800×480、单个静态文本控件以及位于画面内的文本框；文本可为中文、英文、空文本或显式多行，宽、高、X、Y 可变。软件先独立生成 RGB565、LZO1X、长度表和可编辑工程快照，再启动自身的隐藏下载进程，通过系统 USB 驱动传输。不支持的工程在打开 USB 前拒绝。原厂桥接脚本保留为历史实现，但不随新部署包提供，也不会被调用。

固定 TEST 包、变更文字和位置后的 AB12 工程、中文 240×90 文本框，以及三行文本均已独立 USB 写屏，并由用户确认实屏文字与位置正确。要把任意新增或修改的其他控件独立下载，还需恢复其编译格式，并扩展 USB 错误恢复及读回验证；当前没有协议级屏内读回、断电保持或触摸功能证据。
