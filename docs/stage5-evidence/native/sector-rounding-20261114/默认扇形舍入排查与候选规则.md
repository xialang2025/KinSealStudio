# 默认扇形单像素差异：整数混色舍入顺序（2026-11-14）

本轮将默认扇形从此前 1 个像素差异修正到 **768000 字节整帧相等**，原因是候选的整数混色舍入顺序。没有修改生产代码或开放扇形设备编译。

`73653ee69d44d72a4ab9c6547c817423bdfae1e0c5da44b12da347caa5fe0251`

旧公式的 1 差再次真实重现且独立保留，本轮没有覆盖 `sector-investigation-20261114/` 的历史失败结果。

## 2. 精确混色规则

已确认 Qt4 的每项整数函数为：

```text
D(v) = (v + (v >> 8) + 128) >> 8
```

旧候选采用了另一个顺序：

```text
D_old(v) = (v + 128 + ((v + 128) >> 8)) >> 8
```

二者不能互换。每个颜色通道必须分别计算源和目标贡献再相加：

```text
out = D(source * alpha) + D(destination * (255-alpha))
```

本次默认样例的源为白色 255，因此源贡献等于 alpha。先在 RGB32 中依次混色，最后只量化一次 RGB565；不能提前把底色变为 RGB565。

差异点为设备坐标 (268,126)，覆盖率 alpha=11。对底色红通道 197，目标项分子为 `197*244=48068`：新式 D 得 188，旧式 D_old 得 189。源项均为 11，导致候选红通道分别为 199 和 200，跨越 RGB565 的红色量化阈值。新候选 RGB 为 (199,223,255)，量化结果 `0xc6ff` 与原厂吻合；旧候选 RGB 为 (200,223,255)，量化为 `0xceff`。这是对候选整数值的计算，并非直接观测原厂未量化 RGB32。

因此，此前不能用原厂路径重放消除的 1 像素，在同一覆盖图上仅更改 D 顺序即可消除，不需要修改路径、曲线细分或硬编码像素。

## 3. 已核默认输入与仍需验证范围

本轮只核对一个保留默认场景：

- UI 几何框 (100,100,200,200)，中心 (200,200)，独立路径起角 45°、扫角 90°，即弧端点 45°..135°。
- 原厂记录为局部 8 元素路径，真实场景矩阵是整数平移 (100,100)。
- 实际原厂调用是 QPixmap 800×480、NoPen、绘制提示 3；本候选为白填充、无描边、alpha255。
- 页底色 RGB32 为 (197,222,255)，顶行和左列为黑色。全帧不使用忽略掩码。

只有默认白填 NoPen 的整帧和路径构造在此建立了候选证据。平移、尺寸、奇数尺寸、起止角、方向、线型、填充开关、透明度、颜色、描边、保存重开、多对象、贴边与混合包仍须分别取得有效原厂语料后验证。不能把本轮默认 0 差写成“扇形已支持”或直接开放门禁。

独立路径由 Qt6 与已保留公共 Qt4 灰栅格诊断程序产生；细分与直边积分由自写 Python 实现完成。原厂路径只作为另一对照输入，不是生产输入。执行文件导入表同时归档，未导入原厂 QtCore4/QtGui4 DLL；没有启动原厂、访问 USB 或改变生产文件。
