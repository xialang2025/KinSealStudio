## 1. 工程模型与迁移

旧单页`pageName/pageWidth/pageHeight/objects`继续作为当前编辑页的唯一存储，没有双份活动对象缓存。其余页面放入`inactivePages`，统一通过`allPages()`按`pageOrder`枚举。旧文件迁入`project-1/page-1`，原对象ID、layer/group、语言、图片字节和专有属性保留。保存采用最低可表达schema，旧schema1～8都保留读写测试；仅使用新增语义时选择schema9。

| schema9内容 | 规则和边界 |
|---|---|
| 工程身份`projectId` | 稳定字符串身份，显示名可改 |
| 页面`id/kind/name/width/height/objects` | normal/window/keyboard/logo；特殊页角色只实现K持久化 |
| `activePageId/pageOrder` | 编辑页与顺序独立；切树先存当前画布再切页，隐藏页对象不丢失 |
| `startupPageId` | 必须指向存在的普通页；编辑切页不更改它 |
| `startupLanguage` | 显式语言名必须已登记；空串继承可解析原厂启动设置或新工程首语言 |
| 配置节点 | system/project/dataCollection/alarm/recipe/macro/dataTransfer；仅允许implemented=false、active=false、空properties |
| `references` | 所有者和目标按实体类型与稳定ID解析；缺失、重复、悬空均拒绝 |
| `macroIds` | 可选名称到稳定ID映射；不把旧名称当稳定ID |
| `extensions` | 命名空间键和version/inactive=true/data对象信封；只保留惰性元数据 |

`selectPage/addPage/copyPage/renamePage/removePage/renameMacro/setLanguages`提供事务模型操作。复制生成新页面/对象/组身份并重映射页内引用与拥有配置；被引用的页面和启动页不能直接删除。宏改名更新所有页面中的绑定。语言重排按原语言名称重映射所有页面中功能13的目标，拒绝删除仍被功能13或显式启动设置引用的语言；翻译草稿继续保留。完整页面管理窗口属于阶段2，本轮接入了现有工程树的多页切换。

加载在临时候选中验证后替换输出；保存先完整验证再`QSaveFile`。 原0.7.0阶段0工具曾输出空宏表`[]`，schema3～8对这一无损别名提供迁移并规范保存为`{}`；非空数组、null、图片数组及schema9数组仍拒绝。原始旧基线保留不改。未知活动JSON键、未来schema、错误属性组合、非规范Base64、损坏图片/快照、重复身份、超资源保护和非法引用均拒绝。保存失败不覆盖原文件。迁移CLI只允许`.ksp`输出，防止用JSON覆盖原厂`.sm`。
