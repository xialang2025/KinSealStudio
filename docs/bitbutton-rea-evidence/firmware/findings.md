# 位按钮 ARM 固件静态分析结果（2026-11-15）

本证据由现有 Windows Ghidra 12.1.4 和 Python Capstone 直接获得；**不是 REA Evidence 记录**。分析对象为安装包固件 `AMT070W124-L800X480R.bin`，SHA256 为 `74d510f150dc8edadf8e967bdb3c00ca5790ca68b9da6f906125a5234a485c24`。没有执行、刷写或读取实物固件，因此不等于已核当前屏内版本。

## 地址与装载边界

- 原件长 `0xDD800`；32 字节 `eGON.EXE` 头后是 ARM 启动，链接地址为 `fileOffset + 0x8001FFE0`，启动 VA `0x80020000`。异常向量绝对指针和返回分支构成直接交叉依据。
- ARM/Thumb 混合；启动 scatter 项对 RW 段复制、解压、BSS 清零。`reconstruct_firmware.py` 仅转写已见数据循环，输出分析内存映像，未执行固件。
- 解压输入消耗 `0x235F`，输出 `0x5574`；RW SHA256 `2880fba2e52e80abc614fc84926459f55f2e833557307ddd866294b602e4fcd0`。
- **链接 VA 不等于已核 bootloader 物理装载流程。头字段校验含义未知。设备文件 0x280 记录→ARM 运行时 0x5C8 记录的装载/扩展复制链尚未定位。** 不应凭消费偏移相似声称整条映射全证。

## 消费、通知、宏

运行记录基址 `0x80146B34`、步长 `0x5C8`。`0x8007F13C` 读 `+0x106` 子类型；位按钮 subtype=0 先经按压 helper，再检查 `+0x286` 和触控权限。允许后按 `+0x114` **字节**分派：0 SET→`8002B038`，1 RESET→`8002AF44`，2 HOLD→`8002AE44`，3 TOGGLE→`8002AD18`。

SET/RESET 主写 1/0；HOLD 写 1 并登记释放地址；TOGGLE 按 `+0x124` f64 是否为 1 翻转。四个操作都是主 write helper `8007C1E4` 返回后调用通知 `80060E5C`；操作函数返回到 dispatcher 后，再调用宏排队 `80074830` 与同址监视传播 `80040820`。外部通信是队列，调用顺序不保证 PLC 实际完成先后。

通知总使能 `record+0x16`；mask `+0x23 & 1` 位通知优先，否则 `& 2` 字通知。位值 `+0x20`，字 f64 值 `+0x44`，地址 `+0x70`。通知跳表 `80060FB0..80060FC8` 的7项全部保存为原字：`80060FCC,80060FF4,80061024,8006104C,800610B0,800610B0,8006107C`。对应 type 2/3/4/5/8 的转换分支为 I16/I32/U16/U32/F32；type6/7跳到公共末尾 helper，**不能声称无效类型会拒绝**。

宏消费只在 header+1==1、全局ready==1、header+2 **无符号**索引 < 宏数时，设置该宏 pending=2、全局 pending=1。证明的是排队，未证明同触控栈同步执行或与 PLC 写完成之间的时序。

## 权限与显现

触控 wrapper `8005434C` 调 `80057258(record+0x14)`：总使能关闭即允许；mask位/字/等级分别为4/2/1，启用的条件按AND组合。返回1允许，2位/字拒绝，0等级不足；等级最后覆盖，优先返回0。currentLevel-1 >= storedMinimum；storedMinimum由UI最低等级减1编码，普通有效等级下阈值相等允许。

位条件对合法0/1等价预期：desired0只在actual==1拒绝，desired1只在actual==0拒绝。**不能泛化为任意非boolean都严格相等。**

对于有限正常数且加减结果正常，令 x=当前字值，c=目标，t=max(容差,0)：枚举0 `<`，1 `>`，2闭区间 `[c-t,c+t]`，3严格区间外，4 `<=`，5 `>=`。负容差会直接写零回运行记录。比较枚举>=6跳过字条件拒绝路径，不是自动拒绝。`800A3984/800A3C58` 是两种顺序的flags比较；`800A3EFC` 减法与 `800A32AC` 加法共享尾分支。`raw-evidence.json` 保留跨Ghidra函数边界的完整窄范围，避免只导出 `800A3EFC` 的4字节 TEQ。NaN、无穷、次正规数和溢出路径未核。

显现 `80057074` 同样按位/字/等级AND组合，common+1总使能，common+0x0E mask；任一不满足返回0。NaN/无穷/次正规数/溢出和异常回调不在已证范围。

## 按压调度与取消

`80054ED0(index, record+0x1BD, u16(record+0x1BE))`：使能值!=1立即返回0；使能值==1且state=0时登记index、counter=0、threshold、state=1，返回1暂缓；state=1再进入时清state并返回0放行。

无常规PUSH序言的任务入口 `80082248` 在state!=0时比较counter与 `(threshold * 0xCCCD) >> 20`；相等时检查widget+0x26 bit8（`8002A034`），构造消息0x26、参数1（`8008A100`）。任务每轮counter++，尾调 `80061F3C(20或100)`。该helper将参数写到当前TCB+0x30并调度，**只证RTOS延迟计数参数，未核tick频率，不写成已证毫秒**。对全部65536个u16值的除20恒等式数学检验通过，非固件执行。

`80056840` 清index、counter、state、threshold及同组辅助值。`8009F594` 的消息0x26、子码2/3分支在 `8009F6A0` 调它，随后可能尾调释放dispatcher；子码1/4走按下dispatcher。这是直接消息分支证据，硬件触摸输入到消息子码的完整生成链尚未核全。`8009A224` 启动初始化和 `80079B14` 通用重置同样清状态；页面切换的全部调用链尚未核全。

## HOLD 释放真实写零

`8007C1E4` 第二参数=1时登记 `801882C0` 列表，count=`800FFFA0`，每项0x0C、最大200；单项含地址类型/站号/地址、index(+8)、route(+10)。**base+9是整个列表的待处理flag，不是每项独立flag。**

`8003A670` 在base+9==1时逐项消费：route0将四个零栈参数传入 `8007BDB0`。该helper的本地LB type0x42路径实际存0，bit-in-word type0x5F路径清bit。route1/2向相应外部队列写f64=0，容量200；满时跳过入队。随后视监视条件清缓存、更新同址监视，最终清列表flag与count。

`8007F490`：配置 `[80212E68+0xF8B]==0` 时直接调用释放消费者；==1时 `8007F50C` 仅对subtype0、operation2置 `80100285=1` 并清传输位置。`8005FD28→800606E8` 在传输扫描位置达到计数时调用消费者并清该flag。**配置含义名称尚未确定**，这里只记录代码分流。

该释放消费者未调用通知或宏函数，支持“已见释放链不重复通知/宏”。外部队列满分支仍在结尾清释放列表，因此不能保证异常通信/队列耗尽时PLC一定收到释放0；也未证明所有跨页/取消边界行为。
