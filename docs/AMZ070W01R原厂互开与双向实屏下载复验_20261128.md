## 原厂重复编译的变化

原厂最初两次导出的包具有同一时间和 SHA-256。重新打开磁盘上的 01 后，原厂在 21:21:36 生成了另一份包，与 21:03:42 首次编译的 16 个成员中有 12 个相同。按相同偏移比较，并计入长度差，`AlarmPara.dat` 相差 2,455 字节、`SysPara.dat` 相差 122 字节、`Usbload.bin` 相差 2 字节、`upLoad.knr` 相差 1,658 字节。页图和长度表稳定。01 与 02 的屏幕解码结果只有文字最后一位的 43 个像素变化。[三份原厂包、内嵌工程与编译时间](文件规则/样例/AMZ实机首次双向互开_20261128/三次原厂编译归属与重开对照.json)

这三份现场原厂系统段中，偏移 171、207、215、219、231、383、863、903 的值均为 `07`，Lite 的模板为 `06`。另取 7 份不同的原厂工程，每一份都找到相同源 SHA-256 对应两种原厂编译结果，上述 8 处在一个结果中全部为 `04`，在另一个结果中全部为 `06`。这证明输入 SM 不能唯一决定这 8 个值。它们分别位于小端 32 位字的最高字节，具体运行时含义仍未确认。[七组反例和逐字记录](文件规则/样例/AMZ实机首次双向互开_20261128/八个系统字节的同源原厂反例.json)

## Qt 启动弹窗与发布验证

旧绘图回归将 Qt 平台强制设为 `offscreen`，发布目录只包含 `platforms/qwindows.dll`。在没有 Qt SDK 路径的独立 Windows 桌面上复现了用户截图中的完整错误文字。补入与现有 QtCore、QtGui、qwindows 匹配的 Qt 6.12 MinGW x64 插件 `platforms/qoffscreen.dll`，并将其加入 CMake、PowerShell 部署和新 Stage11 包的验证规则。主编辑器继续使用 Windows 平台。

正式发布目录与两个候选目录均经过独立桌面验证。无参数启动可见 KinSealStudio 主窗口，指定 Windows 和 offscreen 的自检均正常退出。正式 EXE 为 52,344,407 字节，SHA-256 为 `a58d7eb8664f80c67362843f5fbc1b67a96b7c091846746ddb27daed6da78f50`。控件套件通过 245 项，原生源套件通过 79 项，Stage11 打包测试通过 35 项。历史 Stage9 r2 的完整运行目录和对应冻结清单未找到，历史 Stage11 整包重建仍待验证。[发布、平台和回归回执](文件规则/样例/AMZ实机首次双向互开_20261128/便携版启动与回归.json)
