## 4. 独立定点曲线细分

调查原型位于任务脚本目录`ellipse_algorithm/ellipse_curve_candidate.h/.cpp`；它由独立模型调用Qt6 `addEllipse`及宽1/SquareCap/BevelJoin `QPainterPathStroker`生成输入路径，未读取原厂pathstream作为算法输入。Qt6仅提供几何路径，实际覆盖不调用Qt6抗锯齿栅格；公开Qt4.6.3灰度程序只通过外部进程提供诊断oracle，没有把公共栅格源码编入候选或生产。

### 4.1 量化、自适应阈值与深度

1. 输入非空，最多512元素；先检查每个控制点有限、非负、X≤800/Y≤480，再截断到26.6整数。move、line、cubic及其两项data序列须完整，不接受孤立data或未知标签。
2. 用量化控制点包围范围计算`extentX=ceil(maxX/64)-floor(minX/64)`，Y同理。任一维大于24加一级，大于120再加一级；`adaptation`为0..2。阈值`T2=16<<adaptation`、`T3=32<<adaptation`，不是按对象宽高直接猜常量。
3. 对26.6三次曲线`a,b,c,d`，计算非负整数幅度：`S=max(abs(ax+dx-2*bx),abs(ay+dy-2*by))/T2`；`T=max(abs(ax+dx-3*(bx+cx)),abs(ay+dy-3*(bx+cy)))/T3`。第二个Y幅度保留历史`bx+cy`交叉项，不能擅自改为`by+cy`或平移不变误差公式。
4. 当S或T非零时，分别`S>>=2,T>>=3`，深度加1；最大深度8，超出即拒绝。由于幅度含绝对场景位置，平移会影响选择，不能先移到原点再计算深度。

### 4.2 整数二分、覆盖与资源预算

26.6控制点乘4进入每像素256单位格点。每层用整数de Casteljau中点二分，所有已接受坐标非负，因此各`/2`向零等于所需floor；每个叶子依次输出`(a+3b+3c+d)/8`加权中点和终点d。每层舍入、叶子中点及输出顺序都保留，不能只在最终输出时统一取整。

输出只含move/line并保留输入fillRule，最多4096元素；整条cubic先计算所需`2<<depth`元素预算，再递归生成，超限明确拒绝，不裁短路径。固定坐标及中间算术使用qint64，在有限坐标守卫下中点和加权中点最大中间量小于2^30。先在局部path/stats完成全部生成，成功才替换调用者输出；失败保留旧path/stats。

展开路径已含1/256精度，面积积分必须直接读`int(x*256),int(y*256)`，不能像原多边形输入那样再经过26.6截断而丢失低两位。随后按有向边先Y后X网格分割、floor有理交点，逐单元格累计cover及twice-area，再按行和Winding/OddEven生成0..255覆盖。负的边差/有理交点仍使用明确数学floor，不能因细分控制点非负就省略有符号面积积分规则。

### 4.3 白填充、黑描边与最终565

最终实现先白填充再黑描边；原始背景为RGB`(197,222,255)`，X=0或Y=0黑边。正确Qt4 `BYTE_MUL`分量为`D(n)=(n+(n>>8)+128)>>8`，先对原n右移，再加128；不能先加128再取右移项。覆盖a、层源色s（白255或黑0）、当前通道c的输出为`out=D(s*a)+D(c*(255-a))`，两个分量分别舍入后相加。受限白源255的源项恰为a，黑源项为0，所以`ellipseOpaqueCoverageOver`以`whiteSource?alpha:0`加正确目的项实现；不能把白填充当作纯黑覆盖，不能先量化为565再混色。早期候选及本报告初稿的错误式在下节作为失败链保留，已从规范算式中纠正。

`paintDeviceEllipseGraphic`先执行和计划一致的几何/样式/颜色/端点及有效painter守卫，生成两张完整800×480掩码后才绘制。补片为`geometry.adjusted(-1,-1,2,2)`与页面交集，RGB32初始化为已核页面背景，先白填后黑描边，再经活跃QPainter等尺寸写回主图；失败在绘制前返回，不直接修改活跃主图存储。补片隔离由计划验证，直接renderer调用不代替peer合成校验。

完整RGB32合成后才转LE RGB565：`((r>>3)<<11)|((g>>2)<<5)|(b>>3)`。诊断CLI不是事务发布入口，实际产品结果由下述最终green绑定。

### 4.4 r1失败、12个差异实例及r2修正

[r1正式B/S/M](stage5-evidence/native/ellipse/B-S-M-ellipse-cell-area-r1.json)采用错误`D(n)=(n+128+((n+128)>>8))>>8`，宽椭圆创建/重开各差1像素，无描边白填`line=0,fill=1`创建/重开各差5像素，共12个差异像素实例；两种场景都保留在完整15份canonical/13场景范围内，没有通过排除难例取得通过。

[逐像素舍入诊断](stage5-evidence/native/ellipse/rounding-diagnosis-r2.json)保留全部12项。比如填充Alpha11、背景红197时，目的乘积为48068；旧式返回189，正确式为188，白填后红由旧200变为199。在无描边样例中这恰好跨过RGB565红色阈值；宽椭圆`(347,117)`还叠加strokeAlpha123，使最终红由104改103，恢复原厂565。早期默认0差异和16张覆盖图都不能揭示这个混色错误，因为覆盖正确与混色舍入是不同层。

旧r1报告、失败帧及12项诊断保留；`ignoredPixelMask=[]`。实际brush RGBA未被直接hook读取，白填语义由活动UI属性及完整帧对照支持，不改写成“已直接观测画刷RGBA”。公开头的BYTE_MUL仅提供诊断线索，最终结论由原厂完整帧核验。

[r2正式B/S/M](stage5-evidence/native/ellipse/B-S-M-ellipse-cell-area-r2.json)的27/27完整768000B帧`differentPixels=0`，`allRasterComparisonsEqual/allStructuresValid/allDiagnosticCoverageEqual=true`；全部无ControlPara/ControlPixel，`PicLenPara=2400B`、动态图数/字节0。采用独立模型生成几何，没有加载原厂绘图库作为生产依赖。B层同源未知容器差异和无忽略掩码仍各自保留，像素相等不等于全部容器字节相等，也不关闭Q-S05-004整体问题。
