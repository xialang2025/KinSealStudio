# 性能r1证据丢失及r2重测

2026年11月14日，第一次性能切片在旧开发树完成105次owned进程，工具输出曾显示执行完成。随后只读核对发现旧工作树不再具有Git元数据，源文件、`performance-owned/run-r1/manifest.json`及原始采样文件已经不在原路径。发生原因未确认；本记录不将原因归属到用户、代理或其它程序。

旧运行的工具消息中保留了部分汇总数字和脚本输入，未保留1194条原始资源采样及全部生成物哈希，无法据此完整重建r1原始manifest。因此本批没有补造r1数据，没有将r1的运行次数、通过次数或资源数据计入阶段10正式结果。

在新的 `.worktrees/kinseal-stage10-20261114` 开发树恢复工具后，使用相同阶段9便携EXE重新实际执行全部105次，正式结果只取 [run-r2/manifest.json](run-r2/manifest.json)。新TEMP位于 `.stage10-run-20261114/temp/performance-r2`，不再位于旧 `.scratch` 树。r2脚本同时加入运行前机器内存和磁盘容量快照，因此脚本SHA与r1不同；r2输入、输出、耗时和清理均以新实际记录为准。

此处仅记录证据中断和恢复方式；不把缺失的r1证据当作功能失败、通过或性能回归。
