# KinSealStudio V5.1 逐项深修与软件模拟复核

本文保留 11 月 27 日第一轮构建和测试的原始结果。当天第二轮修复了 AMZ 原厂 SM 打开、保存和多类控件读写，并用八份现场工程比较设备数据。当前交付版本、最终测试统计和仍受限的项目见[第二轮 SM 双向兼容功能复核](SM双向兼容功能复核_20261127.md)。

2026 年 11 月 27 日。目标型号 AMZ070W01R。重新核对了 121 个桌面固定动作、41 类控件和图形的代表工程、139 份 PLC 配置和八张历史下载页。自动测试在后台运行，本轮没有触控、断电、串口接线或 USB 下载操作。

## 结果概览

- **发布版本**　Qt 6.12、MinGW、CMake Release，完整工作树构建。便携 EXE 的 SHA-256 为 `930d052306101a53b85918a2ab9a4dae089772bc470b899918de6b52e3a99430`。[可执行文件](../build/amz070w01r/KinSealStudioLite.exe)
- **自动回归**　私有 Windows 桌面实际执行 39 套独立 Qt Test。最终用例有 2,377 项通过、1 项失败、0 项跳过，统计含各套件的初始化和收尾。 失败集中在 KinSealStage3CanvasTests。小数居中用例缺历史原件。嵌套锁定样本已按原 SHA-256 恢复，往返及修改后的断言均通过。 [逐套结果和 SHA-256](文件规则/样例/V5.1逐项软件复验_20261127.json)
- **控件**　41/41 个单对象 KSP 能加载。用相同输入比较旧版和新版，PC 模拟支持数由 5 升至 18，其中 18 个均保存了实际 800×480 PNG。指定样式有 8 个编译和验包通过，另选十种图形的基准样式，10/10 均通过。
- **工程文件与现场**　41 个 AMZ 样例当前均可保存 KSP，原厂 SM 导出均明确拒绝。同组输入改为 AMT 时有 3 个通过 SM 导出、重开及二次导出逐字节比对。八个 AMZ 历史工程均可重新编译、验包并生成契约。第八页的两项宏行为等待现场读数。[现场待测和开发缺口](V5.1深修未完成与现场待测_20261127.md)

## 桌面和工程编辑

原厂固定动作含 119 个菜单项和两个工具栏独有入口。当前发布工作树中 117 个接到执行路径。上载数据、安装 USB 驱动、升级、升级底层四个入口仍有占位或暂缓。绑定结果可以回答“点击后是否进入执行路径”；各子窗的字段、保存、错误和设备效果有各自的验收结果。原厂 28 个系统树节点的已验与待验情况另列。[原厂桌面逐项矩阵](V5.1原厂桌面入口逐项矩阵_20261125.md) · [工程树验收](系统参数复刻验收进度.md)

宏父节点已接入“添加宏指令”和“打开宏指令编辑器”。新模板通过原厂 ARM SDK 实际编译；编辑器支持查找替换、整字、大小写、正则和向前查找。单草稿和多草稿的原生关闭、保存、放弃、取消及撤销状态通过私有桌面验证。宏 UI 完整套件 55 项通过。校正八个快捷键，覆盖四种对齐、三种等尺寸及工具箱。原版锁定与解锁均声明 Ctrl+L，该冲突的实际优先级待查。

## PLC 通信

标准 Modbus RTU 单站由真实应用通信线程连接受控软件从站。站号 7、寄存器偏移 246 在首次显示后由从站独立改值。置第 15 位得到 0x215A→0xA15A，清第 15 位得到 0xA15A→0x215A，切换第 0 位得到 0x215A→0x215B。每次先读取当时的字，再只改变目标位，写入后读回。前读异常和前读取消时，写帧计数均为零。写帧已经发出却未获应答时，界面提示核对 PLC。两个读写事务之间的外部并发修改仍可能被覆盖。[PLC 规则及软件从站结果](阶段9_PLC地址模板与通信实现.md)

核对 139 份协议配置、80 个型号描述及 1,724 个地址族条目。Lite 可解析其中 1,689 个，余下 35 个分属五份配置。AMZ 型号两种写法均能查到 COM1 能力。协议目录覆盖量、地址解析量、软件在线读写以及触摸屏接真实 PLC 是四种不同结果。真实串口收发器、HMI 到 PLC 接线、波特率、接地和实际掉线恢复仍需设备台架。

## 设备编译和八张历史页

800×480 普通空页可以编译成只有背景的完整页。单文本工程写入设备包的可编辑源保留自定义工程名、页名、控件名、相应样式和旧版草稿字段。原厂格式可表示的 AMT 样例用正常 SM 导出结果核对，Lite 扩展或 AMZ 对应工程保留可重开的快照。宏样本使用安装目录内的 ARM SDK。详细生成、边界检查和疑点见[UI 编译规则第 48 节](UI编译规则与阶段交付规范.md#48-空白页单文本可编辑源和-pc-模拟)。

八页复编使用 Windows 平台插件、原工程字节和既有实屏记录的 SHA-256。10、12、14 段工程分别生成 41、47、53 步传输契约，开始选项均为 000000。七份与历史实物包逐段字节一致。第 4 页仅操作提示中英文两帧下移一像素，两个长度表项随压缩变化。对同一行文字只替换渲染器即可重现两种帧，差异来自本轮之前的工作树修改。原厂同文、同字号帧尚缺。历史第 1 至 7 页已有现场确认。第 8 页已有成功下载，但初始化宏和全局宏仍缺人工读数。[现场回执与像素比对](AMZ070W01R八页实物复验_20261125.md)

## 运行环境与复验方式

原厂 V5.1 可执行文件 SHA-256 为 `305592b4e4bc1b15a707c7bc832c31f27ca0958b97f9c79a5b50ac6df49e907c`，旧版 Lite 为 `a93f081e5f29be729598736d4a9427acf82921a6cde8c1535c8ee3b07b6707f1`。发布构建来自完整工作树，包含本轮开始前已有的锁定、分组和字体渲染等修改。Git 只提交本轮差异。独立基线缺少工作树既有锁定动作时，桌面绑定数为 115，六个动作未接通。已有验证中锁定与解锁的实际触发属于发布工作树。[两种基线的桌面对照](V5.1原厂桌面入口逐项矩阵_20261125.md)

私有 Windows 桌面启动发布 EXE 时只提供 Windows 与 System32 的 PATH。自检退出 0，程序与同套构建的 35 个运行文件逐字节一致，帮助覆盖 9 个文件、32 个主题、155 条命令和 364 个链接。V31 解压使用三份官方 KNR，三个 SM 和 55 个图库成员比对通过。Qt 套件用当前源码和同一 Qt 工具链构建，历史阶段 4/5 样本从 Git 基线提取到测试目录，两个重复构建相同测试源的目标只计一次。[构建和部署验证](阶段11部署帮助与发布验收.md)

复验时可从 JSON 指明的 sourceFixture 读工程，取活动页上 objectId 对应的唯一对象，其余对象移除。除 GIF 样例外清空未引用的动画表，保留活动全局配置，目标设为 AMZ070W01R。矩阵输入按 UTF-8、无 BOM、LF、JSON 缩进 1 和末尾换行输出。用 --validate-project、--simulation-capabilities、--simulate-offline（空事件数组）、--compile-project、--verify-compiled-package 与 --export-native-project 分别执行。十类基准图形和 AMT 源变体的输入说明、每个首帧摘要及完整诊断均附在回执中。八页原始 KSP 已按原 SHA 归档。
